# Feature: แจ้งเตือนข่าวสารในระบบ (In-System Notification)
Spec ID: SPEC-NTF-017 | Source: Use Case Specification UC-17 แจ้งเตือนข่าวสารในระบบ (Included by UC-14) | Use case: UC-17
Owner: ทีม B | Status: Draft v1 | Updated: 2569-10-21

## Goal
ระบบสร้างและแสดงการแจ้งเตือนข่าวสารหรือผลที่เผยแพร่แล้วให้ผู้มีสิทธิ์เห็นในระบบ
เพื่อให้ผู้ใช้ทราบข้อมูลสำคัญโดยไม่ต้องตรวจสอบด้วยตนเองตลอดเวลา

## Scope
### In scope
- IN-NTF-01 ตรวจพบรายการที่ต้องแจ้งเตือน                            <- UC-17 ขั้น 1, Trigger
- IN-NTF-02 กำหนดผู้รับตามสิทธิ์และความเกี่ยวข้อง                      <- UC-17 ขั้น 2
- IN-NTF-03 สร้างการแจ้งเตือน                                      <- UC-17 ขั้น 3
- IN-NTF-04 แสดงการแจ้งเตือนในระบบแก่ผู้รับ                          <- UC-17 ขั้น 4, Postcondition
- IN-NTF-05 บันทึกสถานะการแจ้งเตือน                                <- UC-17 ขั้น 5
- IN-NTF-06 จัดการกรณีไม่มีผู้รับ กรณีผู้ใช้ปิดการแจ้งเตือน และกรณีแจ้งเตือนไม่สำเร็จ   <- UC-17 alt 1-2, Exception
### Out of scope
- OUT-NTF-01 การเผยแพร่ผลการตรวจสอบ - เป็นของ UC-14 ซึ่งเรียกใช้ use case นี้
- OUT-NTF-02 การแสดงหน้าข่าวสารและตารางเวลา - เป็นของ UC-05
- OUT-NTF-03 การส่งอีเมลหรือข้อความออกนอกระบบ - UC-17 ระบุเพียงการแจ้งเตือนในระบบ (ดู OQ-NTF-01)
- OUT-NTF-04 การสร้างเนื้อหาข่าวสาร - ไม่มี use case ใดใน diagram ครอบคลุม (ดู OQ-NWS-01 ใน specs/005)
- OUT-NTF-05 หน้าตั้งค่าการแจ้งเตือนของผู้ใช้ - UC-17 alt 2 อ้างถึงการตั้งค่าแต่ไม่มี use case จัดการ (ดู OQ-NTF-02)

## Constraints
- IF-AUTH-01 ผู้ใช้ต้องยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัยก่อนเห็นการแจ้งเตือนของตน   <- ข้อ 12
- IF-WEB-01 การแจ้งเตือนต้องแสดงบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลการแจ้งเตือนเก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- CON-NTF-01 ผู้รับการแจ้งเตือนต้องเป็นผู้ที่มีสิทธิ์เห็นข้อมูลนั้นเท่านั้น   <- UC-17 ขั้น 2, Postcondition
- CON-NTF-02 เนื้อหาการแจ้งเตือนต้องไม่เปิดเผยข้อมูลที่ผู้รับไม่มีสิทธิ์เห็น   <- UC-17 NFR (Security)
- CON-NTF-03 เมื่อไม่มีผู้รับที่เกี่ยวข้อง ต้องไม่สร้างการแจ้งเตือน   <- UC-17 alt 1

## Data Rules
- DR-NTF-01 ข้อมูลที่บันทึกต่อ 1 การแจ้งเตือน: ผู้รับ เนื้อหา เวลาที่สร้าง และสถานะการแจ้งเตือน   <- UC-17 ขั้น 3, 5
- DR-NTF-02 สถานะการแจ้งเตือนต้องแยกได้ว่าสร้างแล้ว แสดงแล้ว และแจ้งไม่สำเร็จ   <- UC-17 ขั้น 5, Exception (รายการสถานะรอยืนยัน ดู OQ-NTF-03)
- DR-NTF-03 เหตุการณ์ที่ทำให้เกิดการแจ้งเตือน: การเผยแพร่ข่าวสารหรือผลการตรวจสอบ   <- UC-17 Trigger, Precondition (เหตุการณ์อื่นรอยืนยัน ดู OQ-NTF-04)

## Requirements
- FR-NTF-01 ระบบต้องตรวจพบรายการที่ต้องแจ้งเตือนเมื่อเกิดเหตุการณ์ตาม DR-NTF-03   <- UC-17 ขั้น 1, Trigger
- FR-NTF-02 ระบบต้องกำหนดผู้รับตามสิทธิ์และความเกี่ยวข้องตาม CON-NTF-01   <- UC-17 ขั้น 2
- FR-NTF-03 ระบบต้องสร้างการแจ้งเตือนพร้อมข้อมูลตาม DR-NTF-01   <- UC-17 ขั้น 3
- FR-NTF-04 ระบบต้องแสดงการแจ้งเตือนในระบบให้ผู้รับเห็น   <- UC-17 ขั้น 4
- FR-NTF-05 ระบบต้องบันทึกสถานะการแจ้งเตือนตาม DR-NTF-02   <- UC-17 ขั้น 5
- FR-NTF-06 เมื่อไม่มีผู้รับที่เกี่ยวข้อง ระบบต้องไม่สร้างการแจ้งเตือนตาม CON-NTF-03   <- UC-17 alt 1
- FR-NTF-07 เมื่อผู้ใช้ปิดการแจ้งเตือน ระบบต้องแสดงตามการตั้งค่าที่ระบบรองรับ   <- UC-17 alt 2 (ขอบเขตการตั้งค่ารอยืนยัน ดู OQ-NTF-02)
- FR-NTF-08 เมื่อการแจ้งเตือนไม่สำเร็จ ระบบต้องบันทึกเหตุการณ์ และแจ้งเตือนใหม่เมื่อระบบพร้อม   <- UC-17 Exception
- FR-NTF-09 เนื้อหาการแจ้งเตือนต้องไม่มีข้อมูลที่ผู้รับไม่มีสิทธิ์เห็นตาม CON-NTF-02
- FR-NTF-10 ระบบต้องไม่แสดงการแจ้งเตือนของผู้ใช้คนหนึ่งต่อผู้ใช้คนอื่น ต้องได้ HTTP 403 เมื่อเรียกข้ามผู้ใช้   <- CON-NTF-01

## Quality Requirements
- NFR-NTF-01 [Availability] ระบบแจ้งเตือนต้องพร้อมใช้งานไม่น้อยกว่า 99% ต่อเดือน   <- UC-17 NFR (Availability) + ค่าที่เสนอไว้ ดู ASM-NTF-01
- NFR-NTF-02 [Reliability] การแจ้งเตือนที่ไม่สำเร็จต้องถูกส่งซ้ำอัตโนมัติภายใน 5 นาที และสูงสุด 3 ครั้ง   <- UC-17 NFR (Reliability) + Exception (ค่าที่เสนอไว้ ดู ASM-NTF-01)
- NFR-NTF-03 [Reliability] การแจ้งเตือน 1 เหตุการณ์ต่อ 1 ผู้รับต้องไม่ถูกสร้างซ้ำ แม้มีการส่งซ้ำตาม NFR-NTF-02
- NFR-NTF-04 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-NTF-05 [Usability] ข้อความแจ้งเตือนต้องเป็นภาษาไทย   <- ข้อ 10
- NFR-NTF-06 [Usability] การแจ้งเตือนต้องแสดงได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-NTF-01)
- NFR-NTF-07 [Performance] หลังเกิดเหตุการณ์ที่ต้องแจ้งเตือน ผู้รับต้องเห็นการแจ้งเตือนภายใน 1 นาที   <- ค่าที่เสนอไว้ ดู ASM-NTF-01

## Acceptance Criteria
- [ ] AC-NTF-01 (FR-NTF-02, FR-NTF-03, FR-NTF-04)
      Given มีข่าวสารหรือผลที่เผยแพร่และมีผู้รับที่เกี่ยวข้อง
      When  ระบบสร้างการแจ้งเตือน
      Then  ผู้รับเห็นการแจ้งเตือนในระบบ และข้อมูลในการแจ้งเตือนถูกต้อง
- [ ] AC-NTF-02 (FR-NTF-06, CON-NTF-03)
      Given ไม่มีผู้รับที่เกี่ยวข้องกับรายการนั้น
      When  เกิดเหตุการณ์ที่ต้องแจ้งเตือน
      Then  ระบบไม่สร้างการแจ้งเตือน
- [ ] AC-NTF-03 (FR-NTF-08, NFR-NTF-02, NFR-NTF-03)
      Given การแจ้งเตือนครั้งแรกไม่สำเร็จ
      When  ระบบพร้อมใช้งานอีกครั้ง
      Then  ระบบแจ้งเตือนซ้ำภายใน 5 นาที ไม่เกิน 3 ครั้ง และผู้รับเห็นการแจ้งเตือนเพียง 1 รายการ
- [ ] AC-NTF-04 (FR-NTF-10, CON-NTF-01)
      Given ผู้ใช้ A ไม่ใช่ผู้รับของการแจ้งเตือน N
      When  ผู้ใช้ A เรียกข้อมูลการแจ้งเตือน N
      Then  ระบบตอบ HTTP 403 และไม่คืนข้อมูล
- [ ] AC-NTF-05 (FR-NTF-09, CON-NTF-02)
      Given ผลการตรวจสอบของนักศึกษา B ถูกเผยแพร่
      When  ระบบสร้างการแจ้งเตือนถึงผู้รับอื่นที่เกี่ยวข้อง
      Then  เนื้อหาการแจ้งเตือนไม่เปิดเผยผลของ B ต่อผู้ที่ไม่มีสิทธิ์เห็น
- [ ] AC-NTF-06 (FR-NTF-05, DR-NTF-02)
      Given การแจ้งเตือนถูกสร้างและผู้รับเปิดดูแล้ว
      When  ตรวจสอบข้อมูลการแจ้งเตือนนั้น
      Then  สถานะระบุได้ว่าสร้างแล้วและแสดงแล้ว
- [ ] AC-NTF-07 (FR-NTF-07)
      Given ผู้ใช้ปิดการแจ้งเตือนตามการตั้งค่าที่ระบบรองรับ
      When  เกิดเหตุการณ์ที่ต้องแจ้งเตือน
      Then  ระบบแสดงการแจ้งเตือนตามการตั้งค่านั้น
- [ ] AC-NTF-08 (NFR-NTF-07)
      Given เจ้าหน้าที่เผยแพร่ผลตาม UC-14
      When  เวลาผ่านไป 1 นาที
      Then  ผู้รับที่เกี่ยวข้องเห็นการแจ้งเตือนในระบบ

## Assumptions & Open Questions
- ASM-NTF-01 UC-17 ระบุ NFR เป็นหมวด (Availability, Reliability, Security) ค่าตัวเลขใน NFR-NTF-01, NFR-NTF-02, NFR-NTF-06 และ NFR-NTF-07 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-NTF-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- OQ-NTF-01 UC-17 ระบุเพียงการแจ้งเตือน "ในระบบ" แต่ specs/001 (FR-EDU-09) กำหนดให้ส่งอีเมลด้วย ระบบต้องรองรับอีเมลหรือไม่ และถ้ารองรับ อยู่ที่ use case ใด
- OQ-NTF-02 UC-17 alt 2 อ้างถึง "ผู้ใช้ปิดการแจ้งเตือน" แต่ไม่มี use case สำหรับตั้งค่าการแจ้งเตือน การตั้งค่าที่ระบบรองรับมีอะไรบ้าง และตั้งที่ไหน
- OQ-NTF-03 รายการสถานะการแจ้งเตือนทั้งหมดมีอะไรบ้าง (สร้างแล้ว แสดงแล้ว อ่านแล้ว แจ้งไม่สำเร็จ)
- OQ-NTF-04 นอกจากการเผยแพร่ผลตาม UC-14 ซึ่งระบุให้เรียก UC-17 แล้ว ต้องรองรับเหตุการณ์อื่นเพิ่มเติมหรือไม่ โดยมีประเด็นที่อ้างถึงจาก Specs อื่น ได้แก่ การส่งกลับให้แก้ไขตาม UC-09 (Q-03 ใน SPEC-APR-009), การยืนยันสมาชิกกลุ่มตาม UC-08 (Q-04 ใน SPEC-GRP-008) และการเปลี่ยนตารางเวลาตาม UC-15 (OQ-SCH-05 ใน SPEC-SCH-015); เหตุการณ์เหล่านี้ยังรอคำตอบจากทีม
- OQ-NTF-05 การแจ้งเตือนมีอายุหรือถูกลบเมื่อใด และผู้ใช้ลบการแจ้งเตือนของตนได้หรือไม่
- OQ-NTF-06 ต้องแสดงจำนวนการแจ้งเตือนที่ยังไม่อ่านหรือไม่ UC-17 ไม่ระบุ
