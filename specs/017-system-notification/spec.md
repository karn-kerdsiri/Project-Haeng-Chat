# Feature: แจ้งเตือนข่าวสารในระบบ (In-System Notification)

Spec ID: SPEC-NTF-017 | Source: Use Case Specification UC-17 แจ้งเตือนข่าวสารในระบบ (Included by UC-14)  
Owner: ทีม B | Status: Draft v2 | Updated: 2569-11-14

## Goal

ระบบสร้างและแสดงการแจ้งเตือนข่าวสารหรือผลที่เผยแพร่แล้วให้ผู้มีสิทธิ์เห็นในระบบ เพื่อให้ผู้ใช้ทราบข้อมูลสำคัญโดยไม่ต้องตรวจสอบด้วยตนเองตลอดเวลา

## Scope

### In scope

- IN-NTF-01 ตรวจพบรายการที่ต้องแจ้งเตือน <- UC-17 ขั้น 1, Trigger
- IN-NTF-02 กำหนดผู้รับตามสิทธิ์และความเกี่ยวข้อง <- UC-17 ขั้น 2
- IN-NTF-03 สร้างการแจ้งเตือน <- UC-17 ขั้น 3
- IN-NTF-04 แสดงการแจ้งเตือนในระบบแก่ผู้รับ <- UC-17 ขั้น 4, Postcondition
- IN-NTF-05 บันทึกสถานะการแจ้งเตือน <- UC-17 ขั้น 5
- IN-NTF-06 จัดการกรณีไม่มีผู้รับ กรณีผู้ใช้ปิดการแจ้งเตือน และกรณีแจ้งเตือนไม่สำเร็จ <- UC-17 alt 1-2, Exception

### Out of scope

- OUT-NTF-01 การเผยแพร่ผลการตรวจสอบ เป็นหน้าที่ของ UC-14 ซึ่งเรียกใช้ UC-17 หลังเผยแพร่ผลสำเร็จ
- OUT-NTF-02 การแสดงหน้าข่าวสารและตารางเวลา เป็นหน้าที่ของ UC-05
- OUT-NTF-03 การส่งข้อความออกนอกระบบ เช่น SMS หรือช่องทางภายนอกอื่น ส่วนการส่งอีเมลยังรอการยืนยันขอบเขตตาม OQ-NTF-01
- OUT-NTF-04 การสร้างเนื้อหาข่าวสาร ไม่มี Use Case ใดใน diagram ครอบคลุม (ดู OQ-NWS-01 ใน specs/005)
- OUT-NTF-05 การพัฒนาหน้าตั้งค่าการแจ้งเตือนของผู้ใช้ เนื่องจากยังไม่มี Use Case สำหรับจัดการการตั้งค่า (ดู OQ-NTF-02)

## Constraints

- IF-AUTH-01 ผู้ใช้ต้องยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัยก่อนเห็นการแจ้งเตือนของตน <- ข้อ 12
- IF-WEB-01 การแจ้งเตือนต้องแสดงบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลการแจ้งเตือนเก็บในฐานข้อมูล PostgreSQL <- ข้อ 19
- CON-NTF-01 ผู้รับการแจ้งเตือนต้องเป็นผู้ที่มีสิทธิ์เห็นข้อมูลนั้นเท่านั้น <- UC-17 ขั้น 2, Postcondition
- CON-NTF-02 เนื้อหาการแจ้งเตือนต้องไม่เปิดเผยข้อมูลที่ผู้รับไม่มีสิทธิ์เห็น <- UC-17 NFR (Security)
- CON-NTF-03 เมื่อไม่มีผู้รับที่เกี่ยวข้อง ต้องไม่สร้างการแจ้งเตือน <- UC-17 alt 1

## Data Rules

- DR-NTF-01 ข้อมูลที่บันทึกต่อ 1 การแจ้งเตือน ได้แก่ ผู้รับ เนื้อหา เวลาที่สร้าง และสถานะการแจ้งเตือน <- UC-17 ขั้น 3, 5
- DR-NTF-02 สถานะการแจ้งเตือนต้องแยกได้ว่าสร้างแล้ว แสดงแล้ว และแจ้งไม่สำเร็จ ส่วนสถานะอ่านแล้วและรายละเอียดสถานะอื่นยังรอการยืนยัน (ดู OQ-NTF-03)
- DR-NTF-03 เหตุการณ์ที่ทำให้เกิดการแจ้งเตือน ได้แก่ การเผยแพร่ข่าวสารหรือผลการตรวจสอบตาม UC-17 โดยการเผยแพร่ผลตาม UC-14 เป็นเหตุการณ์ที่ยืนยันแล้ว ส่วนเหตุการณ์อื่นยังรอการยืนยัน (ดู OQ-NTF-04)

## Requirements

- FR-NTF-01 ระบบต้องตรวจพบรายการที่ต้องแจ้งเตือนเมื่อเกิดเหตุการณ์ตาม DR-NTF-03 <- UC-17 ขั้น 1, Trigger
- FR-NTF-02 ระบบต้องกำหนดผู้รับตามสิทธิ์และความเกี่ยวข้องตาม CON-NTF-01 <- UC-17 ขั้น 2
- FR-NTF-03 ระบบต้องสร้างการแจ้งเตือนพร้อมข้อมูลตาม DR-NTF-01 <- UC-17 ขั้น 3
- FR-NTF-04 ระบบต้องแสดงการแจ้งเตือนในระบบให้ผู้รับเห็นผ่านเบราว์เซอร์ตาม IF-WEB-01 <- UC-17 ขั้น 4
- FR-NTF-05 ระบบต้องบันทึกสถานะการแจ้งเตือนตาม DR-NTF-02 <- UC-17 ขั้น 5
- FR-NTF-06 เมื่อไม่มีผู้รับที่เกี่ยวข้อง ระบบต้องไม่สร้างการแจ้งเตือนตาม CON-NTF-03 <- UC-17 alt 1
- FR-NTF-07 เมื่อผู้ใช้ปิดการแจ้งเตือน ระบบต้องแสดงการแจ้งเตือนตามการตั้งค่าที่ระบบรองรับ โดยรายละเอียดการตั้งค่ายังรอการยืนยัน <- UC-17 alt 2 (ดู OQ-NTF-02)
- FR-NTF-08 เมื่อการแจ้งเตือนไม่สำเร็จ ระบบต้องบันทึกเหตุการณ์และรองรับการแจ้งเตือนซ้ำเมื่อระบบพร้อม <- UC-17 Exception
- FR-NTF-09 เนื้อหาการแจ้งเตือนต้องไม่มีข้อมูลที่ผู้รับไม่มีสิทธิ์เห็นตาม CON-NTF-02
- FR-NTF-10 ระบบต้องไม่แสดงการแจ้งเตือนของผู้ใช้คนหนึ่งต่อผู้ใช้คนอื่น และต้องตอบ HTTP 403 เมื่อผู้ใช้เรียกดูการแจ้งเตือนที่ตนไม่มีสิทธิ์เข้าถึง <- CON-NTF-01

## Quality Requirements

- NFR-NTF-01 [Availability] ระบบแจ้งเตือนต้องพร้อมใช้งานไม่น้อยกว่า 99% ต่อเดือน <- UC-17 NFR (Availability) โดยค่า 99% เป็นค่าที่เสนอไว้ รอทีมยืนยันตาม ASM-NTF-01
- NFR-NTF-02 [Reliability] การแจ้งเตือนที่ไม่สำเร็จต้องถูกส่งซ้ำอัตโนมัติภายใน 5 นาที และสูงสุด 3 ครั้ง <- UC-17 NFR (Reliability) และ Exception โดยค่าตัวเลขและความหมายของจำนวนครั้งรอทีมยืนยันตาม ASM-NTF-01
- NFR-NTF-03 [Reliability] การแจ้งเตือน 1 เหตุการณ์ต่อ 1 ผู้รับต้องไม่ถูกสร้างซ้ำ แม้มีการส่งซ้ำตาม NFR-NTF-02
- NFR-NTF-04 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติเมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที <- ข้อ 9
- NFR-NTF-05 [Usability] ข้อความแจ้งเตือนต้องเป็นภาษาไทย <- ข้อ 10
- NFR-NTF-06 [Usability] การแจ้งเตือนต้องแสดงได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px <- ข้อ 11 โดยค่า 360 px เป็นค่าที่เสนอไว้ รอทีมยืนยันตาม ASM-NTF-01
- NFR-NTF-07 [Performance] หลังเกิดเหตุการณ์ที่ต้องแจ้งเตือน ผู้รับต้องเห็นการแจ้งเตือนภายใน 1 นาที โดยค่า 1 นาทีเป็นค่าที่เสนอไว้ รอทีมยืนยันตาม ASM-NTF-01

## Acceptance Criteria

- [ ] AC-NTF-01 (FR-NTF-02, FR-NTF-03, FR-NTF-04)
  Given มีข่าวสารหรือผลที่เผยแพร่และมีผู้รับที่เกี่ยวข้อง
  When ระบบสร้างการแจ้งเตือน
  Then ผู้รับเห็นการแจ้งเตือนในระบบ และข้อมูลในการแจ้งเตือนถูกต้อง

- [ ] AC-NTF-02 (FR-NTF-06, CON-NTF-03)
  Given ไม่มีผู้รับที่เกี่ยวข้องกับรายการนั้น
  When เกิดเหตุการณ์ที่ต้องแจ้งเตือน
  Then ระบบไม่สร้างการแจ้งเตือน

- [ ] AC-NTF-03 (FR-NTF-08, NFR-NTF-02, NFR-NTF-03)
  Given การแจ้งเตือนครั้งแรกไม่สำเร็จ
  When ระบบพร้อมใช้งานอีกครั้ง
  Then ระบบแจ้งเตือนซ้ำตามจำนวนครั้งและระยะเวลาที่ทีมยืนยัน โดยผู้รับต้องไม่เห็นการแจ้งเตือนซ้ำสำหรับเหตุการณ์และผู้รับรายเดิม

- [ ] AC-NTF-04 (FR-NTF-10, CON-NTF-01)
  Given ผู้ใช้ A ไม่ใช่ผู้รับของการแจ้งเตือน N
  When ผู้ใช้ A เรียกข้อมูลการแจ้งเตือน N
  Then ระบบตอบ HTTP 403 และไม่คืนข้อมูลการแจ้งเตือน

- [ ] AC-NTF-05 (FR-NTF-09, CON-NTF-02)
  Given ผลการตรวจสอบของนักศึกษา B ถูกเผยแพร่
  When ระบบสร้างการแจ้งเตือนถึงผู้รับอื่นที่เกี่ยวข้อง
  Then เนื้อหาการแจ้งเตือนไม่เปิดเผยผลของ B ต่อผู้ที่ไม่มีสิทธิ์เห็น

- [ ] AC-NTF-06 (FR-NTF-05, DR-NTF-02)
  Given การแจ้งเตือนถูกสร้างและผู้รับเปิดดูแล้ว
  When ตรวจสอบข้อมูลการแจ้งเตือนนั้น
  Then สถานะระบุได้ว่าสร้างแล้วและแสดงแล้ว โดยไม่สรุปว่าผู้รับอ่านแล้วจนกว่าจะมีการยืนยันนิยามสถานะตาม OQ-NTF-03

- [ ] AC-NTF-07 (FR-NTF-07)
  Given ผู้ใช้ปิดการแจ้งเตือนตามการตั้งค่าที่ระบบรองรับ
  When เกิดเหตุการณ์ที่ต้องแจ้งเตือน
  Then ระบบแสดงการแจ้งเตือนตามการตั้งค่านั้น โดยรายละเอียดการตั้งค้ายังขึ้นกับคำตอบ OQ-NTF-02

- [ ] AC-NTF-08 (NFR-NTF-07)
  Given เจ้าหน้าที่เผยแพร่ผลตาม UC-14
  When เวลาผ่านไปตามเกณฑ์เวลาที่ทีมยืนยัน
  Then ผู้รับที่เกี่ยวข้องเห็นการแจ้งเตือนในระบบ

- [ ] AC-NTF-09 (NFR-NTF-04, IF-AUTH-01)
  Given ผู้ใช้เข้าสู่ระบบแล้วและไม่มีการใช้งานต่อเนื่อง
  When ไม่มีการใช้งานเกิน 30 นาที
  Then ระบบตัดการเชื่อมต่อบัญชีผู้ใช้โดยอัตโนมัติ

- [ ] AC-NTF-10 (NFR-NTF-05, IF-WEB-01)
  Given ผู้ใช้เปิดดูการแจ้งเตือนผ่านเบราว์เซอร์
  When ระบบแสดงข้อความแจ้งเตือน
  Then ข้อความแจ้งเตือนแสดงเป็นภาษาไทยและผู้ใช้สามารถดูได้โดยไม่ต้องติดตั้งโปรแกรมเพิ่มเติม

- [ ] AC-NTF-11 (NFR-NTF-06)
  Given ผู้ใช้เปิดดูการแจ้งเตือนบนโทรศัพท์มือถือที่มีความกว้างหน้าจอตั้งแต่ 360 px
  When ระบบแสดงรายการแจ้งเตือน
  Then เนื้อหาต้องแสดงได้โดยไม่มีการเลื่อนหน้าจอในแนวนอน

## Assumptions & Open Questions

### Assumptions

- ASM-NTF-01 UC-17 ระบุ NFR เป็นหมวด (Availability, Reliability, Security) ค่าตัวเลขใน NFR-NTF-01, NFR-NTF-02, NFR-NTF-06 และ NFR-NTF-07 เป็นค่าที่เสนอเพื่อให้สามารถทดสอบได้ ยังไม่ได้รับการยืนยันจากทีม โดยทีมต้องยืนยันค่า 99% ต่อเดือน ระยะเวลา Retry ภายใน 5 นาที จำนวน Retry สูงสุด 3 ครั้ง ความกว้างหน้าจอ 360 px และระยะเวลาแสดงการแจ้งเตือนภายใน 1 นาที รวมถึงยืนยันว่าจำนวน 3 ครั้งหมายถึงจำนวนครั้งที่ลองใหม่หรือจำนวนครั้งทั้งหมด และวิธีวัด Availability
- ASM-NTF-02 ข้อ 19 ระบุ React + PostgreSQL จึงใช้เป็นข้อกำหนดใน IF-TECH-01 ของ Spec นี้ ส่วน plan.md ของ specs/001-Enter-educational-information ระบุการใช้ Supabase ซึ่งใช้ PostgreSQL เป็นฐานข้อมูล จึงไม่จำเป็นต้องขัดแย้งกันโดยตรง อย่างไรก็ตาม ทีมต้องยืนยันว่าจะใช้ PostgreSQL ผ่าน Supabase หรือจัดการ PostgreSQL โดยตรง และปรับเอกสารที่เกี่ยวข้องให้สอดคล้องกัน

### Open Questions

- OQ-NTF-01 ใน UC-17 ระบุขอบเขตเป็นการแจ้งเตือนภายในระบบ แต่ SPEC-001 (FR-EDU-09 และ FR-EDU-10) มีข้อกำหนดเกี่ยวกับการส่งอีเมลด้วย ทีมต้องยืนยันว่าอีเมลเป็นความรับผิดชอบของ UC-17 หรือเป็นความรับผิดชอบของ Use Case อื่น และ UC-17 ต้องรองรับการส่งอีเมลเพิ่มเติมหรือไม่

- OQ-NTF-02 UC-17 alt 2 ระบุว่าผู้ใช้สามารถปิดการแจ้งเตือนได้ แต่ยังไม่มี Use Case สำหรับจัดการการตั้งค่า ทีมต้องยืนยันว่าผู้ใช้สามารถเปิด/ปิดการแจ้งเตือนเองได้หรือไม่ หากรองรับ ต้องตั้งค่าผ่านหน้าใด และการปิดแจ้งเตือนมีผลกับการแจ้งเตือนทุกประเภทหรือเฉพาะบางประเภท

- OQ-NTF-03 ทีมต้องยืนยันรายการสถานะการแจ้งเตือนที่ระบบต้องจัดเก็บและแสดง โดยมีสถานะที่ระบุไว้เบื้องต้น ได้แก่ สร้างแล้ว (Created), แสดงแล้ว (Displayed), อ่านแล้ว (Read) และแจ้งไม่สำเร็จ (Failed) รวมถึงต้องยืนยันว่า “แสดงแล้ว” กับ “อ่านแล้ว” เป็นคนละสถานะหรือไม่ และระบบต้องเปลี่ยนสถานะเป็น “อ่านแล้ว” เมื่อผู้ใช้เปิดดูการแจ้งเตือนหรือไม่

- OQ-NTF-04 นอกจากการเผยแพร่ผลตาม UC-14 ซึ่งมีการระบุให้เรียก UC-17 หลังเผยแพร่ผลสำเร็จแล้ว ต้องรองรับเหตุการณ์อื่นเพิ่มเติมหรือไม่ โดยมีประเด็นที่อ้างถึงจาก Specs อื่น ได้แก่ การส่งกลับให้แก้ไขตาม UC-09 (Q-03 ใน SPEC-APR-009), การยืนยันสมาชิกกลุ่มตาม UC-08 (Q-04 ใน SPEC-GRP-008) และการเปลี่ยนตารางเวลาตาม UC-15 (OQ-SCH-05 ใน SPEC-SCH-015) เหตุการณ์เหล่านี้ยังรอคำตอบจากทีม

- OQ-NTF-05 ทีมต้องยืนยันนโยบายการเก็บรักษาการแจ้งเตือนว่าแจ้งเตือนจะถูกเก็บไว้นานเท่าใด มีการลบหรือหมดอายุอัตโนมัติหรือไม่ และผู้ใช้สามารถลบการแจ้งเตือนของตนเองได้หรือไม่ หากลบได้ ต้องเป็นการลบเฉพาะรายการที่แสดงต่อผู้ใช้หรือเป็นการลบข้อมูลออกจากระบบด้วย

- OQ-NTF-06 ทีมต้องยืนยันว่าระบบต้องแสดงจำนวนการแจ้งเตือนที่ยังไม่อ่าน (Unread Count) หรือไม่ หากต้องแสดง ต้องนับเฉพาะการแจ้งเตือนที่ยังไม่อ่านของผู้ใช้ที่เข้าสู่ระบบ และจำนวนดังกล่าวต้องปรับปรุงเมื่อผู้ใช้อ่านหรือลบการแจ้งเตือนหรือไม่
