# Feature: เลือกกลุ่มอาจารย์ที่ปรึกษา (Select Advisor Group)
Spec ID: SPEC-ADV-006 | Source: Use Case Specification UC-06 เลือกกลุ่มอาจารย์ที่ปรึกษา (Included by UC-01) + รายการความต้องการของทีม ข้อ 14 | Use case: UC-06
Owner: ทีม B | Status: Draft v2 | Updated: 2569-10-21

## Goal
นักศึกษาที่อยู่ระหว่างส่งผลการศึกษา เลือกกลุ่มอาจารย์ที่ปรึกษาจากรายการที่เปิดรับได้
และระบบบันทึกกลุ่มที่เลือกไว้กับข้อมูลการส่งผลการศึกษาของนักศึกษาคนนั้น

## Scope
### In scope
- IN-ADV-01 ดึงและแสดงรายการกลุ่มอาจารย์ที่เปิดรับ                    <- UC-06 ขั้น 1
- IN-ADV-02 ให้นักศึกษาเลือกกลุ่มอาจารย์                             <- UC-06 ขั้น 2
- IN-ADV-03 แสดงรายละเอียดของกลุ่มที่เลือก                           <- UC-06 ขั้น 3
- IN-ADV-04 ยืนยันการเลือกและบันทึกกลุ่มที่เลือกกับคำขอของนักศึกษา      <- UC-06 ขั้น 4-5
- IN-ADV-05 แจ้งกรณีไม่มีกลุ่มที่เปิดรับ และกรณียังไม่ได้เลือกกลุ่ม       <- UC-06 alt 1-2
### Out of scope
- OUT-ADV-01 การสร้างและแก้ไขรายชื่ออาจารย์ กลุ่มอาจารย์ และโควต้า - เป็นของ UC-12 และ ข้อ 4
- OUT-ADV-02 การกรอกและส่งผลการศึกษา - เป็นของ UC-01 ซึ่งเรียกใช้ use case นี้
- OUT-ADV-03 การอนุมัติโดยอาจารย์ที่ปรึกษา - เป็นของ UC-09
- OUT-ADV-04 การกรอกข้อมูลสมาชิกกลุ่ม/คู่ - เป็นของ UC-08
- OUT-ADV-05 การจัดสรรนักศึกษาให้อาจารย์โดยระบบอัตโนมัติ - UC-06 ระบุว่านักศึกษาเลือกเอง

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลกลุ่มอาจารย์เก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- IF-MST-01 รายการกลุ่มอาจารย์และโควต้าต้องอ่านจากข้อมูลที่เจ้าหน้าที่จัดการไว้ ไม่เก็บซ้ำในฟีเจอร์นี้   <- ข้อ 4
- DOM-QUOTA-01 อาจารย์หนึ่งคนรับนักศึกษาได้ไม่เกินโควต้าที่คณะกำหนดในแต่ละภาคการศึกษา   <- ข้อ 14
- CON-ADV-01 การเลือกกลุ่มต้องผูกกับคำขอส่งผลการศึกษาของนักศึกษาคนนั้นในภาคการศึกษานั้น   <- UC-06 Postcondition

## Data Rules
- DR-ADV-01 ข้อมูลที่แสดงต่อ 1 กลุ่มอาจารย์: ชื่อกลุ่ม และรายละเอียดของกลุ่ม   <- UC-06 ขั้น 1, 3 (รายการฟิลด์ทั้งหมดรอยืนยัน ดู OQ-ADV-01)
- DR-ADV-02 กลุ่มที่แสดงให้เลือกได้ต้องมีสถานะเปิดรับ   <- UC-06 ขั้น 1, alt 1
- DR-ADV-03 การเลือกกลุ่มเป็นฟิลด์บังคับของขั้นตอนนี้ ต้องเลือกจึงจะยืนยันได้   <- UC-06 alt 2
- DR-ADV-04 จำนวนกลุ่มที่นักศึกษา 1 คนเลือกได้ต่อ 1 คำขอ: 1 กลุ่ม   <- UC-06 ขั้น 2

## Requirements
- FR-ADV-01 ระบบต้องดึงและแสดงรายการกลุ่มอาจารย์ที่เปิดรับตาม DR-ADV-01 และ DR-ADV-02   <- UC-06 ขั้น 1
- FR-ADV-02 ระบบต้องให้นักศึกษาเลือกกลุ่มอาจารย์จากรายการที่แสดง   <- UC-06 ขั้น 2
- FR-ADV-03 ระบบต้องแสดงรายละเอียดของกลุ่มที่เลือกก่อนให้ยืนยัน   <- UC-06 ขั้น 3
- FR-ADV-04 เมื่อนักศึกษายืนยัน ระบบต้องบันทึกกลุ่มที่เลือกผูกกับคำขอตาม CON-ADV-01   <- UC-06 ขั้น 4-5
- FR-ADV-05 เมื่อไม่มีกลุ่มที่เปิดรับ ระบบต้องแจ้งว่าไม่สามารถเลือกได้ และไม่ให้ยืนยันขั้นตอนนี้   <- UC-06 alt 1
- FR-ADV-06 เมื่อนักศึกษายังไม่ได้เลือกกลุ่ม ระบบต้องแจ้งให้เลือกกลุ่มก่อน และไม่บันทึก   <- UC-06 alt 2
- FR-ADV-07 ระบบต้องไม่ให้เลือกกลุ่มของอาจารย์ที่มีจำนวนการอนุมัติของภาคการศึกษานั้นเต็มตาม DOM-QUOTA-01 แล้ว   <- ข้อ 14
- FR-ADV-08 หากบันทึกไม่สำเร็จ ระบบต้องแจ้งข้อผิดพลาดและไม่บันทึกการเลือกบางส่วน   <- UC-06 Exception
- FR-ADV-09 ระบบต้องแสดงกลุ่มที่นักศึกษาเลือกไว้แล้วเมื่อกลับเข้ามาที่ขั้นตอนนี้อีกครั้ง   <- UC-06 Postcondition

## Quality Requirements
- NFR-ADV-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-ADV-02 [Security] นักศึกษาแก้ไขการเลือกกลุ่มของคำขอของนักศึกษาคนอื่นไม่ได้ ต้องได้ HTTP 403
- NFR-ADV-03 [Usability] ข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย และระบุช่องที่ต้องแก้ไข   <- ข้อ 10
- NFR-ADV-04 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-ADV-01)
- NFR-ADV-05 [Data Integrity] การอนุมัติหรือบันทึกการเลือกกลุ่มต้องไม่ทำให้จำนวนนักศึกษาของอาจารย์เกินโควต้าตาม DOM-QUOTA-01 แม้มีการเลือกพร้อมกันหลายคน
- NFR-ADV-06 [Performance] บันทึกการเลือกกลุ่ม: เวลาตอบสนอง p95 <= 2 วินาที   <- ค่าที่เสนอไว้ ดู ASM-ADV-01

## Acceptance Criteria
- [ ] AC-ADV-01 (FR-ADV-02, FR-ADV-04, CON-ADV-01)
      Given มีรายการกลุ่มอาจารย์ที่เปิดรับ และนักศึกษาอยู่ระหว่างส่งผลการศึกษา
      When  เลือกกลุ่มและกดยืนยัน
      Then  ระบบบันทึกกลุ่มที่เลือกผูกกับคำขอส่งผลการศึกษาของนักศึกษาคนนั้น
- [ ] AC-ADV-02 (FR-ADV-05, DR-ADV-02)
      Given ไม่มีกลุ่มอาจารย์ที่เปิดรับ
      When  เข้าสู่ขั้นตอนเลือกกลุ่มอาจารย์
      Then  ระบบแจ้งว่าไม่สามารถเลือกได้ และไม่ให้ยืนยันขั้นตอนนี้
- [ ] AC-ADV-03 (FR-ADV-06, DR-ADV-03)
      Given ยังไม่ได้เลือกกลุ่มใด
      When  กดยืนยัน
      Then  ระบบไม่บันทึก และแจ้งให้เลือกกลุ่มก่อน
- [ ] AC-ADV-04 (FR-ADV-07, DOM-QUOTA-01)
      Given กลุ่มของอาจารย์ A มีจำนวนการอนุมัติของภาคการศึกษานั้นครบโควต้าแล้ว
      When  เปิดรายการกลุ่มและพยายามเลือกกลุ่มของอาจารย์ A
      Then  ระบบไม่อนุญาตให้เลือกกลุ่มนั้น
- [ ] AC-ADV-05 (NFR-ADV-05, DOM-QUOTA-01)
      Given อาจารย์ A เหลือโควต้า 1 ที่นั่ง และนักศึกษา 2 คนได้รับการอนุมัติพร้อมกัน
      When  ระบบบันทึกการอนุมัติกลุ่ม
      Then  มีเพียง 1 คนที่บันทึกสำเร็จ และอีกคนได้รับแจ้งว่าโควต้าเต็ม
- [ ] AC-ADV-06 (FR-ADV-08)
      Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึก
      When  กดยืนยันการเลือก
      Then  ไม่มีการบันทึกการเลือก และระบบแจ้งข้อผิดพลาด
- [ ] AC-ADV-07 (FR-ADV-09)
      Given นักศึกษาเลือกกลุ่มไว้แล้ว
      When  กลับเข้ามาที่ขั้นตอนเลือกกลุ่มอีกครั้ง
      Then  ระบบแสดงกลุ่มที่เลือกไว้เดิม
- [ ] AC-ADV-08 (NFR-ADV-02)
      Given นักศึกษา A ส่งคำสั่งเปลี่ยนกลุ่มของคำขอของนักศึกษา B
      When  ส่ง request ด้วย session ของ A
      Then  ระบบตอบ HTTP 403 และข้อมูลของ B ไม่เปลี่ยนแปลง

## Assumptions & Open Questions
- ASM-ADV-01 UC-06 ระบุ NFR เป็นหมวด (Usability, Data Integrity) ค่าตัวเลขใน NFR-ADV-04 และ NFR-ADV-06 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-ADV-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-ADV-03 โควต้าในข้อ 14 กำหนดต่ออาจารย์ 1 คนต่อ 1 ภาคการศึกษา และข้อมูลโควต้ามาจาก UC-12 ตามข้อ 4
- ASM-ADV-04 กลุ่มอาจารย์ที่ปรึกษาเป็น 1 อาจารย์ต่อ 1 กลุ่ม และแสดงข้อมูลที่เกี่ยวข้องกับกลุ่มให้เห็น เช่น ชื่อกลุ่มและรายละเอียดของกลุ่ม
- ASM-ADV-05 นักศึกษาเลือกได้ 1 กลุ่มเท่านั้นต่อคำขอส่งผลการศึกษา และไม่รองรับการจัดลำดับความต้องการหลายกลุ่ม
- ASM-ADV-06 โควต้าในข้อ 14 นับเมื่ออาจารย์อนุมัตินักศึกษาใน UC-09 แล้ว ไม่ใช่เมื่อนักศึกษาเลือกกลุ่มสำเร็จ
- OQ-ADV-04 นักศึกษาเปลี่ยนกลุ่มที่เลือกได้จนถึงเมื่อใด และถ้าอาจารย์อนุมัติแล้วยังเปลี่ยนได้หรือไม่
- OQ-ADV-05 กรณีทำงานแบบกลุ่ม/คู่ตาม UC-08 สมาชิกทุกคนต้องอยู่กลุ่มอาจารย์เดียวกันหรือไม่
