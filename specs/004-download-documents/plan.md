# แผนทางเทคนิค: SPEC-DOC-004 ดาวน์โหลดเอกสารที่เกี่ยวข้อง

สถานะ: ร่างเพื่อให้ทีมตรวจ

## 1. สรุปแนวทาง
- ฟีเจอร์นี้ให้นักศึกษาที่เข้าสู่ระบบดูเอกสารแบบฟอร์ม/เอกสารประกอบโครงงานที่เผยแพร่แล้ว โดยทุกคนเห็นชุดเดียวกันและแสดงเอกสารตามหมวดหมู่ (FR-DOC-01, DR-DOC-01, DR-DOC-02)
- นักศึกษาเลือกและดาวน์โหลดได้ครั้งละหนึ่งไฟล์ โดยรายการแสดงเฉพาะชื่อและคำอธิบาย ไม่แสดงสถานะพร้อมใช้งาน (FR-DOC-02, FR-DOC-04, ASM-DOC-07)
- API ตรวจ session และสิทธิ์ทุกครั้ง รวมถึงการเรียกไฟล์โดยตรง; ส่งไฟล์ผ่าน Backend หลังตรวจสิทธิ์เพื่อไม่เปิดลิงก์ Object Storage สาธารณะ (IF-AUTH-01, CON-DOC-01, FR-DOC-03, FR-DOC-08)
- รองรับเฉพาะ PDF/JPG/PNG ไม่เกิน 10 MB; เมื่อไม่มีเอกสารหรือไฟล์อ่านไม่ได้/หาไม่พบให้แจ้งภาษาไทยโดยไม่ส่งไฟล์ที่ไม่สมบูรณ์ (CON-FILE-01, DR-DOC-03, FR-DOC-05, FR-DOC-07)
- งานอัปโหลด/แก้ไขเอกสารของเจ้าหน้าที่และรายละเอียดหมวดหมู่ยังไม่ทำจนกว่าจะได้คำตอบตาม Open Questions (OUT-DOC-01, Q-01, Q-02)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React + Vite สำหรับหน้าบ้าน | IF-TECH-01; Vite เป็นค่าเริ่มต้นของรายวิชา ไม่ได้ระบุใน spec | React/PostgreSQL เป็นข้อกำหนด; Vite เป็นรายละเอียดเครื่องมือที่ทีมเลือกเอง |
| Python FastAPI สำหรับ Backend | ทีมเลือกเอง ไม่ได้มาจาก spec | ทีมยืนยันใช้ FastAPI ในการวางแผนฟีเจอร์ 002 |
| PostgreSQL สำหรับข้อมูลรายการเอกสาร | IF-TECH-01 | เก็บ metadata ที่ใช้แสดงรายการและอ้างถึงไฟล์ |
| Object storage สำหรับไฟล์จริง | ทีมเลือกเอง ไม่ได้มาจาก spec | ทีมเลือกแนวทางนี้แล้ว; ยังไม่ระบุผู้ให้บริการ |
| Session จากบัญชีมหาวิทยาลัย | IF-AUTH-01 | ทุก request ของฟีเจอร์ต้องมี session ตามเงื่อนไข |
| REST GET APIs | แนวทางทางเทคนิคของแผนนี้ | เสิร์ฟรายการและดาวน์โหลด; ทุกการขอไฟล์ต้องผ่าน Backend เพื่อตรวจสิทธิ์ตาม CON-DOC-01 |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | ความสัมพันธ์/ข้อกำหนด | รองรับ |
|---|---|---|---|
| เอกสาร (metadata ใน PostgreSQL) | รหัสเอกสาร, ชื่อ, คำอธิบาย, หมวดหมู่, สถานะเผยแพร่, ชนิดไฟล์, ขนาดไฟล์, object key | แสดงชื่อและคำอธิบาย; แสดงเฉพาะรายการเผยแพร่ที่ตรง CON-FILE-01; รายการเดียวกันสำหรับนักศึกษาทุกคน (DR-DOC-01, DR-DOC-02, DR-DOC-03, ASM-DOC-05) | FR-DOC-01, FR-DOC-05, FR-DOC-06 |
| หมวดหมู่เอกสาร | รหัสหมวดหมู่และชื่อที่ใช้จัดกลุ่ม | แสดงเป็นกลุ่มในหน้ารายการ; ชื่อหมวดหมู่และแหล่งกำหนดยังไม่ทราบ (Q-02) | FR-DOC-01, DR-DOC-01 |
| ไฟล์เอกสาร (Object Storage) | object key, ชนิดไฟล์, ขนาดไฟล์ | Backend อ่านไฟล์หลังตรวจ session/สิทธิ์; ไม่เปิด direct public URL; ตรวจว่าไม่ส่งข้อมูลบางส่วนเมื่อไฟล์อ่านไม่ได้ (CON-DOC-01, FR-DOC-03, FR-DOC-04, FR-DOC-07, FR-DOC-08) | FR-DOC-03, FR-DOC-04, FR-DOC-06, FR-DOC-07, FR-DOC-08 |

ไม่มี entity ประวัติการดาวน์โหลด (ASM-DOC-07). ไม่มี entity หรือ API สำหรับเจ้าหน้าที่อัปโหลด/แก้ไขเอกสารในฟีเจอร์นี้ (OUT-DOC-01, Q-01). ผู้ให้บริการ Object Storage ยังไม่ถูกเลือกและไม่กำหนดแทนทีม.

## 4. API / หน้าจอ

| รายการ | Method / path หรือหน้าจอ | Input / Output หลัก | รองรับ |
|---|---|---|---|
| อ่านรายการเอกสาร | `GET /api/documents` | Input: session; Output: เอกสารที่เผยแพร่แล้วและผ่าน CON-FILE-01 จัดกลุ่มตามหมวดหมู่ โดยแต่ละรายการมีชื่อและคำอธิบาย; รายการว่างแสดงข้อความไม่มีเอกสาร | FR-DOC-01, FR-DOC-05, DR-DOC-01, DR-DOC-02, DR-DOC-03 |
| ดาวน์โหลดเอกสาร | `GET /api/documents/{documentId}/download` | Input: session และรหัสเอกสาร; ตรวจสิทธิ์ก่อนอ่านไฟล์ทุกครั้ง แล้วส่งเนื้อหาไฟล์จาก Object Storage; ไม่มีสิทธิ์ตอบ HTTP 403; ไฟล์ไม่พร้อมแสดงข้อความภาษาไทยทั่วไปโดยไม่ส่งไฟล์บางส่วน | FR-DOC-02, FR-DOC-03, FR-DOC-04, FR-DOC-06, FR-DOC-07, FR-DOC-08, CON-DOC-01 |
| หน้ารายการเอกสาร | หน้าเว็บแสดงชื่อ/คำอธิบาย แบ่งตามหมวดหมู่ | ใช้ข้อมูลจาก GET; เลือกเอกสารหนึ่งรายการ; ไม่มีเอกสารแสดงคำอธิบาย; ไม่แสดงสถานะพร้อมใช้งาน | FR-DOC-01, FR-DOC-02, FR-DOC-05, DR-DOC-01, DR-DOC-02 |
| สถานะดาวน์โหลด/ข้อผิดพลาด | สถานะในหน้ารายการเอกสาร | แสดงผลสำเร็จหรือข้อความภาษาไทยที่ระบุว่าไฟล์ไม่พร้อมให้ดาวน์โหลด; ไม่แสดงไฟล์ที่ไม่สมบูรณ์ | FR-DOC-04, FR-DOC-07, NFR-DOC-04 |

การตอบกลับสำหรับกรณีไฟล์อ่านไม่ได้/หาไม่พบยังไม่กำหนด HTTP status code เพราะ spec ระบุเฉพาะข้อความและห้ามส่งไฟล์ไม่สมบูรณ์ (FR-DOC-07). API ไม่เปิด endpoint จัดการเอกสารของเจ้าหน้าที่ (OUT-DOC-01).

| IF-WEB-01 | หน้ารายการและดาวน์โหลดใช้งานผ่านเว็บเบราว์เซอร์ ไม่ต้องติดตั้งโปรแกรม | ใช้แล้ว |

## 7. ลำดับงาน

1. ตรวจ metadata เอกสารและข้อมูล Object Storage ที่ระบบมี; ยืนยันว่าการจัดการไฟล์ของเจ้าหน้าที่ไม่รวมในงานนี้ (OUT-DOC-01, Q-01)
2. กำหนด read-only metadata contract สำหรับชื่อ คำอธิบาย หมวดหมู่ สถานะเผยแพร่ ชนิด/ขนาดไฟล์ โดยคงชื่อหมวดหมู่ที่ยังไม่ทราบไว้ (DR-DOC-01, DR-DOC-02, Q-02)
3. สร้าง GET รายการ ตรวจ session กรองรายการเผยแพร่/ไฟล์ที่ตรงรูปแบบ และจัดกลุ่มตามหมวดหมู่ (IF-AUTH-01, FR-DOC-01, FR-DOC-05, DR-DOC-01, DR-DOC-02, DR-DOC-03, CON-FILE-01)
4. สร้างหน้ารายการเว็บ แสดงชื่อ/คำอธิบายและเลือกดาวน์โหลดครั้งละหนึ่งเอกสาร (IF-WEB-01, FR-DOC-02, NFR-DOC-05)
5. สร้าง GET ดาวน์โหลดที่ตรวจสิทธิ์ทุกครั้งและ stream ผ่าน Backend จาก Object Storage (CON-DOC-01, FR-DOC-03, FR-DOC-04, FR-DOC-06, FR-DOC-08)
6. จัดการไฟล์หาย/อ่านไม่ได้โดยไม่ส่งข้อมูลบางส่วน และแสดงข้อความภาษาไทยตามสาเหตุระดับผู้ใช้ (FR-DOC-07, NFR-DOC-04, AC-DOC-05)
7. ทดสอบ AC-DOC-01 ถึง AC-DOC-07 รวมกรณี unauthorized direct request, ไฟล์ไม่ผ่านข้อจำกัด และ timeout (CON-FILE-01, CON-DOC-01, AC-DOC-01 ถึง AC-DOC-07)
8. วัด availability, การเริ่มส่งไฟล์ 10 MB ภายใน 3 วินาที และ responsive ที่ 360 px; รับเกณฑ์ตรวจรับเพิ่มจากทีมก่อนสร้าง test เพิ่ม (NFR-DOC-03, NFR-DOC-05, NFR-DOC-06, Q-03)

## 8. สิ่งที่ยังไม่ทำ

- Q-01 ข้อกำหนดที่อนุมัติแล้วข้อใดจะครอบคลุมการอัปโหลดและปรับปรุงเอกสารโดยเจ้าหน้าที่ทุกคน และจะปรับ use case ที่เกี่ยวข้อง (เช่น UC-12) อย่างไร ก่อนนำงานนี้เข้าขอบเขต; ผู้ตอบ: ทีมเจ้าของ SRS/Use Case
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-02 หมวดหมู่เอกสารที่อนุมัติแล้วมีชื่อใดบ้าง และจะกำหนดรายการหมวดหมู่จากที่ใด; ผู้ตอบ: ทีมเจ้าของเอกสาร/ทีมเจ้าของ SRS
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-03 ต้องมีเกณฑ์ตรวจรับเฉพาะสำหรับ NFR-DOC-05 และ NFR-DOC-06 หรือไม่; หากต้องมี ให้ทีมอนุมัติ AC ID และเงื่อนไขทดสอบก่อนเพิ่ม เนื่องจากยังไม่มี AC ที่ครอบคลุมโดยตรง; ผู้ตอบ: ทีมเอง
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ

## หมายเหตุสำหรับทีม

- Constraint ทั้ง 5 ข้อถูกนำไปใช้ในแผน; ไม่มี Constraint ที่ยังไม่ได้ใช้
- AC-DOC-05 ต้องจำลองไฟล์เสีย/หาไม่พบ; AC-DOC-07 ต้องทดสอบ session timeout; NFR-DOC-03 ต้องติดตาม availability; NFR-DOC-06 ต้องวัดเวลาเริ่มส่งไฟล์ 10 MB ตามเกณฑ์ของทีม
