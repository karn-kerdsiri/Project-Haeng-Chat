# Feature: ตรวจสอบและอนุมัติผลการศึกษาของนักศึกษา (Advisor Review and Approval)
Spec ID: SPEC-APR-009 | Source: Use Case Specification UC-09 ตรวจสอบและอนุมัติผลการศึกษาของนักศึกษา (Includes UC-11) + รายการความต้องการของทีม ข้อ 7, ข้อ 8 | Use case: UC-09
Owner: ทีม B | Status: Draft v2 | Updated: 2569-11-13

## Goal
อาจารย์ที่ปรึกษาตรวจสอบข้อมูลผลการศึกษาของนักศึกษาที่อยู่ในความดูแล
แล้วอนุมัติหรือส่งกลับให้แก้ไขได้ โดยระบบบันทึกผลพร้อมสถานะและผู้ดำเนินการ

## Scope
### In scope
- IN-APR-01 แสดงรายการนักศึกษาที่อยู่ในความดูแลและรอตรวจสอบ          <- UC-09 ขั้น 1, Trigger
- IN-APR-02 เลือกนักศึกษาหนึ่งคนต่อครั้งและแสดงผลการศึกษากับข้อมูลที่เกี่ยวข้อง   <- UC-09 ขั้น 2-3, ASM-APR-05
- IN-APR-03 อนุมัติหรือส่งกลับให้นักศึกษาที่เลือกแก้ไขทีละคน                  <- UC-09 ขั้น 4-5, ASM-APR-05
- IN-APR-04 บันทึกผลการตรวจสอบและสถานะ พร้อมผู้ดำเนินการ            <- UC-09 ขั้น 6, Postcondition + ข้อ 8
- IN-APR-05 เรียกใช้ขั้นตอนลงนาม/รับรองเอกสารตามความสัมพันธ์ include   <- UC-09 Includes UC-11
### Out of scope
- OUT-APR-01 รายละเอียดการลงนาม/รับรองเอกสาร - เป็นของ UC-11 spec นี้เพียงเรียกใช้
- OUT-APR-02 การตรวจสอบและยืนยันโดยเจ้าหน้าที่ - เป็นของ UC-13
- OUT-APR-03 การคำนวณผลการตรวจสอบคุณสมบัติ - เป็นของ UC-16
- OUT-APR-04 การเผยแพร่ผล - เป็นของ UC-14
- OUT-APR-05 การกำหนดว่านักศึกษาคนใดอยู่ในความดูแลของอาจารย์คนใด - มาจาก UC-06 และข้อมูลที่จัดการใน UC-12
- OUT-APR-06 การแจ้งเตือนนักศึกษาเมื่อถูกส่งกลับให้แก้ไข - เป็นของ UC-17 (ดู Q-03)

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลผลการตรวจสอบเก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- IF-AUDIT-01 ทุกการเปลี่ยนสถานะคำร้องต้องบันทึกประวัติการแก้ไขและผู้ดำเนินการให้เจ้าหน้าที่เรียกดูได้   <- ข้อ 8
- CON-APR-01 อาจารย์ต้องเห็นและดำเนินการได้เฉพาะนักศึกษาที่อยู่ในความดูแลของตน   <- UC-09 Precondition
- CON-APR-02 เมื่อบันทึกผลไม่สำเร็จ สถานะคำร้องต้องไม่เปลี่ยน   <- UC-09 Exception

## Data Rules
- DR-APR-01 ข้อมูลที่แสดงต่อ 1 รายการในรายการรอตรวจสอบ: ชื่อนักศึกษา รหัสนักศึกษา และสถานะคำร้อง   <- UC-09 ขั้น 1 + ข้อ 7
- DR-APR-02 ข้อมูลที่แสดงเมื่อเลือกนักศึกษา: ผลการศึกษาที่ส่งมา และข้อมูลที่เกี่ยวข้องกับคำร้องนั้น   <- UC-09 ขั้น 3 (ขอบเขตรอยืนยัน ดู Q-01)
- DR-APR-03 ผลการตัดสินใจของอาจารย์มี 2 ค่า: อนุมัติ และ ส่งกลับให้แก้ไข   <- UC-09 ขั้น 5
- DR-APR-04 เมื่อส่งกลับให้แก้ไข อาจารย์ต้องกรอกเหตุผลเป็นข้อความเองก่อนส่งกลับ; หากยังไม่กรอก ระบบต้องไม่ส่งกลับ   <- UC-09 alt 1, ASM-APR-04
- DR-APR-05 ประวัติที่บันทึกต่อ 1 การกระทำ: ผู้ดำเนินการ เวลา สถานะก่อนและหลัง   <- ข้อ 8

## Requirements
- FR-APR-01 ระบบต้องแสดงรายการนักศึกษาที่อยู่ในความดูแลของอาจารย์ผู้เรียกตาม CON-APR-01 และ DR-APR-01   <- UC-09 ขั้น 1
- FR-APR-02 ระบบต้องให้อาจารย์เลือกนักศึกษาหนึ่งคนต่อครั้งและแสดงข้อมูลตาม DR-APR-02   <- UC-09 ขั้น 2-3, ASM-APR-05
- FR-APR-03 ระบบต้องให้อาจารย์เลือกผลการตัดสินใจสำหรับนักศึกษาที่เลือกหนึ่งคนตาม DR-APR-03   <- UC-09 ขั้น 4-5, ASM-APR-05
- FR-APR-04 เมื่ออาจารย์อนุมัติ ระบบต้องบันทึกผลและเปลี่ยนสถานะคำร้องเป็นสถานะหลังอนุมัติ   <- UC-09 ขั้น 6, Postcondition
- FR-APR-05 เมื่ออาจารย์ส่งกลับให้แก้ไข ระบบต้องกำหนดให้กรอกเหตุผลเป็นข้อความตาม DR-APR-04 ก่อนส่งกลับ; หากไม่มีเหตุผล ระบบต้องไม่ส่งกลับ; เมื่อมีเหตุผลจึงบันทึกผลและเปลี่ยนสถานะเป็นรอการแก้ไขของนักศึกษา   <- UC-09 alt 1, ASM-APR-04
- FR-APR-06 เมื่อไม่มีรายการนักศึกษาที่รอตรวจสอบ ระบบต้องแจ้งว่าไม่มีรายการ   <- UC-09 alt 2
- FR-APR-07 หากบันทึกผลไม่สำเร็จ ระบบต้องแจ้งข้อผิดพลาดและคงสถานะเดิมตาม CON-APR-02   <- UC-09 Exception
- FR-APR-08 ระบบต้องบันทึกประวัติการแก้ไขและผู้ดำเนินการตาม DR-APR-05 ทุกครั้งที่สถานะเปลี่ยน   <- ข้อ 8
- FR-APR-09 ระบบต้องแสดงสถานะล่าสุดของคำร้องหลังบันทึกผล ทั้งฝั่งอาจารย์และให้นักศึกษาเห็นผ่าน UC-03   <- ข้อ 7
- FR-APR-10 หลังอนุมัติ ระบบต้องให้อาจารย์ดำเนินการลงนาม/รับรองเอกสารตาม UC-11 ต่อได้   <- UC-09 Includes UC-11
- FR-APR-11 ระบบต้องปฏิเสธการอนุมัติหรือส่งกลับคำร้องของนักศึกษาที่ไม่อยู่ในความดูแลของผู้เรียกด้วย HTTP 403   <- CON-APR-01

## Quality Requirements
- NFR-APR-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-APR-02 [Authorization] เฉพาะผู้ใช้บทบาทอาจารย์ที่ปรึกษาที่เป็นผู้ดูแลนักศึกษาคนนั้นจึงจะอนุมัติหรือส่งกลับได้   <- UC-09 NFR (Security, Authorization)
- NFR-APR-03 [Auditability] ประวัติการอนุมัติและการส่งกลับต้องเก็บไว้ไม่น้อยกว่า 1 ปี และลบหรือแก้ไขย้อนหลังไม่ได้   <- UC-09 NFR (Auditability) + ข้อ 8 (ระยะเวลา 1 ปีเป็นค่าที่เสนอไว้ ดู ASM-APR-01)
- NFR-APR-04 [Usability] ข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย และระบุช่องที่ต้องแก้ไข   <- ข้อ 10
- NFR-APR-05 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-APR-01)
- NFR-APR-06 [Performance] บันทึกผลการอนุมัติ: เวลาตอบสนอง p95 <= 2 วินาที   <- ค่าที่เสนอไว้ ดู ASM-APR-01

## Acceptance Criteria
- [ ] AC-APR-01 (FR-APR-04, FR-APR-08)
      Given มีรายการของนักศึกษาที่อาจารย์มีสิทธิ์ตรวจสอบ
      When  อาจารย์ตรวจสอบและกดอนุมัติ
      Then  ระบบบันทึกผล เปลี่ยนสถานะเป็นสถานะหลังอนุมัติ และมีประวัติที่ระบุผู้ดำเนินการกับเวลา
- [ ] AC-APR-02 (FR-APR-05, DR-APR-04)
      Given ข้อมูลของนักศึกษาไม่ครบหรือไม่ถูกต้องและอาจารย์ยังไม่กรอกเหตุผล
      When  อาจารย์พยายามส่งกลับให้แก้ไข
      Then  ระบบไม่ส่งกลับ ไม่เปลี่ยนสถานะ และแจ้งให้กรอกเหตุผล
      Given ข้อมูลของนักศึกษาไม่ครบหรือไม่ถูกต้องและอาจารย์กรอกเหตุผลเป็นข้อความแล้ว
      When  อาจารย์ส่งกลับให้แก้ไข
      Then  ระบบบันทึกเหตุผล และเปลี่ยนสถานะเป็นรอการแก้ไขของนักศึกษา
- [ ] AC-APR-03 (FR-APR-06)
      Given ไม่มีนักศึกษาที่รอตรวจสอบในความดูแลของอาจารย์
      When  เปิดเมนูรายการนักศึกษาที่รอตรวจสอบ
      Then  ระบบแจ้งว่าไม่มีรายการ
- [ ] AC-APR-04 (FR-APR-07, CON-APR-02)
      Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึกผล
      When  อาจารย์กดอนุมัติ
      Then  ระบบแจ้งข้อผิดพลาด และสถานะคำร้องยังเป็นสถานะเดิม
- [ ] AC-APR-05 (FR-APR-11, CON-APR-01, NFR-APR-02)
      Given นักศึกษา X ไม่อยู่ในความดูแลของอาจารย์ Y
      When  อาจารย์ Y ส่ง request อนุมัติคำร้องของนักศึกษา X
      Then  ระบบตอบ HTTP 403 และคำร้องของ X ไม่เปลี่ยนแปลง
- [ ] AC-APR-06 (FR-APR-09)
      Given อาจารย์อนุมัติคำร้องแล้ว
      When  นักศึกษาเปิดหน้าผลการตรวจสอบของตนเองตาม UC-03
      Then  สถานะที่นักศึกษาเห็นตรงกับสถานะหลังอนุมัติ
- [ ] AC-APR-07 (FR-APR-10)
      Given คำร้องได้รับการอนุมัติจากอาจารย์แล้ว
      When  อาจารย์เปิดเมนูลงนาม/รับรองเอกสาร
      Then  ระบบให้ดำเนินการตาม UC-11 ได้
- [ ] AC-APR-08 (NFR-APR-03, FR-APR-08)
      Given มีการเปลี่ยนสถานะคำร้อง 1 ครั้ง
      When  เจ้าหน้าที่เรียกดูประวัติของคำร้องนั้น
      Then  มีประวัติ 1 รายการที่ระบุผู้ดำเนินการ เวลา และสถานะก่อน/หลัง และแก้ไขย้อนหลังไม่ได้

## Assumptions & Open Questions
- ASM-APR-01 UC-09 ระบุ NFR เป็นหมวด (Security, Authorization, Auditability) ค่าตัวเลขใน NFR-APR-03, NFR-APR-05 และ NFR-APR-06 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน (Q-06)
- ASM-APR-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-APR-03 ความสัมพันธ์ "นักศึกษาในความดูแล" มาจากกลุ่มอาจารย์ที่นักศึกษาเลือกใน UC-06
- ASM-APR-04 การส่งกลับให้แก้ไขต้องมีเหตุผลเป็นข้อความที่อาจารย์กรอกเอง และหากยังไม่กรอกเหตุผลจะยังส่งกลับไม่ได้ (คำตอบทีมต่อ Q3)
- ASM-APR-05 อาจารย์ตรวจและอนุมัติหรือส่งกลับนักศึกษาทีละคนตาม UC-09; ยังไม่รองรับการอนุมัติหลายรายการพร้อมกัน (คำตอบทีมต่อ Q8)
- Q-01 (เดิม OQ-APR-01) อาจารย์ต้องเห็นข้อมูลอะไรบ้างในหน้าตรวจสอบ (รายวิชาและเกรดทั้งหมด ผลการตรวจเบื้องต้นจาก UC-07 ข้อมูลสมาชิกกลุ่มจาก UC-08 หรือเอกสารแนบ); ต้องรอคำตอบจากทีมและอาจารย์ที่ปรึกษา
- Q-02 (เดิม OQ-APR-03) ชื่อสถานะหลังอนุมัติและหลังส่งกลับใช้คำว่าอะไร และต้องสอดคล้องกับรายการสถานะใน OQ-OWN-01 ของ specs/003 อย่างไร; ต้องรอคำตอบจากทีม ผู้รับผิดชอบ UC-03 และอาจารย์ผู้ตรวจสอบ
- Q-03 (เดิม OQ-APR-04) เมื่ออาจารย์ส่งกลับให้แก้ไข ต้องแจ้งเตือนนักศึกษาผ่าน UC-17 หรือไม่; ต้องรอคำตอบจากทีมและผู้รับผิดชอบ UC-17
- Q-04 (เดิม OQ-APR-05) เมื่อนักศึกษาส่งผลเพิ่มเติมตาม UC-02 หลังอาจารย์อนุมัติแล้ว อาจารย์ต้องอนุมัติใหม่หรือไม่; ต้องรอคำตอบจากทีม ผู้รับผิดชอบ UC-02 และอาจารย์ที่ปรึกษา
- Q-05 (IF-AUTH-01, IF-AUDIT-01, FR-APR-07, CON-APR-02, AC-APR-04) เมื่อระบบบัญชีมหาวิทยาลัย ฐานข้อมูล หรือการบันทึกประวัติไม่พร้อมขณะอนุมัติหรือส่งกลับ ระบบต้องแจ้งและคงสถานะ/ประวัติอย่างไร; ต้องรอคำตอบจากทีมและผู้ดูแลระบบบัญชี/ฐานข้อมูล
- Q-06 (ASM-APR-01, NFR-APR-03, NFR-APR-05, NFR-APR-06) ทีมยืนยันค่าระยะเก็บประวัติ 1 ปี, หน้าจอ 360 px และ p95 2 วินาทีหรือไม่; หากไม่ยืนยัน ต้องใช้ค่าใด; ต้องรอคำตอบจากทีม
- Q-07 (IF-AUTH-01, FR-APR-01, FR-APR-02, FR-APR-09, NFR-APR-01, NFR-APR-04, NFR-APR-05, NFR-APR-06) AC ปัจจุบันยังไม่ตรวจข้อมูลรายการรอตรวจสอบที่ไม่ว่าง สถานะล่าสุดฝั่งอาจารย์ การตอบ HTTP 401, timeout, ข้อความภาษาไทย/ช่องที่ต้องแก้, การใช้งานบนมือถือ และ p95 โดยตรง; ทีมจะปรับ AC เดิมให้ครอบคลุมอย่างไรโดยไม่สร้าง ID ใหม่; ต้องรอคำตอบจากทีม
