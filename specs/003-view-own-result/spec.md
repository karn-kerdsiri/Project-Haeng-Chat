# Feature: ดูผลการตรวจสอบคุณสมบัติของตนเอง (View Own Eligibility Result)
Spec ID: SPEC-OWN-003 | Source: Use Case Specification UC-03 ดูผลการตรวจสอบคุณสมบัติของตนเอง + รายการความต้องการของทีม ข้อ 7 | Use case: UC-03
Owner: ทีม B | Status: Draft v2 | Updated: 2569-11-13

## Goal
นักศึกษาที่เข้าสู่ระบบแล้ว ดูสถานะคำร้องและผลการตรวจสอบคุณสมบัติของตนเองได้ชัดเจน
โดยระบบแสดงเฉพาะข้อมูลของนักศึกษาคนนั้น และแสดงสถานะล่าสุดเสมอ
"สถานะคำร้อง" และ "ผลการตรวจสอบ" เป็นข้อมูล 2 ชุดที่แยกกันตาม ASM-OWN-04

## Scope
### In scope
- IN-OWN-01 ตรวจสอบสิทธิ์ของนักศึกษาก่อนแสดงข้อมูล                     <- UC-03 ขั้น 1
- IN-OWN-02 ดึงและแสดงสถานะ/ผลการตรวจสอบของนักศึกษาคนนั้น              <- UC-03 ขั้น 2-3
- IN-OWN-03 แสดงเหตุผลประกอบเมื่อผลการตรวจสอบเป็น "ไม่ผ่าน"              <- UC-03 ขั้น 4 + ASM-OWN-07
- IN-OWN-04 แสดงสถานะ "รอตรวจสอบ" เมื่อยังไม่มีผล                      <- UC-03 alt 1
- IN-OWN-05 แจ้งรายการที่นักศึกษาต้องดำเนินการเมื่อข้อมูลยังไม่ครบ         <- UC-03 alt 2
### Out of scope
- OUT-OWN-01 การกรอกหรือส่งผลการศึกษา - เป็นของ UC-01 และ UC-02
- OUT-OWN-02 การคำนวณผลการตรวจสอบคุณสมบัติ - เป็นของ UC-16 spec นี้แสดงผลที่คำนวณไว้แล้วเท่านั้น
- OUT-OWN-03 การเผยแพร่ผล - เป็นของ UC-14 spec นี้เพียงอ่านสถานะการเผยแพร่ตาม ASM-OWN-06
- OUT-OWN-04 การแจ้งเตือนเมื่อมีผลใหม่ - เป็นของ UC-17
- OUT-OWN-05 การดูผลของนักศึกษาคนอื่น - เป็นของ UC-10 (อาจารย์) และ UC-13 (เจ้าหน้าที่)
- OUT-OWN-06 การดาวน์โหลดเอกสารผลการตรวจสอบ - เป็นของ UC-04
- OUT-OWN-07 หน้ารายละเอียดแยกที่แสดงรายวิชาทุกวิชาและเงื่อนไขการผ่านทีละข้อ - ทีมเลือกระดับการแสดงผลเป็นระดับ 2 ตาม ASM-OWN-07

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลอ่านจากฐานข้อมูล PostgreSQL   <- ข้อ 19
- CON-OWN-01 ระบบต้องแสดงผลของนักศึกษาที่เป็นเจ้าของ session เท่านั้น   <- UC-03 Postcondition
- CON-OWN-02 ระบบต้องอ่านสถานะและผลการตรวจสอบจากฐานข้อมูลใหม่ทุกครั้งที่เปิดหน้า ห้ามเก็บสำเนาไว้แสดงซ้ำ (ห้ามแคช)   <- UC-03 Acceptance Criteria + ASM-OWN-08

## Data Rules
- DR-OWN-01 ข้อมูลที่แสดงต่อ 1 คำร้อง: สถานะปัจจุบันของคำร้องตาม DR-OWN-02 และผลการตรวจสอบคุณสมบัติตาม DR-OWN-04 (ถ้ามี)   <- UC-03 ขั้น 3 + ข้อ 7
- DR-OWN-02 สถานะคำร้องมี 2 ค่าเท่านั้น: "รอตรวจสอบ" และ "เสร็จสิ้น" โดย "รอเจ้าหน้าที่ตรวจสอบ" ในข้อ 7 คือสถานะเดียวกับ "รอตรวจสอบ"   <- ข้อ 7 + UC-03 alt 1 + ASM-OWN-03 (ข้อความที่แสดงบนหน้าจอของแต่ละสถานะ ดู OQ-OWN-01)
- DR-OWN-03 เมื่อข้อมูลของนักศึกษายังไม่ครบ ต้องแสดงรายการสิ่งที่ต้องดำเนินการเป็นรายข้อ   <- UC-03 alt 2 (กรณีที่เกิดได้จริง ดู OQ-OWN-08)
- DR-OWN-04 ผลการตรวจสอบคุณสมบัติเป็นข้อมูลแยกจากสถานะ มี 2 ค่า: "ผ่านเงื่อนไข" และ "ไม่ผ่าน" และมีค่าได้เฉพาะเมื่อสถานะเป็น "เสร็จสิ้น" และเจ้าหน้าที่เผยแพร่ผลแล้ว   <- ASM-OWN-04, ASM-OWN-06
- DR-OWN-05 เมื่อผลเป็น "ไม่ผ่าน" ต้องแสดงเหตุผลประกอบที่ระบุเงื่อนไขที่ไม่ผ่านพร้อมจำนวน เช่น "ยังมี I ค้างอยู่ 2 วิชา"   <- ASM-OWN-07
- DR-OWN-06 นักศึกษา 1 คนมีคำร้องได้ 1 คำร้อง หน้านี้แสดงข้อมูลของคำร้องนั้นตามการส่งหรือการแก้ไขครั้งล่าสุด   <- ASM-OWN-09

## Requirements
- FR-OWN-01 ระบบต้องตรวจสอบสิทธิ์ของผู้เรียกก่อนดึงข้อมูลทุกครั้ง โดยไม่มี session ตอบ HTTP 401 ตาม IF-AUTH-01 และมี session แต่ไม่ใช่เจ้าของคำร้องตอบ HTTP 403 ตาม FR-OWN-08   <- UC-03 ขั้น 1
- FR-OWN-02 ระบบต้องดึงและแสดงสถานะกับผลการตรวจสอบของนักศึกษาที่เป็นเจ้าของ session ตาม DR-OWN-01 และ DR-OWN-06   <- UC-03 ขั้น 2-3
- FR-OWN-03 ระบบต้องแสดงสถานะปัจจุบันของคำร้องด้วยข้อความที่กำหนดไว้ล่วงหน้าของแต่ละสถานะตาม DR-OWN-02   <- ข้อ 7
- FR-OWN-04 เมื่อผลการตรวจสอบเป็น "ไม่ผ่าน" ระบบต้องแสดงเหตุผลประกอบตาม DR-OWN-05 บนหน้าเดียวกัน   <- UC-03 ขั้น 4 + ASM-OWN-07
- FR-OWN-05 เมื่อยังไม่มีผลการตรวจสอบ ระบบต้องแสดงสถานะ "รอตรวจสอบ" และต้องไม่แสดงค่าผ่านหรือไม่ผ่านใด ๆ   <- UC-03 alt 1 (ข้อนี้รวม 2 พฤติกรรม การแยกข้อต้องสร้าง ID ใหม่ ดู OQ-OWN-10)
- FR-OWN-06 เมื่อข้อมูลของนักศึกษายังไม่ครบ ระบบต้องแจ้งรายการที่ต้องดำเนินการตาม DR-OWN-03   <- UC-03 alt 2
- FR-OWN-07 เมื่อเรียกข้อมูลไม่สำเร็จ ระบบต้องแสดงข้อผิดพลาดพร้อมช่องทางให้ลองใหม่ และต้องไม่แสดงค่าสถานะหรือผลใด ๆ   <- UC-03 Exception + CON-OWN-02
- FR-OWN-08 เมื่อ session ไม่มีสิทธิ์ในคำร้องที่ขอ ระบบต้องปฏิเสธด้วย HTTP 403 และไม่คืนข้อมูลใด   <- CON-OWN-01

## Quality Requirements
- NFR-OWN-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-OWN-02 [Privacy] ผลการตรวจสอบของนักศึกษาคนหนึ่งต้องไม่ปรากฏต่อนักศึกษาคนอื่นในทุกช่องทางของฟีเจอร์นี้   <- UC-03 NFR (Security, Privacy)
- NFR-OWN-03 [Usability] ข้อความสถานะ ข้อความเหตุผล และข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย   <- ข้อ 10
- NFR-OWN-04 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-OWN-01)
- NFR-OWN-05 [Performance] หน้าผลการตรวจสอบ: เวลาตอบสนอง p95 <= 2 วินาที   <- ค่าที่เสนอไว้ ดู ASM-OWN-01 (ยังไม่มี AC และยังไม่ระบุจำนวนผู้ใช้พร้อมกันที่ใช้วัด ดู OQ-OWN-10)

## Acceptance Criteria
- [ ] AC-OWN-01 (FR-OWN-02, FR-OWN-03, CON-OWN-01, CON-OWN-02)
      Given นักศึกษาเข้าสู่ระบบแล้ว และมีผลการตรวจสอบของตนเองที่เผยแพร่แล้วอยู่ในระบบ
      When  เปิดหน้าผลการตรวจสอบ
      Then  ระบบแสดงเฉพาะข้อมูลของนักศึกษาคนนั้น โดยสถานะและผลตรงกับค่าล่าสุดในฐานข้อมูล
- [ ] AC-OWN-02 (FR-OWN-05, DR-OWN-02)
      Given คำร้องของนักศึกษายังไม่มีผลการตรวจสอบ
      When  เปิดหน้าผลการตรวจสอบ
      Then  ระบบแสดงสถานะ "รอตรวจสอบ" และไม่แสดงค่าผ่านเงื่อนไขหรือไม่ผ่านใด ๆ
- [ ] AC-OWN-03 (FR-OWN-06, DR-OWN-03)
      Given ข้อมูลของนักศึกษายังไม่ครบ
      When  เปิดหน้าผลการตรวจสอบ
      Then  ระบบแสดงรายการสิ่งที่ต้องดำเนินการเป็นรายข้อ
- [ ] AC-OWN-04 (FR-OWN-08, NFR-OWN-02)
      Given นักศึกษา A เรียกผลการตรวจสอบของนักศึกษา B
      When  ส่ง request ด้วย session ของ A
      Then  ระบบตอบ HTTP 403 และไม่คืนข้อมูลของ B
- [ ] AC-OWN-05 (FR-OWN-07)
      Given แหล่งข้อมูลผลการตรวจสอบไม่พร้อมใช้งาน
      When  เปิดหน้าผลการตรวจสอบ
      Then  ระบบแสดงข้อความผิดพลาดภาษาไทยพร้อมช่องทางลองใหม่ และไม่แสดงค่าสถานะหรือผลใด ๆ
- [ ] AC-OWN-06 (FR-OWN-03, DR-OWN-02)
      Given คำร้องอยู่ในสถานะ "รอตรวจสอบ"
      When  เปิดหน้าผลการตรวจสอบ
      Then  ระบบแสดงข้อความสถานะที่กำหนดไว้ของสถานะ "รอตรวจสอบ"
- [ ] AC-OWN-07 (NFR-OWN-01)
      Given ผู้ใช้ไม่มีการใช้งานต่อเนื่องเกิน 30 นาที
      When  เปิดหน้าผลการตรวจสอบอีกครั้ง
      Then  ระบบตัดการเชื่อมต่อและให้ยืนยันตัวตนใหม่
- [ ] AC-OWN-08 (NFR-OWN-04)
      Given เปิดหน้าผลการตรวจสอบบนจอกว้าง 360 px
      When  แสดงผลเสร็จ
      Then  เนื้อหาอ่านได้ครบและไม่มีการเลื่อนแนวนอน

## Assumptions & Open Questions
- ASM-OWN-01 UC-03 ระบุ NFR เป็นหมวด (Security, Privacy, Usability) ค่าตัวเลขใน NFR-OWN-04 และ NFR-OWN-05 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-OWN-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-OWN-03 ทีมตัดสินว่าสถานะคำร้องในกระบวนการตรวจสอบคุณสมบัติมี 2 ค่าคือ "รอตรวจสอบ" และ "เสร็จสิ้น" และ "รอตรวจสอบ" กับ "รอเจ้าหน้าที่ตรวจสอบ" เป็นสถานะเดียวกัน หมายถึงรอให้เจ้าหน้าที่เข้ามาตรวจว่าเกรดถูกต้อง (คำตอบทีม 2569-11-13) ตรงกับ ASM-ADD-04 ใน specs/002
- ASM-OWN-04 ทีมตัดสินว่าผลการตรวจสอบ (ผ่านเงื่อนไข/ไม่ผ่าน) เป็นข้อมูลแยกจากสถานะ เป็นผลที่เกิดหลังการตรวจสอบเสร็จ และนักศึกษายังแก้ไขข้อมูลต่อได้แม้สถานะเป็น "เสร็จสิ้น" แล้ว (คำตอบทีม 2569-11-13)
- ASM-OWN-05 ทีมตัดสินว่ากระบวนการส่งผลเพื่อตรวจสอบเงื่อนไขไม่มีขั้นตอนให้อาจารย์ที่ปรึกษาอนุมัติ จึงไม่มีสถานะ "รออาจารย์อนุมัติ" ในฟีเจอร์นี้ ส่วนการอนุมัติของอาจารย์และคณะกรรมการยังมีอยู่สำหรับการส่งเอกสารขั้นเริ่มทำโปรเจกต์ ซึ่งเป็นกระบวนการอื่น (คำตอบทีม 2569-11-13) spec นี้จึงไม่กระทบ specs/009-advisor-approve-record ดู OQ-OWN-11
- ASM-OWN-06 ทีมตัดสินว่านักศึกษาเห็นผลการตรวจสอบได้หลังเจ้าหน้าที่กดเผยแพร่ผลตาม UC-14 เท่านั้น ก่อนนั้นเห็นได้เฉพาะสถานะ (คำตอบทีม 2569-11-13) การอ่านสถานะการเผยแพร่ยังไม่มี Constraint รองรับ ดู OQ-OWN-07
- ASM-OWN-07 ทีมตัดสินว่าหน้านี้แสดงผลรวมพร้อมเหตุผลประกอบ (ระดับ 2) ไม่มีหน้ารายละเอียดแยกที่แสดงรายวิชาทุกวิชาหรือเงื่อนไขการผ่านทีละข้อ (คำตอบทีม 2569-11-13) FR-OWN-04 จึงเปลี่ยนจาก "เปิดดูรายละเอียด" เป็น "แสดงเหตุผลประกอบ" และเพิ่ม OUT-OWN-07
- ASM-OWN-08 ทีมตัดสินว่าไม่ใช้แคช ให้อ่านข้อมูลใหม่ทุกครั้งที่เปิดหน้า (คำตอบทีม 2569-11-13) CON-OWN-02 จึงเขียนเป็นข้อห้ามแคชโดยตรง
- ASM-OWN-09 ทีมตัดสินว่านักศึกษา 1 คนมี 1 คำร้อง หน้านี้แสดงการส่งหรือแก้ไขครั้งล่าสุด และส่งซ้ำได้เมื่อมีการเปลี่ยนแปลงผลเกรดเท่านั้น โดยไม่จำกัดจำนวนครั้ง (คำตอบทีม 2569-11-13) ต้องปรับ ASM-ADD-09 ใน specs/002 ให้ตรงกัน
- ASM-OWN-10 ทีมยืนยันว่า I คือผลที่ยังไม่สมบูรณ์และยังไม่นับว่าผ่าน W คือการถอนรายวิชา และภาควิชากำหนดว่าค้างรายวิชาที่ยังไม่ออกผลได้ไม่เกิน 1 วิชาจึงยังถือว่าผ่านเงื่อนไข (คำตอบทีม 2569-11-13) เกณฑ์นี้เป็นเงื่อนไขการผ่าน ดู OQ-OWN-09
- ASM-OWN-11 ทีมตัดสินว่าหน้ากรอกข้อมูลต้องกรอกเกรดให้ครบทุกรายวิชา ถ้าผลยังไม่ออกให้เลือก I ห้ามปล่อยว่าง (คำตอบทีม 2569-11-13) กฎนี้เป็นของ specs/001 และ specs/002 ไม่ใช่ฟีเจอร์นี้ แต่กระทบ FR-OWN-06 ดู OQ-OWN-08
- OQ-OWN-01 ข้อความที่แสดงบนหน้าจอของแต่ละสถานะใช้คำว่าอะไรแน่ สถานะ "รอตรวจสอบ" จะแสดงว่า "รอตรวจสอบ" หรือ "รอเจ้าหน้าที่ตรวจสอบ" และสถานะ "เสร็จสิ้น" แสดงว่าอะไร (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
- OQ-OWN-06 ค่าเกรด T หมายถึงอะไร และนับเป็นผลที่สมบูรณ์หรือไม่สมบูรณ์ (ต้องถาม: เจ้าหน้าที่งานทะเบียน) ตรงกับ OQ-ADD-01 ใน specs/002
- OQ-OWN-07 ตาม ASM-OWN-06 ระบบต้องอ่านสถานะการเผยแพร่ผลจาก UC-14 ก่อนแสดงผล ซึ่งยังไม่มี Constraint รองรับ ผมสร้าง IF ID ใหม่เองไม่ได้ จึงเสนอให้ทีมอนุมัติเพิ่ม IF-PUB-01 "ระบบต้องอ่านสถานะการเผยแพร่ผลของคำร้องก่อนแสดงผลการตรวจสอบทุกครั้ง" และตอบด้วยว่าถ้าอ่านสถานะการเผยแพร่ไม่ได้ ต้องถือว่ายังไม่เผยแพร่หรือเผยแพร่แล้ว (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้เผยแพร่ผล)
- OQ-OWN-08 ถ้าหน้ากรอกข้อมูลห้ามปล่อยช่องว่างตาม ASM-OWN-11 กรณี "ข้อมูลยังไม่ครบ" ตาม FR-OWN-06 และ UC-03 alt 2 จะเกิดขึ้นได้ในสถานการณ์ใด และรายการที่ต้องดำเนินการมีอะไรได้บ้าง ถ้าเกิดขึ้นไม่ได้เลย FR-OWN-06, DR-OWN-03, IN-OWN-05 และ AC-OWN-03 ต้องจัดการอย่างไร เพราะผมลบ ID เองไม่ได้ (ต้องถาม: เจ้าหน้าที่ผู้ตรวจสอบคำร้อง และทีมเอง)
- OQ-OWN-09 เกณฑ์ "ค้างรายวิชาที่ยังไม่ออกผลได้ไม่เกิน 1 วิชา" ตาม ASM-OWN-10 เป็นเงื่อนไขการผ่านที่ควรอยู่ในข้อมูลที่เจ้าหน้าที่จัดการตาม UC-12 และใช้คำนวณใน UC-16 ต้องให้ specs/012 และ specs/016 รองรับเกณฑ์นี้หรือไม่ และ W นับรวมในจำนวนที่ค้างด้วยหรือไม่ (ต้องถาม: ภาควิชา หรือเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
- OQ-OWN-10 ข้อที่ยังตามรอยไม่ได้ ผมสร้าง AC ID ใหม่เองไม่ได้ จึงเสนอให้ทีมอนุมัติเพิ่ม AC ตามนี้ (ต้องถาม: ทีมเอง)
  - AC-OWN-09 (FR-OWN-01, IF-AUTH-01): เรียกหน้านี้โดยไม่มี session ต้องได้ HTTP 401
  - AC-OWN-10 (FR-OWN-04, DR-OWN-05): ผลเป็น "ไม่ผ่าน" เพราะค้าง I 2 วิชา หน้าจอต้องแสดงเหตุผลที่ระบุจำนวนวิชาที่ค้าง
  - AC-OWN-11 (CON-OWN-02, ASM-OWN-08): เจ้าหน้าที่เปลี่ยนสถานะแล้ว นักศึกษาเปิดหน้าใหม่ต้องเห็นค่าใหม่ทันที
  - AC-OWN-12 (NFR-OWN-03): ข้อความสถานะและข้อความแจ้งข้อผิดพลาดทุกข้อเป็นภาษาไทย
  - AC-OWN-13 (NFR-OWN-05): หน้าผลการตรวจสอบ p95 <= 2 วินาที (ต้องระบุจำนวนผู้ใช้พร้อมกันที่ใช้วัด)
  - AC-OWN-14 (DR-OWN-04, ASM-OWN-06): ผลคำนวณเสร็จแต่เจ้าหน้าที่ยังไม่เผยแพร่ นักศึกษาต้องเห็นเฉพาะสถานะ ไม่เห็นค่าผ่าน/ไม่ผ่าน
  - และเสนอให้แยก FR-OWN-05 เป็น 2 ข้อ (แสดงสถานะ / ห้ามแสดงค่าผล) ซึ่งต้องสร้าง FR ID ใหม่ รอทีมตัดสิน
- OQ-OWN-11 การอนุมัติของอาจารย์ที่ปรึกษาและคณะกรรมการสำหรับการส่งเอกสารขั้นเริ่มทำโปรเจกต์ตาม ASM-OWN-05 อยู่ใน use case ใด specs/009-advisor-approve-record ครอบคลุมกระบวนการนี้อยู่แล้วหรือต้องปรับขอบเขต และสถานะของกระบวนการนั้นเป็นชุดเดียวกับ DR-OWN-02 หรือเป็นชุดแยก (ต้องถาม: ทีมเอง ร่วมกับผู้รับผิดชอบ specs/009)
