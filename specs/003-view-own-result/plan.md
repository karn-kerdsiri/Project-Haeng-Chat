# แผนทางเทคนิค: SPEC-OWN-003 ดูผลการตรวจสอบคุณสมบัติของตนเอง

สถานะ: ร่างเพื่อให้ทีมตรวจ

## 1. สรุปแนวทาง
- ฟีเจอร์นี้ให้นักศึกษาที่เข้าสู่ระบบดูสถานะคำร้องและผลการตรวจสอบของตนเองจากข้อมูลล่าสุด (FR-OWN-02, DR-OWN-01, DR-OWN-06)
- แสดงผลการตรวจสอบแยกจากสถานะคำร้อง และแสดงผลผ่าน/ไม่ผ่านได้เมื่อเจ้าหน้าที่เผยแพร่แล้วเท่านั้น (DR-OWN-04, ASM-OWN-04, ASM-OWN-06)
- เมื่อไม่ผ่านให้แสดงเหตุผลพร้อมจำนวน และเมื่อยังไม่มีผลหรือข้อมูลไม่ครบให้แสดงสถานะ/รายการดำเนินการตามข้อกำหนด (FR-OWN-04, FR-OWN-05, FR-OWN-06)
- ใช้ API แบบอ่านข้อมูล ตรวจเจ้าของคำร้องทุกครั้ง และอ่านฐานข้อมูลใหม่ทุกครั้งที่เปิดหน้าโดยไม่ใช้แคช (FR-OWN-01, FR-OWN-08, CON-OWN-01, CON-OWN-02)
- สร้างหน้าจอเว็บแบบ responsive; ไม่คำนวณผล ตรวจข้อมูลรายวิชา หรือทำงานอื่นที่อยู่นอกขอบเขต (IF-WEB-01, NFR-OWN-04, OUT-OWN-01, OUT-OWN-02, OUT-OWN-07)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React + Vite สำหรับหน้าบ้าน | IF-TECH-01; Vite เป็นค่าเริ่มต้นของรายวิชา ไม่ได้ระบุใน spec | React/PostgreSQL เป็นข้อกำหนด; Vite เป็นรายละเอียดเครื่องมือที่ทีมเลือกเอง |
| Python FastAPI สำหรับ Backend | ทีมเลือกเอง ไม่ได้มาจาก spec | ทีมยืนยันใช้ FastAPI ในการวางแผนฟีเจอร์ 002 |
| PostgreSQL | IF-TECH-01 | อ่านข้อมูลคำร้องและผลการตรวจสอบตาม CON-OWN-02 |
| Session จากบัญชีมหาวิทยาลัย | IF-AUTH-01 | ทุก request ต้องยืนยัน session ก่อนอ่านข้อมูล |
| REST GET APIs | ทีมยืนยันแนวทางในแผนนี้ ไม่ได้มาจาก spec | อ่านอย่างเดียว; ไม่มี endpoint สำหรับคำนวณหรือแก้ไขข้อมูลในฟีเจอร์นี้ |

## 3. โมเดลข้อมูล

| Entity / แหล่งข้อมูล | ฟิลด์หลัก | ความสัมพันธ์/ข้อกำหนด | รองรับ |
|---|---|---|---|
| คำร้อง (ใช้ข้อมูลเดิม) | เจ้าของคำร้องจาก session, สถานะคำร้อง | นักศึกษา 1 คนมีคำร้อง 1 คำร้อง; แสดงข้อมูลจากการส่งหรือแก้ไขครั้งล่าสุด (DR-OWN-02, DR-OWN-06); ไม่สร้างคำร้องใหม่ | FR-OWN-01, FR-OWN-02, FR-OWN-03, FR-OWN-05, FR-OWN-08 |
| ผลการตรวจสอบ (อ่านจากข้อมูลเดิม) | ผล “ผ่านเงื่อนไข” หรือ “ไม่ผ่าน”; มีได้เมื่อคำร้องเสร็จสิ้นและผลเผยแพร่แล้ว | คงแยกจากสถานะคำร้อง; ไม่คำนวณผลในฟีเจอร์นี้ (DR-OWN-04, OUT-OWN-02); การอ่านสถานะเผยแพร่รอคำตอบ OQ-OWN-07 | FR-OWN-02, FR-OWN-04, FR-OWN-05 |
| เหตุผลที่ไม่ผ่าน (อ่านจากผลเดิม) | เงื่อนไขที่ไม่ผ่านและจำนวน | แสดงเหตุผลระดับรวม ไม่แสดงรายวิชาทุกวิชาหรือรายละเอียดแยก (DR-OWN-05, ASM-OWN-07, OUT-OWN-07) | FR-OWN-04 |
| รายการที่ต้องดำเนินการ (แหล่งข้อมูลยังไม่ยืนยัน) | รายการสิ่งที่ยังไม่ครบตามแต่ละข้อ | แสดงเป็นรายข้อเมื่อมีกรณีข้อมูลไม่ครบ; ไม่กำหนด schema/แหล่งที่มาจนกว่าจะตอบ OQ-OWN-08 | FR-OWN-06, DR-OWN-03 |

ไม่มีข้อมูลใหม่ที่ฟีเจอร์นี้ต้องบันทึก; ข้อมูลทั้งหมดอ่านจากฐานข้อมูลใหม่เมื่อเปิดหน้า และห้ามใช้ cache (CON-OWN-02). ไม่เพิ่มฟิลด์ประวัติหรือข้อมูลรายละเอียดรายวิชานอกเหนือจากที่ spec ระบุ.

## 4. API / หน้าจอ

| รายการ | Method / path หรือหน้าจอ | Input / Output หลัก | รองรับ |
|---|---|---|---|
| อ่านสถานะและผลของคำร้อง | `GET /api/requests/{requestId}/eligibility` | Input: session และรหัสคำร้อง; Output: สถานะล่าสุด, ผลที่เผยแพร่แล้ว, เหตุผลประกอบ และรายการดำเนินการเมื่อข้อมูลไม่ครบ; ตรวจเจ้าของก่อนคืนข้อมูล | FR-OWN-01, FR-OWN-02, FR-OWN-03, FR-OWN-04, FR-OWN-05, FR-OWN-06, FR-OWN-08, CON-OWN-01, CON-OWN-02 |
| หน้าผลการตรวจสอบ | หน้าเว็บอ่านข้อมูลจาก GET endpoint และแสดงสถานะ/ผลรวม | แสดงเฉพาะเจ้าของคำร้อง; ผลเผยแพร่แล้วจึงแสดงผ่าน/ไม่ผ่าน; ข้อความภาษาไทย; ไม่มี cache | FR-OWN-02, FR-OWN-03, FR-OWN-04, DR-OWN-01, DR-OWN-04, DR-OWN-05, NFR-OWN-02, NFR-OWN-03 |
| สถานะรอตรวจสอบ | สถานะย่อยบนหน้าผลการตรวจสอบ | แสดงสถานะและไม่แสดงค่าผ่าน/ไม่ผ่านเมื่อยังไม่มีผล; คำที่ใช้แสดงสถานะรอคำตอบ OQ-OWN-01 | FR-OWN-05, DR-OWN-02 |
| รายการข้อมูลที่ต้องดำเนินการ | สถานะย่อยบนหน้าผลการตรวจสอบ | แสดงรายการแยกเป็นข้อเมื่อข้อมูลไม่ครบ; เงื่อนไขเกิดและรายการที่แสดงรอ OQ-OWN-08 | FR-OWN-06, DR-OWN-03 |
| ข้อผิดพลาด/ลองใหม่ | สถานะย่อยบนหน้าผลการตรวจสอบ | เมื่ออ่านข้อมูลไม่สำเร็จ แสดงข้อความผิดพลาดภาษาไทยและช่องทางลองใหม่ โดยไม่แสดงสถานะหรือผล | FR-OWN-07, NFR-OWN-03 |

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| IF-AUTH-01 | ตรวจ session บนทุก request; ไม่มี session ตอบ HTTP 401 | ใช้แล้ว |
| IF-WEB-01 | ทุกหน้าจอเป็นเว็บเบราว์เซอร์ ไม่ต้องติดตั้งโปรแกรม | ใช้แล้ว |
| IF-TECH-01 | React สำหรับหน้าบ้านและ PostgreSQL สำหรับอ่านข้อมูล | ใช้แล้ว |
| CON-OWN-01 | API ตรวจเจ้าของ session ก่อนคืนข้อมูล; ผู้ไม่มีสิทธิ์ได้ HTTP 403 | ใช้แล้ว |
| CON-OWN-02 | อ่านฐานข้อมูลใหม่ทุกครั้งที่เปิดหน้า; ปิดการใช้ cache | ใช้แล้ว |

## 7. ลำดับงาน

1. ตรวจแหล่งข้อมูลคำร้อง สถานะ และผลตรวจสอบที่มีอยู่ พร้อมยืนยันความสัมพันธ์กับข้อมูลเผยแพร่ของ UC-14 ตาม OQ-OWN-07 (FR-OWN-02, DR-OWN-04, ASM-OWN-06)
2. วางการตรวจ session และเจ้าของคำร้องในทุก GET request (IF-AUTH-01, CON-OWN-01, FR-OWN-01, FR-OWN-08, AC-OWN-04)
3. สร้าง GET สำหรับอ่านข้อมูลล่าสุดโดยไม่ใช้ cache (CON-OWN-02, DR-OWN-06, AC-OWN-01)
4. สร้างการแสดงสถานะคำร้องและผลที่เผยแพร่แล้ว โดยไม่คำนวณผล (FR-OWN-02, FR-OWN-03, FR-OWN-05, DR-OWN-02, DR-OWN-04, AC-OWN-02, AC-OWN-06)
5. สร้างการแสดงเหตุผลประกอบเมื่อไม่ผ่าน โดยคงระดับรายละเอียดตาม scope (FR-OWN-04, DR-OWN-05, ASM-OWN-07)
6. เพิ่มสถานะข้อมูลไม่ครบและรายการที่ต้องดำเนินการหลังได้คำตอบ OQ-OWN-08 (FR-OWN-06, DR-OWN-03, AC-OWN-03)
7. จัดการข้อผิดพลาดโดยซ่อนผล/สถานะเมื่ออ่านข้อมูลไม่สำเร็จ พร้อมข้อความไทยและช่องทางลองใหม่ (FR-OWN-07, NFR-OWN-03, AC-OWN-05)
8. ตรวจการใช้งานบนเว็บ, ภาษาไทย, timeout, privacy และ responsive; ทดสอบ p95 เมื่อมีเกณฑ์วัดครบ (IF-WEB-01, NFR-OWN-01 ถึง NFR-OWN-05, AC-OWN-07, AC-OWN-08, OQ-OWN-10)

## 8. สิ่งที่ยังไม่ทำ

- OQ-OWN-01 ข้อความที่แสดงบนหน้าจอของแต่ละสถานะใช้คำว่าอะไรแน่ สถานะ "รอตรวจสอบ" จะแสดงว่า "รอตรวจสอบ" หรือ "รอเจ้าหน้าที่ตรวจสอบ" และสถานะ "เสร็จสิ้น" แสดงว่าอะไร (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-OWN-06 ค่าเกรด T หมายถึงอะไร และนับเป็นผลที่สมบูรณ์หรือไม่สมบูรณ์ (ต้องถาม: เจ้าหน้าที่งานทะเบียน) ตรงกับ OQ-ADD-01 ใน specs/002
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-OWN-07 ตาม ASM-OWN-06 ระบบต้องอ่านสถานะการเผยแพร่ผลจาก UC-14 ก่อนแสดงผล ซึ่งยังไม่มี Constraint รองรับ ผมสร้าง IF ID ใหม่เองไม่ได้ จึงเสนอให้ทีมอนุมัติเพิ่ม IF-PUB-01 "ระบบต้องอ่านสถานะการเผยแพร่ผลของคำร้องก่อนแสดงผลการตรวจสอบทุกครั้ง" และตอบด้วยว่าถ้าอ่านสถานะการเผยแพร่ไม่ได้ ต้องถือว่ายังไม่เผยแพร่หรือเผยแพร่แล้ว (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้เผยแพร่ผล)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-OWN-08 ถ้าหน้ากรอกข้อมูลห้ามปล่อยช่องว่างตาม ASM-OWN-11 กรณี "ข้อมูลยังไม่ครบ" ตาม FR-OWN-06 และ UC-03 alt 2 จะเกิดขึ้นในสถานการณ์ใด และรายการที่ต้องดำเนินการมีอะไรได้บ้าง ถ้าเกิดขึ้นไม่ได้เลย FR-OWN-06, DR-OWN-03, IN-OWN-05 และ AC-OWN-03 ต้องจัดการอย่างไร เพราะผมลบ ID เองไม่ได้ (ต้องถาม: เจ้าหน้าที่ผู้ตรวจสอบคำร้อง และทีมเอง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-OWN-09 เกณฑ์ "ค้างรายวิชาที่ยังไม่ออกผลได้ไม่เกิน 1 วิชา" ตาม ASM-OWN-10 เป็นเงื่อนไขการผ่านที่ควรอยู่ในข้อมูลที่เจ้าหน้าที่จัดการตาม UC-12 และใช้คำนวณใน UC-16 ต้องให้ specs/012 และ specs/016 รองรับเกณฑ์นี้หรือไม่ และ W นับรวมในจำนวนที่ค้างด้วยหรือไม่ (ต้องถาม: ภาควิชา หรือเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-OWN-10 ข้อที่ยังตามรอยไม่ได้ ผมสร้าง AC ID ใหม่เองไม่ได้ จึงเสนอให้ทีมอนุมัติเพิ่ม AC ตามนี้ (ต้องถาม: ทีมเอง)
  - AC-OWN-09 (FR-OWN-01, IF-AUTH-01): เรียกหน้านี้โดยไม่มี session ต้องได้ HTTP 401
  - AC-OWN-10 (FR-OWN-04, DR-OWN-05): ผลเป็น "ไม่ผ่าน" เพราะค้าง I 2 วิชา หน้าจอต้องแสดงเหตุผลที่ระบุจำนวนวิชาที่ค้าง
  - AC-OWN-11 (CON-OWN-02, ASM-OWN-08): เจ้าหน้าที่เปลี่ยนสถานะแล้ว นักศึกษาเปิดหน้าใหม่ต้องเห็นค่าใหม่ทันที
  - AC-OWN-12 (NFR-OWN-03): ข้อความสถานะและข้อความแจ้งข้อผิดพลาดทุกข้อเป็นภาษาไทย
  - AC-OWN-13 (NFR-OWN-05): หน้าผลการตรวจสอบ p95 <= 2 วินาที (ต้องระบุจำนวนผู้ใช้พร้อมกันที่ใช้วัด)
  - AC-OWN-14 (DR-OWN-04, ASM-OWN-06): ผลคำนวณเสร็จแต่เจ้าหน้าที่ยังไม่เผยแพร่ นักศึกษาต้องเห็นเฉพาะสถานะ ไม่เห็นค่าผ่าน/ไม่ผ่าน
  - และเสนอให้แยก FR-OWN-05 เป็น 2 ข้อ (แสดงสถานะ / ห้ามแสดงค่าผล) ซึ่งต้องสร้าง FR ID ใหม่ รอทีมตัดสิน
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ

## หมายเหตุสำหรับทีม

- Constraint ทั้ง 5 ข้อถูกนำไปใช้ในแผน; การเชื่อมสถานะเผยแพร่จาก UC-14 ยังรอคำตอบ OQ-OWN-07
