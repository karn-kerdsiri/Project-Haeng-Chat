# Feature: ตรวจสอบและยืนยันข้อมูลที่นักศึกษาส่งมา (Staff Verify and Confirm)
Spec ID: SPEC-VRF-013 | Source: Use Case Specification UC-13 ตรวจสอบและยืนยันข้อมูลที่นักศึกษาส่งมา (Includes UC-16) + รายการความต้องการของทีม ข้อ 8, ข้อ 17 | Use case: UC-13
Owner: ทีม B | Status: Draft v2 | Updated: 2569-11-14

## Goal
เจ้าหน้าที่ตรวจสอบความถูกต้องของข้อมูลที่นักศึกษาส่งมา แล้วยืนยันรายการที่ถูกต้อง
โดยระบบเรียกการคำนวณผลการตรวจสอบคุณสมบัติตามขั้นตอน และบันทึกสถานะยืนยันพร้อมผู้ดำเนินการ

## Scope
### In scope
- IN-VRF-01 แสดงรายการคำร้องที่รอตรวจสอบ                            <- UC-13 ขั้น 1, Trigger
- IN-VRF-02 ค้นหาคำร้องด้วยรหัสนักศึกษา ชื่อ หรือกลุ่มอาจารย์              <- ข้อ 17
- IN-VRF-03 เลือกคำร้องและแสดงข้อมูลกับเอกสารที่เกี่ยวข้อง                <- UC-13 ขั้น 2-3
- IN-VRF-04 เรียกใช้การคำนวณผลการตรวจสอบคุณสมบัติตามขั้นตอน             <- UC-13 ขั้น 5, Includes UC-16
- IN-VRF-05 ยืนยันข้อมูลและบันทึกสถานะยืนยัน                            <- UC-13 ขั้น 6-7, Postcondition
- IN-VRF-06 ส่งกลับให้แก้ไขเมื่อข้อมูลผิดหรือเอกสารไม่ครบ                  <- UC-13 alt 1-2
- IN-VRF-07 เรียกดูประวัติการแก้ไขและผู้ดำเนินการของคำร้อง                 <- ข้อ 8
### Out of scope
- OUT-VRF-01 รายละเอียดการคำนวณผล - เป็นของ UC-16 spec นี้เพียงเรียกใช้และรับผล
- OUT-VRF-02 การอนุมัติโดยอาจารย์ที่ปรึกษา - เป็นของ UC-09
- OUT-VRF-03 การเผยแพร่ผล - เป็นของ UC-14
- OUT-VRF-04 การแก้ไขข้อมูลผลการศึกษาแทนนักศึกษา - UC-13 ระบุให้ส่งกลับให้นักศึกษาแก้ไข
- OUT-VRF-05 การจัดการข้อมูลพื้นฐานและเงื่อนไขการผ่าน - เป็นของ UC-12

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลสถานะเก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- IF-AUDIT-01 ทุกการเปลี่ยนสถานะคำร้องต้องบันทึกประวัติการแก้ไขและผู้ดำเนินการ และเจ้าหน้าที่ต้องเรียกดูได้   <- ข้อ 8
- IF-CALC-01 การคำนวณผลต้องเรียกผ่าน UC-16 เท่านั้น ไม่คำนวณซ้ำในฟีเจอร์นี้   <- UC-13 ขั้น 5
- CON-VRF-01 เฉพาะผู้ใช้บทบาทเจ้าหน้าที่ที่มีสิทธิ์ตรวจสอบจึงจะยืนยันหรือส่งกลับได้   <- UC-13 Precondition
- CON-VRF-02 เมื่อการคำนวณหรือการบันทึกไม่สำเร็จ สถานะคำร้องต้องไม่เปลี่ยน   <- UC-13 Exception
- CON-VRF-03 ระบบต้องไม่ให้ยืนยันคำร้องที่ข้อมูลยังไม่พร้อม   <- UC-13 alt 3

## Data Rules
- DR-VRF-01 ข้อมูลที่แสดงต่อ 1 รายการในรายการรอตรวจสอบ: รหัสนักศึกษา ชื่อนักศึกษา กลุ่มอาจารย์ และสถานะคำร้อง   <- UC-13 ขั้น 1 + ข้อ 17
- DR-VRF-02 ข้อมูลที่แสดงเมื่อเลือกคำร้อง: ข้อมูลผลการศึกษาที่ส่งมา และเอกสารที่เกี่ยวข้อง   <- UC-13 ขั้น 3 (ขอบเขตรอยืนยัน ดู OQ-VRF-01)
- DR-VRF-03 คำค้นที่รองรับ: รหัสนักศึกษา, ชื่อนักศึกษา, กลุ่มอาจารย์   <- ข้อ 17
- DR-VRF-04 เงื่อนไขที่ถือว่า "ข้อมูลยังไม่พร้อม" ต้องกำหนดชัดเจน (ยังไม่ระบุ ดู OQ-VRF-02)
- DR-VRF-05 เมื่อส่งกลับให้แก้ไข ต้องระบุเหตุผลหรือรายการที่ต้องแก้ไข   <- UC-13 alt 1-2
- DR-VRF-06 ประวัติที่บันทึกต่อ 1 การกระทำ: ผู้ดำเนินการ เวลา สถานะก่อนและหลัง   <- ข้อ 8

## Requirements
- FR-VRF-01 ระบบต้องแสดงรายการคำร้องที่รอตรวจสอบตาม DR-VRF-01   <- UC-13 ขั้น 1
- FR-VRF-02 ระบบต้องให้เจ้าหน้าที่ค้นหาคำร้องด้วยคำค้นตาม DR-VRF-03   <- ข้อ 17
- FR-VRF-03 ระบบต้องให้เลือกคำร้องและแสดงข้อมูลกับเอกสารตาม DR-VRF-02   <- UC-13 ขั้น 2-3
- FR-VRF-04 ระบบต้องเรียกการคำนวณผลผ่าน UC-16 ตาม IF-CALC-01 ในขั้นตอนตรวจสอบ   <- UC-13 ขั้น 5
- FR-VRF-05 ระบบต้องแสดงผลที่ได้จากการคำนวณให้เจ้าหน้าที่เห็นก่อนยืนยัน   <- UC-13 ขั้น 4-6
- FR-VRF-06 เมื่อเจ้าหน้าที่กดยืนยัน ระบบต้องบันทึกสถานะยืนยันของคำร้องนั้น   <- UC-13 ขั้น 7, Postcondition
- FR-VRF-07 เมื่อข้อมูลผิดหรือเอกสารไม่ครบ ระบบต้องให้ส่งกลับให้นักศึกษาแก้ไขพร้อมเหตุผลตาม DR-VRF-05 และเปลี่ยนสถานะเป็นรอการแก้ไข   <- UC-13 alt 1-2
- FR-VRF-08 เมื่อข้อมูลยังไม่พร้อมตาม DR-VRF-04 ระบบต้องไม่อนุญาตให้ยืนยัน   <- UC-13 alt 3, CON-VRF-03
- FR-VRF-09 หากการคำนวณหรือการบันทึกไม่สำเร็จ ระบบต้องแจ้งข้อผิดพลาดและคงสถานะเดิมตาม CON-VRF-02   <- UC-13 Exception
- FR-VRF-10 ระบบต้องบันทึกประวัติการแก้ไขและผู้ดำเนินการตาม DR-VRF-06 และให้เจ้าหน้าที่เรียกดูประวัติของแต่ละคำร้องได้   <- ข้อ 8
- FR-VRF-11 ระบบต้องปฏิเสธการยืนยันหรือส่งกลับโดยผู้ใช้ที่ไม่มีสิทธิ์ด้วย HTTP 403   <- CON-VRF-01
- FR-VRF-12 คำร้องที่ยืนยันแล้วต้องพร้อมให้ UC-14 นำไปเผยแพร่   <- UC-13 Goal, Postcondition

## Quality Requirements
- NFR-VRF-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-VRF-02 [Security] เฉพาะบทบาทเจ้าหน้าที่ที่มีสิทธิ์ตรวจสอบจึงจะเรียก API ยืนยันหรือส่งกลับได้   <- UC-13 NFR (Security)
- NFR-VRF-03 [Data Integrity] การยืนยันคำร้องต้องบันทึกผลการคำนวณและสถานะในธุรกรรมเดียว   <- UC-13 NFR (Data Integrity)
- NFR-VRF-04 [Auditability] ประวัติการตรวจสอบและยืนยันต้องเก็บไว้ไม่น้อยกว่า 1 ปี และแก้ไขย้อนหลังไม่ได้   <- UC-13 NFR (Auditability) + ข้อ 8 (ระยะเวลา 1 ปีเป็นค่าที่เสนอไว้ ดู ASM-VRF-01)
- NFR-VRF-05 [Usability] ข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย และระบุสิ่งที่ต้องแก้ไข   <- ข้อ 10
- NFR-VRF-06 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-VRF-01)
- NFR-VRF-07 [Performance] ค้นหาคำร้องจากฐานข้อมูล 2,000 รายการ: เวลาตอบสนอง p95 <= 2 วินาที   <- ค่าที่เสนอไว้ ดู ASM-VRF-01

## Acceptance Criteria
- [ ] AC-VRF-01 (FR-VRF-04, FR-VRF-06, NFR-VRF-03)
      Given มีคำร้องที่พร้อมตรวจสอบ
      When  เจ้าหน้าที่ตรวจสอบและกดยืนยันข้อมูล
      Then  ระบบเรียกการคำนวณผ่าน UC-16 บันทึกสถานะยืนยัน และข้อมูลพร้อมใช้ในขั้นตอนถัดไป
- [ ] AC-VRF-02 (FR-VRF-02, DR-VRF-03, NFR-VRF-07)
      Given มีคำร้องหลายรายการในระบบ
      When  เจ้าหน้าที่ค้นหาด้วยรหัสนักศึกษา ชื่อ หรือกลุ่มอาจารย์
      Then  ระบบแสดงเฉพาะคำร้องที่ตรงกับคำค้น
- [ ] AC-VRF-03 (FR-VRF-07, DR-VRF-05)
      Given เอกสารของคำร้องไม่ครบ
      When  เจ้าหน้าที่ส่งกลับให้แก้ไขพร้อมระบุเหตุผล
      Then  ระบบบันทึกเหตุผล และเปลี่ยนสถานะเป็นรอการแก้ไขของนักศึกษา
- [ ] AC-VRF-04 (FR-VRF-08, CON-VRF-03)
      Given คำร้องมีข้อมูลที่ยังไม่พร้อมตาม DR-VRF-04
      When  เจ้าหน้าที่พยายามกดยืนยัน
      Then  ระบบไม่อนุญาตให้ยืนยัน และแจ้งเหตุผล
- [ ] AC-VRF-05 (FR-VRF-09, CON-VRF-02)
      Given การคำนวณผลใน UC-16 ล้มเหลว
      When  เจ้าหน้าที่กดยืนยัน
      Then  ระบบแจ้งข้อผิดพลาด และสถานะคำร้องยังเป็นสถานะเดิม
- [ ] AC-VRF-06 (FR-VRF-11, NFR-VRF-02)
      Given ผู้ใช้ที่ไม่ใช่เจ้าหน้าที่ที่มีสิทธิ์
      When  เรียก API ยืนยันคำร้อง
      Then  ระบบตอบ HTTP 403 และสถานะคำร้องไม่เปลี่ยน
- [ ] AC-VRF-07 (FR-VRF-10, IF-AUDIT-01, NFR-VRF-04)
      Given คำร้องถูกยืนยัน 1 ครั้งและถูกส่งกลับให้แก้ไข 1 ครั้ง
      When  เจ้าหน้าที่เปิดดูประวัติของคำร้องนั้น
      Then  ระบบแสดงประวัติ 2 รายการ แต่ละรายการระบุผู้ดำเนินการ เวลา และสถานะก่อน/หลัง
- [ ] AC-VRF-08 (FR-VRF-12)
      Given คำร้องมีสถานะยืนยันแล้ว
      When  เจ้าหน้าที่เปิดเมนูเผยแพร่ผลตาม UC-14
      Then  คำร้องนั้นปรากฏในรายการที่พร้อมเผยแพร่

## Assumptions & Open Questions
- ASM-VRF-01 UC-13 ระบุ NFR เป็นหมวด (Security, Data Integrity, Auditability) ค่าตัวเลขใน NFR-VRF-04, NFR-VRF-06 และ NFR-VRF-07 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-VRF-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-VRF-03 ข้อ 17 ระบุการค้นหาคำร้องเป็นความสามารถของเจ้าหน้าที่ spec นี้จึงรวมไว้ใน UC-13 ซึ่ง UC-13 ไม่ได้เขียนขั้นตอนค้นหาไว้ รอทีมยืนยันว่าควรอยู่ที่ use case นี้
- ASM-VRF-04 การยืนยันหรือส่งกลับคำร้องทำงานแบบทีละรายการตาม UC-13 ที่ระบุการเลือก 1 รายการต่อครั้ง จึงไม่รองรับการยืนยันหลายคำร้องพร้อมกัน
- ASM-VRF-05 เมื่อการคำนวณผลหรือการบันทึกไม่สำเร็จ ระบบต้องไม่เปลี่ยนสถานะคำร้อง และต้องแจ้งข้อผิดพลาดตาม CON-VRF-02 และ FR-VRF-09
- ASM-VRF-06 การเรียก API ยืนยันหรือส่งกลับโดยผู้ใช้ที่ไม่มีสิทธิ์จะต้องตอบ HTTP 403 ตาม CON-VRF-01 และ FR-VRF-11
- ASM-VRF-07 ประวัติการเปลี่ยนสถานะแต่ละครั้งต้องบันทึกผู้ดำเนินการ เวลา สถานะก่อน และสถานะหลัง ตาม DR-VRF-06
- ASM-VRF-08 การบันทึกผลการคำนวณและสถานะของคำร้องต้องเกิดในธุรกรรมเดียวตาม NFR-VRF-03
- ASM-VRF-09 คำร้องที่ยืนยันแล้วต้องพร้อมให้ UC-14 นำไปเผยแพร่ตาม FR-VRF-12 และ AC-VRF-08
- OQ-VRF-01 ต้องถามเจ้าหน้าที่ตรวจสอบ/ทีมธุรกิจ: เจ้าหน้าที่ต้องเห็นข้อมูลอะไรบ้าง (รายวิชาและเกรดทั้งหมด ผลการอนุมัติของอาจารย์ ผลการลงนาม เอกสารแนบ หรือผลการตรวจเบื้องต้นจาก UC-07)
- OQ-VRF-02 ต้องถามเจ้าหน้าที่ตรวจสอบ/ทีมธุรกิจ: เงื่อนไขที่ถือว่า "ข้อมูลยังไม่พร้อม" ตาม UC-13 alt 3 คืออะไร (เช่น ยังไม่ผ่านอาจารย์ ยังไม่ลงนาม หรือเกรดยังไม่ครบ)
- OQ-VRF-03 ต้องถามทีมธุรกิจ/นักวิเคราะห์ระบบ: คำร้องต้องผ่าน UC-09 และ UC-11 ก่อนจึงจะเข้ามาที่ UC-13 ได้หรือไม่
- OQ-VRF-04 ต้องถามทีมข้อมูล/ผู้ดูแลสถานะ: ชื่อสถานะยืนยันแล้วและสถานะรอการแก้ไขใช้คำว่าอะไร เพื่อให้สอดคล้องกับ OQ-OWN-01 ของ specs/003 และ OQ-APR-03 ของ specs/009
- OQ-VRF-05 ต้องถามเจ้าหน้าที่ตรวจสอบ: เจ้าหน้าที่ยืนยันหลายคำร้องพร้อมกันได้หรือไม่ เพราะ UC-13 ระบุการเลือก 1 รายการต่อครั้ง
- OQ-VRF-06 ต้องถามทีมธุรกิจ/เจ้าหน้าที่ตรวจสอบ: เมื่อนักศึกษาส่งผลเพิ่มเติมตาม UC-02 หลังยืนยันแล้ว ต้องตรวจสอบและยืนยันใหม่หรือไม่
