# ข้อกำหนดร่วมของทุกฟีเจอร์ (Common Constraints)

Spec ID: SPEC-COMMON | Source: รายการความต้องการของทีม ข้อ 6, 12, 13, 14, 15, 16, 19
Owner: ทีม B | Status: v1 | Updated: 2569-11-14

## ไฟล์นี้มีไว้ทำไม

ข้อกำหนดบางข้อใช้ร่วมกันทุกฟีเจอร์ จึงถูกเขียนซ้ำไว้ในหลาย `spec.md` ด้วย ID เดียวกัน
การตรวจเมื่อ 2569-11-14 พบว่า **ID ร่วม 10 รายการ มี 9 รายการที่ข้อความไม่ตรงกันระหว่างไฟล์** (ดู CF-10 ในรายงาน `docs/srs/report-requirement.md`)
ส่วนใหญ่เป็นการเรียบเรียงใหม่ ไม่ได้ขัดกันในเนื้อหา แต่ทำให้ 1 ID ไม่ได้หมายถึงข้อความเดียว ซึ่งขัดกับกฎข้อ 5 และข้อ 7 ของ `AGENTS.md`

ไฟล์นี้จึงประกาศ **ข้อความอ้างอิงฉบับจริง (canonical)** ของ ID ร่วมแต่ละข้อ

## กฎการใช้

1. ถ้าข้อความของ ID ร่วมใน `specs/NNN-*/spec.md` ไฟล์ใด **ต่างจากไฟล์นี้ ให้ถือว่าไฟล์นี้ถูกต้อง**
2. ข้อความในไฟล์รายฟีเจอร์ถือเป็นคำอธิบายเฉพาะบริบทของฟีเจอร์นั้น ใช้อ่านประกอบได้ แต่ไม่ใช้ตัดสิน
3. **ไม่มีการเปลี่ยนหรือสร้าง ID ใหม่** ID ทุกตัวยังเป็นตัวเดิม `plan.md` และ `tasks.md` ที่อ้าง ID เหล่านี้ไว้แล้วยังใช้ได้ทั้งหมด ไม่ต้องแก้ตาม
4. ไฟล์รายฟีเจอร์ **ไม่จำเป็นต้องแก้** ใครจะปรับข้อความของตัวเองให้ตรงกับไฟล์นี้ภายหลังก็ได้ ไม่บังคับ
5. การแก้ข้อความใน `common.md` ต้องมาจากคำตอบของทีม และบันทึกใน `prompt-log.md` เช่นเดียวกับ spec อื่น

## ข้อกำหนดร่วมที่มีข้อความเดียวทุกฟีเจอร์

| ID | ข้อความอ้างอิงฉบับจริง | ที่มา | ใช้ในไฟล์ |
|---|---|---|---|
| `IF-AUTH-01` | ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401 | ข้อ 12 | ทั้ง 17 ไฟล์ |
| `IF-WEB-01` | ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม | ข้อ 13 | 15 ไฟล์ (002 ถึง 015, 017) |
| `IF-TECH-01` | ส่วนหน้าจอพัฒนาด้วย React และข้อมูลของระบบเก็บในฐานข้อมูล PostgreSQL | ข้อ 19 | 16 ไฟล์ (002 ถึง 017) |
| `IF-FORM-01` | ระบบต้องใช้ตารางเวลาประจำเทอมที่เจ้าหน้าที่จัดทำไว้ตาม UC-15 เป็นแหล่งเดียวในการเปิดและปิดแบบฟอร์ม และต้องอ่านสถานะ (open/closed) ก่อนแสดงฟอร์มและก่อนบันทึกทุกครั้ง ไม่เก็บช่วงเวลาซ้ำในฟีเจอร์ใด | ข้อ 6 + ASM-EDU-13 | 001, 015 |
| `IF-SCHED-01` | ช่วงเวลาที่ฟีเจอร์ใดอ่านหรือแสดง ต้องเป็นชุดเดียวกับตารางเวลาประจำเทอมของ UC-15 ที่ `IF-FORM-01` อ้างถึง | ข้อ 6 | 002, 005 |
| `CON-FILE-01` | ไฟล์เอกสารต้องเป็น PDF, JPG หรือ PNG ขนาดไม่เกิน 10 MB ต่อไฟล์ | ข้อ 15 | 004, 011 |
| `DOM-GRADE-01` | เกรดที่ใช้ตรวจสอบต้องเป็นค่าตามระบบเกรดของมหาวิทยาลัย และรายวิชาที่ได้ผลไม่สมบูรณ์ต้องไม่ถูกนับว่าผ่าน | ข้อ 16 | 002, 007, 012, 016 |
| `DOM-QUOTA-01` | อาจารย์หนึ่งคนรับนักศึกษาได้ไม่เกินโควต้าที่คณะกำหนดในแต่ละภาคการศึกษา | ข้อ 14 | 006, 012 |

### หมายเหตุประกอบ

- `IF-AUTH-01` ข้อความใน `specs/001` ไม่ได้ระบุ "บัญชีเดียวกับระบบของมหาวิทยาลัย" ซึ่งเป็นสาระของข้อ 12 ให้ยึดข้อความในไฟล์นี้
- `CON-FILE-01` กำหนด 10 MB ตามข้อ 15 ซึ่งต่างจาก `DR-EDU-06` ใน `specs/001` ที่กำหนด 5 MB **`DR-EDU-06` ไม่ใช่ ID ร่วม** จึงไม่อยู่ในไฟล์นี้ และยังเป็นข้อขัดแย้งที่ทีมรับทราบแล้วแต่ยังไม่ได้แก้ (CF-03)
- `IF-TECH-01` ข้อความอ้างอิงตัดคำขยายเฉพาะฟีเจอร์ออก เช่น "ข้อมูลกลุ่มอาจารย์" หรือ "ข้อมูลการแจ้งเตือน" เพราะเป็นรายละเอียดของแต่ละไฟล์ ไม่ใช่สาระของข้อ 19

## ID ร่วมที่ความหมายกำหนดต่อฟีเจอร์

สอง ID นี้ใช้ชื่อร่วมกันแต่ **ขอบเขตต่างกันจริงในแต่ละฟีเจอร์** ไม่ใช่การเรียบเรียงคนละแบบ
จึงไม่มีข้อความอ้างอิงฉบับเดียว ให้ยึดข้อความในไฟล์ของฟีเจอร์นั้น และใช้ตารางนี้เป็นสารบัญ

### `IF-AUDIT-01` — บันทึกประวัติการกระทำ (ที่มา: ข้อ 8)

หลักการร่วม: ทุกการกระทำที่เปลี่ยนข้อมูลหรือสถานะ ต้องบันทึกประวัติพร้อมผู้ดำเนินการและเวลา ส่วนสิ่งที่ต้องบันทึกในแต่ละฟีเจอร์เป็นดังนี้

| ไฟล์ | สิ่งที่ต้องบันทึก |
|---|---|
| 009 | ทุกการเปลี่ยนสถานะคำร้อง ให้เจ้าหน้าที่เรียกดูได้ |
| 011 | ทุกการลงนามและการเปลี่ยนสถานะ ให้เจ้าหน้าที่เรียกดูได้ |
| 012 | ทุกการเพิ่ม แก้ไข และลบข้อมูลพื้นฐาน |
| 013 | ทุกการเปลี่ยนสถานะคำร้อง และเจ้าหน้าที่ต้องเรียกดูได้ |
| 014 | การเผยแพร่ผลทุกครั้ง |
| 015 | การสร้างและแก้ไขตารางเวลา |
| 016 | ผลการคำนวณทุกครั้ง พร้อมชุดเงื่อนไขที่ใช้ |

### `IF-MST-01` — อ่านข้อมูลพื้นฐานจาก UC-12 (ที่มา: ข้อ 4)

หลักการร่วม: ข้อมูลพื้นฐานที่เจ้าหน้าที่จัดการไว้ตาม UC-12 ต้องอ่านจากแหล่งเดียว ไม่เก็บซ้ำและไม่ฝังไว้ในโค้ด ส่วนข้อมูลที่อ่านในแต่ละฟีเจอร์เป็นดังนี้

| ไฟล์ | ข้อมูลที่อ่าน |
|---|---|
| 006 | รายการกลุ่มอาจารย์และโควต้า |
| 007 | เงื่อนไขการผ่าน |
| 016 | เงื่อนไขการผ่าน |
