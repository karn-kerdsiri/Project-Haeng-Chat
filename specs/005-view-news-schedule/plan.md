# แผนทางเทคนิค: SPEC-NWS-005 ดูข่าวสารและตารางเวลาประจำเทอม

สถานะ: ร่างเพื่อให้ทีมตรวจ

## 1. สรุปแนวทาง

- ฟีเจอร์นี้ให้นักศึกษาที่เข้าสู่ระบบดูข่าวสารและตารางเวลาที่เผยแพร่แล้ว โดยตารางเวลาเป็นของภาคการศึกษาปัจจุบัน (FR-NWS-01, CON-NWS-01, ASM-NWS-04)
- จัดข้อมูลข่าวสารและตารางเวลาให้อ่านรายละเอียดได้ตามหัวข้อที่เลือก โดยคงเฉพาะหัวข้อและช่วงเวลาที่ spec ระบุ (FR-NWS-02, FR-NWS-03, DR-NWS-01, DR-NWS-02)
- แสดงสถานะว่างเมื่อไม่มีข่าวหรือยังไม่มีตารางเวลาที่เผยแพร่ และแสดงข้อผิดพลาด/ทางลองใหม่เมื่ออ่านข้อมูลไม่สำเร็จ (FR-NWS-04, FR-NWS-05, FR-NWS-06)
- อ่านตารางเวลาชุดเดียวกับข้อมูลที่ใช้ควบคุมแบบฟอร์ม ไม่สร้างหรือแก้ไขข่าวและตารางเวลาในฟีเจอร์นี้ (IF-SCHED-01, FR-NWS-07, OUT-NWS-01, OUT-NWS-03, OUT-NWS-04)
- ใช้หน้าจอเว็บภาษาไทยที่รองรับจอ 360 px; การเรียงลำดับ รูปแบบหน้า และรายละเอียด integration ที่ยังเปิดอยู่ให้รอคำตอบ Q-NWS-01–08 (IF-WEB-01, NFR-NWS-01, NFR-NWS-02)

## 3. โมเดลข้อมูล

ใช้แหล่งข้อมูลที่มีอยู่แบบอ่านอย่างเดียว ไม่กำหนด schema หรือตารางใหม่จนกว่าจะยืนยันแหล่งและความสัมพันธ์จริง

| Entity / แหล่งข้อมูลเชิงตรรกะ | ข้อมูลที่อ่าน/แสดง | ความสัมพันธ์/ข้อจำกัด | รองรับ |
|---|---|---|---|
| ข่าวสารที่เผยแพร่แล้ว | หัวข้อ, รายละเอียด, ช่วงเวลาที่เกี่ยวข้อง (ถ้ามี) | อ่านเฉพาะรายการที่เผยแพร่แล้ว; ผู้สร้าง/แหล่งข้อมูลและฟิลด์สถานะจริงรอ Q-NWS-01 | FR-NWS-01, FR-NWS-02, FR-NWS-03, FR-NWS-04, DR-NWS-01, CON-NWS-01 |
| ตารางเวลาที่เผยแพร่แล้ว | ภาคการศึกษาปัจจุบัน, ชื่อกิจกรรม, วันเริ่ม, วันสิ้นสุด | อ่านชุดเดียวกับข้อมูลที่ควบคุมการเปิด/ปิดแบบฟอร์ม; ไม่แก้ไขข้อมูลใน feature นี้; การระบุ source/version และความหมายวันรอ Q-NWS-06 | FR-NWS-01, FR-NWS-03, FR-NWS-05, FR-NWS-07, DR-NWS-02, IF-SCHED-01, ASM-NWS-03, ASM-NWS-04 |
| Session ผู้ใช้ | สถานะยืนยันตัวตนด้วยบัญชีมหาวิทยาลัย | ตรวจสิทธิ์ก่อนเข้าหน้าหรือเรียกข้อมูล; วิธีตอบสนองกรณีไม่มี session รอ Q-NWS-04 | IF-AUTH-01, NFR-NWS-05 |

ฟีเจอร์ไม่มีการสร้างหรือแก้ไขข้อมูลข่าวสาร/ตารางเวลา และไม่เก็บข้อมูลเพิ่มตามข้อกำหนดปัจจุบัน (OUT-NWS-01, OUT-NWS-03, OUT-NWS-04)

## 4. API / หน้าจอ

ชื่อ path เป็นข้อเสนอเพื่ออธิบายขอบเขตการอ่านข้อมูลเท่านั้น ปรับตาม convention ของระบบได้; ไม่กำหนดรูปแบบหน้าโดยแทนคำตอบ Q-NWS-05

| รายการ | Method / path หรือหน้าจอ | Input / Output หลัก | รองรับ |
|---|---|---|---|
| อ่านรายการข่าวสารที่เผยแพร่ | `GET /api/news` | Input: session; Output: หัวข้อและข้อมูลตาม DR-NWS-01 ของข่าวที่เผยแพร่; เกณฑ์เรียงตาม DR-NWS-03 รอ Q-NWS-03 | FR-NWS-01, FR-NWS-04, DR-NWS-01, DR-NWS-03, CON-NWS-01 |
| อ่านรายละเอียดข่าวสารที่เลือก | `GET /api/news/{newsId}` | Input: session และรหัสหัวข้อ; Output: หัวข้อ รายละเอียด และช่วงเวลาที่เกี่ยวข้อง (ถ้ามี); แหล่งข้อมูลจริงรอ Q-NWS-01 | FR-NWS-02, FR-NWS-03, DR-NWS-01 |
| อ่านตารางเวลาปัจจุบันที่เผยแพร่ | `GET /api/term-schedule/current` | Input: session; Output: รายการกิจกรรมภาคการศึกษาปัจจุบันที่เผยแพร่ พร้อมวันเริ่มและวันสิ้นสุดจากแหล่งเดียวกับระบบควบคุมแบบฟอร์ม; ถ้ายังไม่เผยแพร่ให้หน้าจอแสดงสถานะว่าง | FR-NWS-01, FR-NWS-05, FR-NWS-07, DR-NWS-02, IF-SCHED-01, CON-NWS-01, ASM-NWS-04 |
| หน้ารายการข่าวสาร/ตารางเวลา | หน้าจอเว็บสำหรับเปิดรายการและเลือกหัวข้อ | เข้าถึงได้หลังยืนยันตัวตน; แสดงเฉพาะข้อมูลที่เผยแพร่; ตำแหน่ง/รูปแบบหน้าและการเรียงจริงรอ Q-NWS-03, Q-NWS-05 | FR-NWS-01, FR-NWS-02, IF-AUTH-01, CON-NWS-01 |
| หน้ารายละเอียดและสถานะว่าง | หน้าจอรายละเอียดข่าว/ตารางเวลา และข้อความเมื่อไม่มีข้อมูล | แสดงฟิลด์ตาม DR-NWS-01/02; ข่าวว่างและตารางเวลาที่ยังไม่เผยแพร่มีข้อความตาม FR-NWS-04/05 โดยไม่แสดงร่าง | FR-NWS-03, FR-NWS-04, FR-NWS-05, NFR-NWS-01 |
| สถานะข้อผิดพลาด/ลองใหม่ | สถานะบนหน้าจอของข้อมูลที่อ่านไม่สำเร็จ | แสดงข้อความภาษาไทยและให้ลองใหม่; การแสดงข้อมูลที่สำเร็จบางส่วนหรือโหลดทั้งหน้าซ้ำรอ Q-NWS-07 | FR-NWS-06, NFR-NWS-01 |

## 7. ลำดับงาน

1. ตรวจและยืนยันแหล่งข้อมูลข่าวสารกับผู้รับผิดชอบ โดยไม่สร้างหรือแก้ไขระบบจัดการข่าวใน feature นี้ (Q-NWS-01, OUT-NWS-03)
2. ยืนยัน source/version ของตารางเวลาที่ใช้ร่วมกับการควบคุมแบบฟอร์มและนิยามวันเริ่ม/สิ้นสุดก่อนเชื่อมข้อมูล (IF-SCHED-01, FR-NWS-07, Q-NWS-06)
3. วางการบังคับยืนยัน session ของมหาวิทยาลัยก่อนเข้าหน้าและ API พร้อมคง timeout ตาม NFR-NWS-05; พฤติกรรมผู้ไม่มี session รอยืนยัน (IF-AUTH-01, NFR-NWS-05, Q-NWS-04)
4. สร้างการอ่านและแสดงรายการข่าวสาร/ตารางเวลาที่เผยแพร่แล้ว โดยจำกัดตารางเวลาที่ภาคปัจจุบัน (FR-NWS-01, CON-NWS-01, ASM-NWS-04, AC-NWS-01)
5. เพิ่มการเลือกและเปิดรายละเอียด โดยจัดรูปแบบและการนำทางหลังทีมตอบ Q-NWS-02/Q-NWS-05 (FR-NWS-02, FR-NWS-03, DR-NWS-01, DR-NWS-02)
6. เพิ่มการเรียงรายการตามเกณฑ์ที่ทีมยืนยัน ไม่กำหนดวันที่เผยแพร่/วันที่แก้ไขหรือการปักหมุดเอง (DR-NWS-03, Q-NWS-03)
7. เพิ่มข้อความสถานะว่างและข้อผิดพลาดภาษาไทย พร้อมการลองใหม่; กำหนดขอบเขตการโหลดเมื่อข้อมูลล้มเหลวบางส่วนหลังได้คำตอบ (FR-NWS-04, FR-NWS-05, FR-NWS-06, NFR-NWS-01, Q-NWS-07)
8. ตรวจรับ AC-NWS-01–06, responsive 360 px, timeout, availability และ p95; วิธีวัด NFR ที่เสนอไว้รอการยืนยัน (NFR-NWS-02–05, Q-NWS-08)

## 8. สิ่งที่ยังไม่ทำ

- Q-NWS-01 ข่าวสารถูกสร้างและเผยแพร่โดยใครหรือ use case/ระบบใด แผนภาพไม่มี use case จัดการเนื้อหาข่าวสาร และรายการความต้องการ 20 ข้อไม่ได้ระบุ; ต้องถามทีมเจ้าของ UC-05 หรือผู้ดูแลข่าวสาร  
  ส่วนที่เกี่ยวข้องกับแหล่งข้อมูลข่าวสารจะยังไม่เชื่อมต่อจนกว่าจะได้คำตอบ
- Q-NWS-02 ตารางเวลาของภาคการศึกษาปัจจุบันควรแสดงในรูปแบบใด (ตารางรายกิจกรรม ปฏิทิน หรือรายการช่วงวัน); ต้องถามทีมเจ้าของ UC-05  
  ส่วนที่เกี่ยวข้องกับรูปแบบการแสดงตารางเวลาจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-NWS-03 "ล่าสุด" ใช้เกณฑ์วันที่เผยแพร่หรือวันที่แก้ไขครั้งสุดท้าย จัดลำดับข่าวกับตารางเวลาร่วมกันหรือแยกกัน และต้องมีการปักหมุดประกาศสำคัญหรือไม่; ต้องถามทีมเจ้าของ UC-05 หรือผู้ดูแลข่าวสาร  
  ส่วนที่เกี่ยวข้องกับการเรียงและการปักหมุดจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-NWS-04 นอกจากนักศึกษาแล้ว อาจารย์ที่ปรึกษาหรือเจ้าหน้าที่มีสิทธิ์ใช้หน้านี้ด้วยหรือไม่ และเมื่อผู้ที่ยังไม่เข้าสู่ระบบเปิดหน้า ระบบควรตอบสนองอย่างไร; ต้องถามทีมเจ้าของ UC-05 หรือผู้กำหนดสิทธิ์  
  ส่วนที่เกี่ยวข้องกับบทบาทเพิ่มเติมและ UX เมื่อไม่มี session จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-NWS-05 ข่าวสารกับตารางเวลาอยู่หน้าเดียวกันหรือแยกเมนู/หน้า และเมื่อเลือกหัวข้อแล้วต้องแสดงรายละเอียดอย่างไร; ต้องถามทีมเจ้าของ UC-05  
  ส่วนที่เกี่ยวข้องกับการจัดหน้าและการนำทางจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-NWS-06 ตารางเวลาที่แสดงต้องอ้างอิงข้อมูลหรือเวอร์ชันใดให้ตรงกับข้อมูลที่ใช้เปิด/ปิดแบบฟอร์ม และวันเริ่ม/วันสิ้นสุดตีความอย่างไร; ต้องถามผู้รับผิดชอบ UC-15 และผู้ดูแลการเปิด/ปิดแบบฟอร์ม  
  ส่วนที่เกี่ยวข้องกับการเชื่อม source/version และการตีความขอบเขตวันจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-NWS-07 หากแหล่งข่าวสารหรือตารางเวลาล้มเหลวเพียงบางส่วน ควรแสดงข้อมูลที่ดึงสำเร็จพร้อมข้อผิดพลาด หรือปฏิเสธทั้งหน้า และการลองใหม่ควรโหลดส่วนใด; ต้องถามทีมเจ้าของ UC-05  
  ส่วนที่เกี่ยวข้องกับพฤติกรรม partial failure และขอบเขตการลองใหม่จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-NWS-08 ทีมยืนยันค่า 360 px, availability 99% ต่อเดือน, p95 <= 2 วินาที และ timeout 30 นาทีหรือไม่ และจะวัด availability/เวลาตอบสนองจากขอบเขตใด; ต้องถามทีมและผู้รับผิดชอบ NFR  
  ส่วนที่เกี่ยวข้องกับเกณฑ์ NFR ที่ยังไม่ยืนยันและวิธีวัดจะยังไม่กำหนดจนกว่าจะได้คำตอบ

## หมายเหตุสำหรับทีม

- Constraint ทั้ง 5 ข้อถูกนำไปใช้ในแผน; การเชื่อมโยง source/version ตาม IF-SCHED-01 ยังต้องยืนยัน Q-NWS-06
- AC-NWS-01 ต้องรอเกณฑ์การเรียงตาม Q-NWS-03; AC-NWS-05 ต้องเข้าถึงข้อมูลจากแหล่งควบคุมแบบฟอร์ม; AC-NWS-04 จำลองความล้มเหลวของแหล่งข่าว
- NFR-NWS-03 ต้องเฝ้าระวังตามวิธีวัดที่ทีมยืนยัน; AC-NWS-06 ตรวจ viewport 360 px; NFR-NWS-05 ตรวจ timeout 30 นาที แต่ spec ยังไม่มี AC เฉพาะสำหรับ timeout
- IF-AUTH-01 กำหนดให้เข้าถึงได้เฉพาะผู้ยืนยันตัวตนแล้ว แต่ยังไม่มี AC สำหรับกรณีไม่มี session; การตอบสนองที่คาดหวังยังรอ Q-NWS-04
- ไม่เดาแหล่งข่าว รูปแบบ/การจัดหน้าจอ เกณฑ์ “ล่าสุด” source/version ตารางเวลา พฤติกรรม partial failure หรือการยืนยันค่าตัวเลข NFR
