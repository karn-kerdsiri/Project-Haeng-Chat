# Plan: Calculate Eligibility Result

## 1. Summary

- Feature: Calculate Eligibility Result
- Spec ID: SPEC-CAL-016
- Use Case: UC-16
- Owner: ทีม B
- Status: Draft v2
- Purpose: วางแผนการพัฒนาระบบคำนวณผลการตรวจสอบคุณสมบัติจากข้อมูลผลการเรียนที่ผ่านการตรวจสอบแล้ว
- Scope: รับข้อมูลผลการเรียน ดึงเกณฑ์ที่ใช้งาน คำนวณผล บันทึกผล และส่งผลกลับไปยัง UC-13

## 2. Technology Choices

| รายการ | เทคโนโลยี | ที่มา |
|---|---|---|
| Frontend | React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec |
| Backend | Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec |
| Database | PostgreSQL | IF-TECH-01 |
| Authentication | ใช้การยืนยันตัวตนผ่าน UC-13 | ตาม Spec |
| Criteria Source | ดึงเกณฑ์จาก UC-12 | ตาม Spec |

หมายเหตุ: เทคโนโลยี Frontend และ Backend เป็นข้อเสนอสำหรับการวางแผน ยังไม่ใช่ข้อกำหนดที่ทีมยืนยันแล้ว

## 3. Data Model

ข้อมูลหลักที่เกี่ยวข้องกับการทำงานมีดังนี้

| ข้อมูล | รายละเอียด |
|---|---|
| Application Reference | อ้างอิงใบสมัครที่ผ่านการตรวจสอบจาก UC-13 |
| Academic Results | ข้อมูลปีการศึกษา รายวิชา และผลการเรียน |
| Active Criteria Set | ชุดเกณฑ์ที่ใช้งานจาก UC-12 ประกอบด้วย GPAX ขั้นต่ำ หน่วยกิตสะสมขั้นต่ำ และรายวิชาบังคับที่ต้องผ่าน |
| Calculation Result | ผลการคำนวณ มีเพียง ผ่าน/ไม่ผ่าน |
| Calculation History | ประวัติผลการคำนวณแต่ละครั้ง โดยเก็บผลเดิมไว้ |
| Criteria Version | ข้อมูลอ้างอิงชุดเกณฑ์ที่ใช้คำนวณในแต่ละครั้ง |

หมายเหตุ: ยังไม่ต้องกำหนดตัวเลข GPAX จำนวนหน่วยกิต หรือรายวิชาบังคับ เพราะต้องใช้ค่าจาก UC-12

## 4. API / System Interaction

ลำดับการทำงานที่วางแผนไว้

1. รับคำขอคำนวณจาก UC-13
2. ตรวจสอบข้อมูลผลการเรียนที่ผ่านการตรวจสอบแล้ว
3. ดึงชุดเกณฑ์ที่ใช้งานจาก UC-12
4. ตรวจสอบว่ามีข้อมูลและเกณฑ์ครบถ้วนหรือไม่
5. คำนวณผลตามเกณฑ์ที่ทีมกำหนด
6. บันทึกผลการคำนวณและข้อมูลชุดเกณฑ์ที่ใช้
7. ส่งผลกลับไปยัง UC-13

ข้อเสนอทางเทคนิค: อาจใช้ API ภายในสำหรับรับคำขอคำนวณและส่งผลกลับ โดยรายละเอียด Endpoint จะกำหนดหลังจากทีมยืนยันรูปแบบการเชื่อมต่อ

กรณีเกิดข้อผิดพลาด ระบบต้องไม่เปลี่ยนแปลงผลการคำนวณเดิม

## 7. Implementation Steps

1. เตรียมรับข้อมูลผลการศึกษาที่ผ่านการตรวจสอบจาก UC-13 (FR-CAL-01, AC-CAL-01)
2. ดึงเงื่อนไขการผ่านที่ใช้งานอยู่จาก UC-12 ตามภาคการศึกษาที่เกี่ยวข้อง (FR-CAL-02, AC-CAL-01)
3. ตรวจสอบความครบถ้วนของข้อมูลก่อนเริ่มคำนวณ หากข้อมูลไม่ครบให้แจ้งรายการที่ขาดและหยุดการคำนวณ (FR-CAL-07, AC-CAL-02)
4. คำนวณผลผ่าน/ไม่ผ่านตามเงื่อนไขที่ได้รับ โดยไม่นับรายวิชาที่มีผลการเรียนไม่สมบูรณ์ว่าผ่าน (FR-CAL-03, FR-CAL-04, AC-CAL-01, AC-CAL-05)
5. ตรวจสอบกรณีไม่พบเงื่อนไขที่ใช้งานอยู่ และแจ้งว่าไม่สามารถคำนวณได้ (FR-CAL-08, AC-CAL-03)
6. บันทึกผลการคำนวณพร้อมเวลาและชุดเงื่อนไขที่ใช้ (FR-CAL-05, FR-CAL-11, AC-CAL-01, AC-CAL-08)
7. ส่งผลการคำนวณที่สำเร็จกลับไปยัง UC-13 เพื่อใช้ในขั้นตอนตรวจสอบและยืนยัน (FR-CAL-06, AC-CAL-07)
8. จัดการข้อผิดพลาดระหว่างคำนวณ โดยบันทึกข้อผิดพลาดและไม่เปลี่ยนผลเดิม (FR-CAL-09, AC-CAL-04)
9. ตรวจสอบความถูกต้องของผลเมื่อคำนวณซ้ำด้วยข้อมูลและเงื่อนไขชุดเดิม (FR-CAL-10, AC-CAL-06)
10. ทดสอบการป้องกันการเรียกใช้จากผู้ที่ไม่มีสิทธิ์ (NFR-CAL-04, AC-CAL-09)

## 8. Open Questions

- OQ-CAL-01 โครงสร้างและตรรกะของเงื่อนไขการผ่านเป็นแบบใด (เกรดขั้นต่ำต่อวิชา จำนวนวิชาที่ต้องผ่าน หน่วยกิตรวม หรือหลายเงื่อนไขรวมกันด้วย AND/OR) ซึ่งจำเป็นต่อ FR-CAL-03
- OQ-CAL-02 ผลการคำนวณมีเพียง ผ่าน/ไม่ผ่าน หรือมีค่าอื่น เช่น ผ่านแบบมีเงื่อนไข หรือรออีกภาคการศึกษา
- OQ-CAL-03 ผลการคำนวณต้องเก็บเหตุผลประกอบ (เงื่อนไขข้อใดไม่ผ่าน) ไว้ด้วยหรือไม่ เพื่อให้ UC-03, UC-10 และ UC-13 แสดงได้
- OQ-CAL-04 เมื่อคำนวณใหม่แล้วได้ผลต่างจากเดิม ต้องเก็บผลเดิมไว้เป็นประวัติหรือเขียนทับ
- OQ-CAL-05 คำนวณเป็นรายคำร้องเท่านั้น หรือรองรับการคำนวณเป็นชุดหลายคำร้องพร้อมกัน
- OQ-CAL-06 กรณีคำร้องแบบกลุ่ม/คู่ตาม UC-08 คำนวณแยกรายบุคคลหรือรวมเป็นกลุ่ม

หมายเหตุ: ยังไม่มีการกำหนดคำตอบแทนทีม และจะไม่สมมติรายละเอียดที่ยังไม่ได้รับการยืนยัน
