# Feature: ตรวจสอบเงื่อนไขเบื้องต้นอัตโนมัติ (Automatic Pre-check)
Spec ID: SPEC-PRE-007 | Source: Use Case Specification UC-07 ตรวจสอบเงื่อนไขเบื้องต้นอัตโนมัติ (Included by UC-01) + รายการความต้องการของทีม ข้อ 2 | Use case: UC-07
Owner: ทีม B | Status: Draft v2 | Updated: 2569-11-13

## Goal
ระบบตรวจสอบข้อมูลผลการศึกษาที่นักศึกษากรอกกับเงื่อนไขการผ่านที่เจ้าหน้าที่จัดการไว้โดยอัตโนมัติ
และแสดงผลการตรวจสอบเบื้องต้นให้นักศึกษาเห็นก่อนส่ง เพื่อลดความผิดพลาด

## Scope
### In scope
- IN-PRE-01 รับข้อมูลผลการศึกษาที่นักศึกษากรอกจาก UC-01            <- UC-07 ขั้น 1, Trigger
- IN-PRE-02 ดึงเงื่อนไขการผ่านที่เกี่ยวข้องและใช้งานอยู่             <- UC-07 ขั้น 2
- IN-PRE-03 เปรียบเทียบข้อมูลกับเงื่อนไข                          <- UC-07 ขั้น 3
- IN-PRE-04 แสดงผลการตรวจสอบเบื้องต้น                           <- UC-07 ขั้น 4
- IN-PRE-05 แจ้งกรณีข้อมูลไม่เพียงพอ ไม่พบเงื่อนไข และเงื่อนไขไม่พร้อมใช้งาน   <- UC-07 alt 1-2, Exception
### Out of scope
- OUT-PRE-01 การคำนวณผลการตรวจสอบคุณสมบัติที่เป็นผลทางการ - เป็นของ UC-16
- OUT-PRE-02 การสร้างและแก้ไขเงื่อนไขการผ่าน - เป็นของ UC-12 และ ข้อ 4
- OUT-PRE-03 การกรอกและบันทึกข้อมูลผลการศึกษา - เป็นของ UC-01
- OUT-PRE-04 การอนุมัติโดยอาจารย์ที่ปรึกษาหรือเจ้าหน้าที่ - เป็นของ UC-09 และ UC-13
- OUT-PRE-05 การแจ้งเตือนผลเบื้องต้นผ่านการแจ้งเตือนในระบบ - เป็นของ UC-17 และ UC-07 ไม่ระบุ

## Constraints
- IF-AUTH-01 การเรียกใช้ฟีเจอร์นี้ต้องอยู่ภายใต้ session ของนักศึกษาที่ยืนยันตัวตนแล้ว   <- ข้อ 12
- IF-WEB-01 ผลการตรวจสอบต้องแสดงบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และเงื่อนไขการผ่านอ่านจากฐานข้อมูล PostgreSQL   <- ข้อ 19
- IF-MST-01 เงื่อนไขการผ่านต้องอ่านจากข้อมูลที่เจ้าหน้าที่จัดการไว้ตาม UC-12 ไม่ฝังเงื่อนไขไว้ในโค้ด   <- ข้อ 4
- DOM-GRADE-01 เกรดที่ใช้ตรวจสอบต้องเป็นค่าตามระบบเกรดของมหาวิทยาลัย และรายวิชาที่ได้ผลไม่สมบูรณ์ต้องไม่ถูกนับว่าผ่าน   <- ข้อ 16
- CON-PRE-01 ผลการตรวจสอบเบื้องต้นต้องไม่ถูกนำไปใช้เป็นผลการตรวจสอบคุณสมบัติทางการ   <- UC-07 Goal, Postcondition
- CON-PRE-02 ระบบต้องตรวจสอบทันทีที่นักศึกษากดส่ง   <- ข้อ 2

## Data Rules
- DR-PRE-01 ข้อมูลนำเข้า: ข้อมูลผลการศึกษาที่นักศึกษากรอกในขั้นตอน UC-01 (ปีการศึกษา รายวิชา เกรด)   <- UC-07 ขั้น 1
- DR-PRE-02 ผลลัพธ์ประกอบด้วยผลสรุปรวมและผลรายเงื่อนไข โดยระบุสถานะผ่าน/ไม่ผ่าน/ข้อมูลไม่เพียงพอ ข้อมูลที่ใช้เปรียบเทียบ และเหตุผลเมื่อเงื่อนไขไม่ผ่าน   <- UC-07 ขั้น 3-4 (รูปแบบผลรายวิชาที่ยังไม่สมบูรณ์รอยืนยัน ดู Q-03)
- DR-PRE-03 รายวิชาที่ผลยังไม่สมบูรณ์ต้องถูกนับเป็น "ยังไม่ผ่าน" ในการตรวจเบื้องต้น ไม่ใช่ "ไม่ผ่าน"   <- ข้อ 16 (รอยืนยัน ดู Q-03)
- DR-PRE-04 เงื่อนไขที่ใช้ต้องเป็นชุดที่มีสถานะใช้งานอยู่ในภาคการศึกษานั้น   <- UC-07 Precondition

## Requirements
- FR-PRE-01 ระบบต้องรับข้อมูลผลการศึกษาที่นักศึกษากรอกตาม DR-PRE-01 เมื่อถูกเรียกจาก UC-01   <- UC-07 ขั้น 1, Trigger
- FR-PRE-02 ระบบต้องดึงเงื่อนไขการผ่านที่ใช้งานอยู่ตาม DR-PRE-04 และ IF-MST-01   <- UC-07 ขั้น 2
- FR-PRE-03 ระบบต้องเปรียบเทียบข้อมูลกับเงื่อนไขทุกข้อที่ดึงมา   <- UC-07 ขั้น 3
- FR-PRE-04 ระบบต้องแสดงผลสรุปรวมและผลรายเงื่อนไขตาม DR-PRE-02 โดยระบุว่าเงื่อนไขใดผ่านหรือไม่ผ่าน และบอกเหตุผลเมื่อไม่ผ่าน พร้อมระบุว่าเป็นผลเบื้องต้นตาม CON-PRE-01 และ ASM-PRE-04   <- UC-07 ขั้น 4
- FR-PRE-05 ระบบต้องตรวจสอบและแสดงผลทันทีที่นักศึกษากดส่งตาม CON-PRE-02   <- ข้อ 2
- FR-PRE-06 เมื่อข้อมูลที่กรอกไม่เพียงพอต่อการเปรียบเทียบ ระบบต้องไม่สรุปผ่าน/ไม่ผ่าน และแจ้งให้กรอกข้อมูลเพิ่มเติมเป็นรายข้อ   <- UC-07 alt 1
- FR-PRE-07 เมื่อไม่พบเงื่อนไขที่ใช้งานอยู่ ระบบต้องไม่สรุปผล และแจ้งให้ติดต่อเจ้าหน้าที่หรือรอการตรวจสอบ   <- UC-07 alt 2
- FR-PRE-08 เมื่อข้อมูลเงื่อนไขไม่พร้อมใช้งาน ระบบต้องไม่สรุปผล และแจ้งข้อผิดพลาด   <- UC-07 Exception
- FR-PRE-09 รายวิชาที่ผลไม่สมบูรณ์ต้องถูกจัดการตาม DR-PRE-03 ไม่ถูกนับว่าผ่าน   <- ข้อ 16
- FR-PRE-10 ผลการตรวจสอบเบื้องต้นต้องไม่เปลี่ยนสถานะคำร้องและต้องไม่ขัดขวางการส่งข้อมูลของนักศึกษา แม้ผลเบื้องต้นไม่ผ่าน ตาม ASM-PRE-05   <- CON-PRE-01

## Quality Requirements
- NFR-PRE-01 [Performance] การตรวจสอบเงื่อนไขเบื้องต้นต้องแสดงผลภายใน 3 วินาทีหลังนักศึกษากดส่ง   <- UC-07 NFR (Performance) + ค่าที่เสนอไว้ ดู ASM-PRE-01
- NFR-PRE-02 [Data Integrity] ผลการตรวจสอบต้องมาจากเงื่อนไขชุดเดียวกับที่ UC-16 ใช้คำนวณผลทางการ เพื่อไม่ให้ผลเบื้องต้นขัดกับผลทางการโดยไม่มีเหตุ
- NFR-PRE-03 [Usability] ข้อความผลการตรวจสอบและข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย และระบุช่องหรือรายการที่ต้องแก้ไข   <- ข้อ 10
- NFR-PRE-04 [Usability] หน้าผลการตรวจสอบเบื้องต้นต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-PRE-01)
- NFR-PRE-05 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9

## Acceptance Criteria
- [ ] AC-PRE-01 (FR-PRE-02, FR-PRE-03, FR-PRE-04)
      Given มีข้อมูลผลการศึกษาที่นักศึกษากรอก และมีเงื่อนไขการผ่านที่ใช้งานอยู่
      When  ระบบตรวจสอบอัตโนมัติ
      Then  ระบบแสดงผลสรุปรวมและผลรายเงื่อนไข โดยระบุว่าเงื่อนไขใดผ่านหรือไม่ผ่าน และบอกเหตุผลเมื่อไม่ผ่าน พร้อมระบุว่าเป็นผลเบื้องต้น
- [ ] AC-PRE-02 (FR-PRE-05, CON-PRE-02, NFR-PRE-01)
      Given นักศึกษากรอกข้อมูลผลการศึกษาครบ
      When  กดส่ง
      Then  ระบบตรวจสอบเงื่อนไขเบื้องต้นทันทีและแสดงผลภายใน 3 วินาที
- [ ] AC-PRE-03 (FR-PRE-06)
      Given ข้อมูลที่กรอกไม่เพียงพอต่อการเปรียบเทียบเงื่อนไข
      When  ระบบตรวจสอบอัตโนมัติ
      Then  ระบบไม่สรุปผ่าน/ไม่ผ่าน และแจ้งรายการข้อมูลที่ต้องกรอกเพิ่ม
- [ ] AC-PRE-04 (FR-PRE-07)
      Given ไม่มีเงื่อนไขการผ่านที่ใช้งานอยู่
      When  ระบบตรวจสอบอัตโนมัติ
      Then  ระบบไม่สรุปผล และแจ้งให้ติดต่อเจ้าหน้าที่หรือรอการตรวจสอบ
- [ ] AC-PRE-05 (FR-PRE-08)
      Given แหล่งข้อมูลเงื่อนไขไม่พร้อมใช้งาน
      When  ระบบตรวจสอบอัตโนมัติ
      Then  ระบบไม่สรุปผล และแจ้งข้อผิดพลาด
- [ ] AC-PRE-06 (FR-PRE-09, DR-PRE-03, DOM-GRADE-01)
      Given ข้อมูลมีรายวิชาที่ผลยังไม่สมบูรณ์
      When  ระบบตรวจสอบอัตโนมัติ
      Then  รายวิชานั้นไม่ถูกนับว่าผ่าน
- [ ] AC-PRE-07 (FR-PRE-10, CON-PRE-01)
      Given ผลการตรวจสอบเบื้องต้นระบุว่ายังไม่ผ่านเงื่อนไขบางข้อ
      When  นักศึกษาเลือกส่งข้อมูลต่อ
      Then  นักศึกษาส่งข้อมูลต่อได้ สถานะคำร้องไม่ถูกเปลี่ยนด้วยผลเบื้องต้น และผลเบื้องต้นไม่ถือเป็นผลทางการ
- [ ] AC-PRE-08 (NFR-PRE-02)
      Given เงื่อนไขการผ่านชุดเดียวกัน
      When  เทียบผลเบื้องต้นจาก UC-07 กับผลคำนวณจาก UC-16 บนข้อมูลชุดเดียวกัน
      Then  ผลทั้งสองต้องสอดคล้องกัน

## Assumptions & Open Questions
- ASM-PRE-01 UC-07 ระบุ NFR เป็นหมวด (Performance, Data Integrity) ค่าตัวเลขใน NFR-PRE-01 และ NFR-PRE-04 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-PRE-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-PRE-03 เงื่อนไขการผ่านที่ใช้ในฟีเจอร์นี้คือชุดเดียวกับที่เจ้าหน้าที่จัดการใน UC-12 ตามข้อ 4
- ASM-PRE-04 ผลการตรวจสอบเบื้องต้นต้องแสดงทั้งผลสรุปรวมและรายละเอียดรายเงื่อนไข ระบุว่าเงื่อนไขใดผ่านหรือไม่ผ่าน และเหตุผลเมื่อไม่ผ่าน (คำตอบทีมต่อ Q4)
- ASM-PRE-05 นักศึกษาต้องสามารถส่งข้อมูลต่อได้ แม้ผลการตรวจสอบเบื้องต้นไม่ผ่าน เพราะผลนี้เป็นเพียงการช่วยตรวจสอบก่อนส่ง ไม่ใช่ผลตัดสินจริง (คำตอบทีมต่อ Q5)
- Q-01 (เดิม OQ-PRE-05) เงื่อนไขการผ่านมีรูปแบบอะไรบ้าง (เช่น เกรดขั้นต่ำต่อวิชา จำนวนหน่วยกิต วิชาบังคับ) ซึ่งกระทบตรรกะการเปรียบเทียบใน FR-PRE-03; ต้องรอคำตอบจากเจ้าหน้าที่ผู้จัดการเงื่อนไขตาม UC-12 หรือทีม
- Q-02 ผลเบื้องต้นกับผลจาก UC-16 ที่ใช้ข้อมูลชุดเดียวกันต้องสอดคล้องกันในระดับใด และผลต่างแบบใดถือว่ายอมรับได้; ต้องรอคำตอบจากทีมและผู้รับผิดชอบ UC-16
- Q-03 (เดิม OQ-PRE-02) รายวิชาที่ผลไม่สมบูรณ์ให้ถือเป็น "ยังไม่ผ่าน" หรือ "ข้อมูลไม่เพียงพอ" ในผลเบื้องต้น; ต้องรอคำตอบจากทีม
- Q-04 (FR-PRE-08) กรณีใดบ้างที่ถือว่าข้อมูลเงื่อนไขไม่พร้อมใช้งาน และต้องแจ้งข้อผิดพลาดอย่างไร; ต้องรอคำตอบจากเจ้าหน้าที่ผู้ดูแลข้อมูลเงื่อนไขหรือทีม
- Q-05 (เดิม OQ-PRE-04) ผลการตรวจสอบเบื้องต้นต้องถูกบันทึกไว้ให้เจ้าหน้าที่หรืออาจารย์เห็นหรือเป็นเพียงการแสดงผลชั่วคราว; ต้องรอคำตอบจากทีมและผู้ใช้งานที่เกี่ยวข้อง
- Q-06 (ASM-PRE-01) ทีมยืนยันค่า 3 วินาทีใน NFR-PRE-01 และ 360 px ใน NFR-PRE-04 หรือไม่; ต้องรอคำตอบจากทีม
