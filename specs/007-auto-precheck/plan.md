# Plan: ตรวจสอบเงื่อนไขเบื้องต้นอัตโนมัติ

## 1. สรุปแนวทาง
- ให้นักศึกษาเรียกตรวจผลการศึกษาที่กรอกจาก UC-01 กับเงื่อนไขการผ่านที่เกี่ยวข้องและกำลังใช้งาน (FR-PRE-01, FR-PRE-02)
- อ่านเงื่อนไขที่เจ้าหน้าที่จัดการไว้จาก PostgreSQL โดยไม่ฝังเงื่อนไขไว้ในโค้ด (IF-TECH-01, IF-MST-01)
- เปรียบเทียบข้อมูลกับเงื่อนไขและจัดเตรียมผลสรุปกับรายละเอียดรายเงื่อนไข (FR-PRE-03, FR-PRE-04, DR-PRE-02)
- แสดงผลในเบราว์เซอร์เป็นภาษาไทย และแสดงผลภายในเกณฑ์เวลาที่กำหนดใน spec (IF-WEB-01, NFR-PRE-01, NFR-PRE-03)
- ผลเบื้องต้นต้องไม่เป็นผลทางการหรือขัดขวางการส่งข้อมูล และจัดการข้อมูลผลไม่สมบูรณ์ตามข้อสรุปที่ทีมยังต้องให้ (CON-PRE-01, FR-PRE-10, Q-03)

| PostgreSQL | IF-TECH-01 | อ่านชุดเงื่อนไขผ่านข้อมูลที่ UC-12 จัดการ (IF-MST-01); ยังไม่เลือกว่าจะเชื่อมต่อโดยตรงหรือผ่านบริการใด เพราะ ASM-PRE-02 ระบุว่าทีมต้องตัดสินเรื่องความต่างจาก plan 001 |

## 3. โมเดลข้อมูล

รายการต่อไปนี้เป็น data contract เชิงแนวคิด ไม่ได้กำหนดตารางฐานข้อมูลหรือการบันทึกผลเบื้องต้น

| Entity / DTO | ฟิลด์หลัก | รองรับ FR / Constraint |
|---|---|---|
| `PrecheckInput` | ปีการศึกษา, รายวิชา, เกรด (รายละเอียดตามข้อมูลที่ UC-01 ส่งมา) | FR-PRE-01, DR-PRE-01 |
| `ActiveConditionReadModel` | ชุดเงื่อนไขที่เกี่ยวข้องและมีสถานะใช้งานในภาคการศึกษานั้น; โครงสร้างและชนิดเงื่อนไขรอคำตอบ Q-01 | FR-PRE-02, FR-PRE-03, DR-PRE-04, IF-MST-01 |
| `ConditionCheckResult` | สถานะรายเงื่อนไข, ข้อมูลที่ใช้เปรียบเทียบ, เหตุผลเมื่อไม่ผ่าน | FR-PRE-03, FR-PRE-04, DR-PRE-02, ASM-PRE-04; การจัดประเภทผลที่ยังไม่สมบูรณ์รอ Q-03 |
| `PrecheckSummary` | ผลสรุปรวมและรายการผลรายเงื่อนไข; กติกาสรุปภาพรวมยังไม่กำหนดเกินกว่าข้อความใน spec และรอคำตอบ Q-01 ถึง Q-03 | FR-PRE-04, DR-PRE-02, ASM-PRE-04 |

ยังไม่กำหนด persistent entity สำหรับผลเบื้องต้นจนกว่าทีมจะตอบ Q-05; ห้ามถือว่าผลเบื้องต้นเป็นผลทางการ (CON-PRE-01). ไม่มีการสร้างหรือแก้ไขเงื่อนไขในฟีเจอร์นี้ (OUT-PRE-02).

## 4. API / หน้าจอ

| รายการ | รายละเอียด | รองรับ FR |
|---|---|---|
| `POST /student/academic-records/pre-check` (ชื่อ path เสนอในแผน) | Input: `PrecheckInput` จาก UC-01; Output: `PrecheckSummary` และผลรายเงื่อนไข; กรณีข้อมูลไม่พอ/ไม่พบเงื่อนไข/แหล่งข้อมูลไม่พร้อม ต้องคืนสถานะที่ไม่สรุปผ่านหรือไม่ผ่านตามกรณี (รูปแบบ API สุดท้ายรอทีมเลือก backend และรายละเอียด Q-04) | FR-PRE-01 ถึง FR-PRE-09 |
| ส่วนแสดงผลตรวจเบื้องต้นใน UC-01 | แสดงผลสรุปและรายละเอียดรายเงื่อนไข พร้อมระบุว่าเป็นผลเบื้องต้น; ใช้ข้อความภาษาไทย; ไม่ขัดขวางการส่งข้อมูลต่อเมื่อผลไม่ผ่าน | FR-PRE-04, FR-PRE-05, FR-PRE-10, NFR-PRE-03 |
| การตรวจ session ก่อนเรียกใช้ | รับเฉพาะ session ของนักศึกษาที่ผ่านการยืนยันตัวตน; ใช้การจัดการ session ของระบบโดยไม่เพิ่ม flow การยืนยันตัวตนใหม่ | IF-AUTH-01, NFR-PRE-05 |

การเรียกตรวจเริ่มจากการกดส่งตาม FR-PRE-05/CON-PRE-02 แต่ผลตรวจไม่ตัดสินแทนการส่งข้อมูลจริงและไม่ขัดขวางการส่งตาม FR-PRE-10/ASM-PRE-05; การกรอกหรือบันทึกข้อมูลผลการศึกษาใน UC-01 อยู่นอกขอบเขตของฟีเจอร์นี้ (OUT-PRE-03).

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-PRE-01 | `test_AC_PRE_01_summary_and_condition_details` | เตรียมข้อมูลนักศึกษาและชุดเงื่อนไขที่ใช้งานอยู่ ตรวจว่ามีผลสรุป ผลรายเงื่อนไข และเหตุผลเมื่อไม่ผ่าน พร้อมระบุว่าเป็นผลเบื้องต้น |
| AC-PRE-02 | `test_AC_PRE_02_precheck_after_submit_within_3_seconds` | กดส่งข้อมูลครบ จับเวลาตั้งแต่กดจนแสดงผลและตรวจเกณฑ์ 3 วินาที; ค่านี้ยังรอการยืนยันตาม Q-06 |
| AC-PRE-03 | `test_AC_PRE_03_insufficient_input_lists_missing_items` | ส่งข้อมูลที่ไม่พอต่อการเปรียบเทียบ ตรวจว่าไม่สรุปผ่าน/ไม่ผ่านและแจ้งรายการที่ต้องกรอกเพิ่ม |
| AC-PRE-04 | `test_AC_PRE_04_no_active_conditions` | ใช้ชุดข้อมูลที่ไม่มีเงื่อนไขใช้งานอยู่ ตรวจว่าไม่สรุปผลและแจ้งให้ติดต่อเจ้าหน้าที่หรือรอการตรวจสอบ |
| AC-PRE-05 | `test_AC_PRE_05_condition_source_unavailable` | ทำให้แหล่งข้อมูลเงื่อนไขไม่พร้อมใช้งานในสภาพแวดล้อมทดสอบ ตรวจว่าไม่สรุปผลและแจ้งข้อผิดพลาด |
| AC-PRE-06 | `test_AC_PRE_06_incomplete_course_not_counted_as_pass` | ส่งข้อมูลที่มีรายวิชาผลไม่สมบูรณ์ ตรวจว่าไม่ถูกนับว่าผ่าน; ไม่ยืนยันป้ายสถานะจนกว่าจะตอบ Q-03 |
| AC-PRE-07 | `test_AC_PRE_07_failed_precheck_does_not_block_submission` | ให้ผลเบื้องต้นไม่ผ่านแล้วส่งข้อมูลต่อ ตรวจว่าส่งต่อได้ สถานะคำร้องไม่เปลี่ยนเพราะผลเบื้องต้น และผลไม่ถือเป็นผลทางการ |
| AC-PRE-08 | `test_AC_PRE_08_precheck_matches_official_check` | ใช้ข้อมูลและชุดเงื่อนไขเดียวกันเปรียบเทียบผล UC-07 กับ UC-16; เกณฑ์ความสอดคล้องยังรอคำตอบ Q-02 |

AC-PRE-02 ต้องทดสอบกับสภาพแวดล้อมที่วัดเวลาได้ และ AC-PRE-05 ต้องจำลองแหล่งข้อมูลไม่พร้อมใช้งาน; เกณฑ์ที่เกี่ยวข้องยังขึ้นกับคำตอบ Q-06 และ Q-04 ตามลำดับ. AC-PRE-08 ต้องมีผลจาก UC-16 บนข้อมูลชุดเดียวกัน และยังขาดเกณฑ์ความสอดคล้องจนกว่าจะได้คำตอบ Q-02.

## 7. ลำดับงาน

1. กำหนดสัญญาข้อมูลระหว่าง UC-01 กับการตรวจเบื้องต้น โดยใช้ปีการศึกษา รายวิชา และเกรดตาม DR-PRE-01 (FR-PRE-01, FR-PRE-05, CON-PRE-02)
2. อ่านเงื่อนไขที่เกี่ยวข้องและใช้งานอยู่จากข้อมูลที่ UC-12 จัดการ โดยไม่ฝังเงื่อนไขในโค้ด (FR-PRE-02, DR-PRE-04, IF-MST-01, IF-TECH-01)
3. กำหนดการเปรียบเทียบกับทุกเงื่อนไขและจัดการเกรดตามที่ทีมยืนยัน; หยุดส่วนตรรกะที่ขึ้นกับรายละเอียดจนได้คำตอบ Q-01/Q-03 (FR-PRE-03, FR-PRE-09, DOM-GRADE-01)
4. สร้างรูปแบบผลสรุปและผลรายเงื่อนไข พร้อมข้อมูลที่ใช้เปรียบเทียบและเหตุผลเมื่อไม่ผ่าน (FR-PRE-04, DR-PRE-02, ASM-PRE-04)
5. สร้างการตอบกรณีข้อมูลไม่พอ ไม่พบเงื่อนไข หรือแหล่งข้อมูลไม่พร้อมใช้งาน โดยไม่สรุปผลเมื่อกำหนดไว้ (FR-PRE-06, FR-PRE-07, FR-PRE-08)
6. เชื่อมส่วนแสดงผลภาษาไทยในเบราว์เซอร์กับจุดเรียกจาก UC-01 และคงการส่งข้อมูลต่อแม้ผลเบื้องต้นไม่ผ่าน (FR-PRE-05, FR-PRE-10, ASM-PRE-05, IF-WEB-01, NFR-PRE-03)
7. ตรวจ session นักศึกษา ความเข้ากันได้บนจอมือถือ และการจัดการ session idle ตามข้อกำหนด (IF-AUTH-01, NFR-PRE-04, NFR-PRE-05)
8. ทดสอบ AC-PRE-01 ถึง AC-PRE-08 รวมเวลาตอบสนองและเทียบผลกับ UC-16; เกณฑ์ที่ขึ้นกับ Q-02/Q-06 รอการยืนยันจากทีม (NFR-PRE-01, AC-PRE-01 ถึง AC-PRE-08)

## 8. สิ่งที่ยังไม่ทำ

- Q-01 (เดิม OQ-PRE-05) เงื่อนไขการผ่านมีรูปแบบอะไรบ้าง (เช่น เกรดขั้นต่ำต่อวิชา จำนวนหน่วยกิต วิชาบังคับ) ซึ่งกระทบตรรกะการเปรียบเทียบใน FR-PRE-03; ต้องรอคำตอบจากเจ้าหน้าที่ผู้จัดการเงื่อนไขตาม UC-12 หรือทีม — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-02 ผลเบื้องต้นกับผลจาก UC-16 ที่ใช้ข้อมูลชุดเดียวกันต้องสอดคล้องกันในระดับใด และผลต่างแบบใดถือว่ายอมรับได้; ต้องรอคำตอบจากทีมและผู้รับผิดชอบ UC-16 — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-03 (เดิม OQ-PRE-02) รายวิชาที่ผลไม่สมบูรณ์ให้ถือเป็น "ยังไม่ผ่าน" หรือ "ข้อมูลไม่เพียงพอ" ในผลเบื้องต้น; ต้องรอคำตอบจากทีม — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-04 (FR-PRE-08) กรณีใดบ้างที่ถือว่าข้อมูลเงื่อนไขไม่พร้อมใช้งาน และต้องแจ้งข้อผิดพลาดอย่างไร; ต้องรอคำตอบจากเจ้าหน้าที่ผู้ดูแลข้อมูลเงื่อนไขหรือทีม — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-05 (เดิม OQ-PRE-04) ผลการตรวจสอบเบื้องต้นต้องถูกบันทึกไว้ให้เจ้าหน้าที่หรืออาจารย์เห็นหรือเป็นเพียงการแสดงผลชั่วคราว; ต้องรอคำตอบจากทีมและผู้ใช้งานที่เกี่ยวข้อง — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-06 (ASM-PRE-01) ทีมยืนยันค่า 3 วินาทีใน NFR-PRE-01 และ 360 px ใน NFR-PRE-04 หรือไม่; ต้องรอคำตอบจากทีม — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
