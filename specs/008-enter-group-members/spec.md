# Feature: กรอกข้อมูลสมาชิกกลุ่ม / คู่ (Enter Group or Pair Members)
Spec ID: SPEC-GRP-008 | Source: Use Case Specification UC-08 กรอกข้อมูลสมาชิกกลุ่ม / คู่ (Extend ของ UC-01) | Use case: UC-08
Owner: ทีม B | Status: Draft v1 | Updated: 2569-10-21

## Goal
นักศึกษาที่เลือกทำงานแบบกลุ่มหรือคู่ ระบุข้อมูลสมาชิกที่เกี่ยวข้องได้
และระบบบันทึกความสัมพันธ์ของสมาชิกให้ผูกกับคำขอเดียวกัน

## Scope
### In scope
- IN-GRP-01 แสดงช่องกรอกข้อมูลสมาชิกกลุ่ม/คู่                       <- UC-08 ขั้น 1
- IN-GRP-02 กรอกข้อมูลสมาชิก หรือระบุข้อมูลที่ใช้เชื่อมโยงสมาชิก        <- UC-08 ขั้น 2
- IN-GRP-03 ตรวจสอบสมาชิกที่ระบุ รวมถึงกรณีไม่พบ อยู่กลุ่มอื่น และข้อมูลซ้ำ   <- UC-08 ขั้น 3, alt 1-3
- IN-GRP-04 ยืนยันข้อมูลสมาชิก                                    <- UC-08 ขั้น 4
- IN-GRP-05 บันทึกความสัมพันธ์ของสมาชิกให้ผูกกับคำขอเดียวกัน         <- UC-08 ขั้น 5, Postcondition
### Out of scope
- OUT-GRP-01 การกรอกและส่งผลการศึกษา - เป็นของ UC-01 ซึ่ง use case นี้เป็น extend
- OUT-GRP-02 การเลือกกลุ่มอาจารย์ที่ปรึกษา - เป็นของ UC-06
- OUT-GRP-03 การตรวจสอบและอนุมัติโดยอาจารย์หรือเจ้าหน้าที่ - เป็นของ UC-09 และ UC-13
- OUT-GRP-04 การสร้างบัญชีผู้ใช้ของสมาชิก - เป็นของระบบบัญชีมหาวิทยาลัยตามข้อ 12
- OUT-GRP-05 การแจ้งเตือนสมาชิกให้ยืนยันการเข้ากลุ่ม - UC-08 ไม่ระบุ (ดู OQ-GRP-04)

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และความสัมพันธ์ของสมาชิกเก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- CON-GRP-01 นักศึกษา 1 คนอยู่ได้เพียง 1 กลุ่ม/คู่ ต่อ 1 ภาคการศึกษา   <- UC-08 alt 2
- CON-GRP-02 รายชื่อสมาชิกใน 1 กลุ่มต้องไม่มีรายการซ้ำ   <- UC-08 alt 3
- CON-GRP-03 สมาชิกที่ระบุต้องเป็นนักศึกษาที่มีอยู่ในระบบ   <- UC-08 ขั้น 3, alt 1

## Data Rules
- DR-GRP-01 ข้อมูลที่ใช้ระบุสมาชิก 1 คน: ข้อมูลที่ใช้เชื่อมโยงกับบัญชีนักศึกษาในระบบ (ฟิลด์ที่ใช้ยังไม่ระบุ ดู OQ-GRP-01)
- DR-GRP-02 ข้อมูลสมาชิกเป็นฟิลด์บังคับเมื่อนักศึกษาเลือกทำงานแบบกลุ่ม/คู่   <- UC-08 Precondition
- DR-GRP-03 สมาชิกซ้ำ = ระบุนักศึกษาคนเดียวกันมากกว่า 1 ครั้งในกลุ่มเดียวกัน   <- UC-08 alt 3
- DR-GRP-04 จำนวนสมาชิกต่อกลุ่มต้องอยู่ในช่วงที่คณะกำหนด (ค่ายังไม่ระบุ ดู OQ-GRP-02)

## Requirements
- FR-GRP-01 ระบบต้องแสดงช่องกรอกข้อมูลสมาชิกเมื่อนักศึกษาเลือกทำรายการแบบกลุ่ม/คู่   <- UC-08 ขั้น 1, Trigger
- FR-GRP-02 ระบบต้องให้นักศึกษากรอกหรือระบุข้อมูลที่ใช้เชื่อมโยงสมาชิกตาม DR-GRP-01   <- UC-08 ขั้น 2
- FR-GRP-03 ระบบต้องตรวจสอบว่าสมาชิกที่ระบุมีอยู่ในระบบตาม CON-GRP-03 ก่อนให้ยืนยัน   <- UC-08 ขั้น 3
- FR-GRP-04 เมื่อไม่พบสมาชิกที่ระบุ ระบบต้องไม่บันทึก และแจ้งให้ตรวจสอบข้อมูล   <- UC-08 alt 1
- FR-GRP-05 เมื่อสมาชิกที่ระบุอยู่ในกลุ่มอื่นแล้วตาม CON-GRP-01 ระบบต้องแจ้งเตือนและไม่ผูกสมาชิกนั้นเข้ากลุ่มใหม่   <- UC-08 alt 2
- FR-GRP-06 เมื่อพบสมาชิกซ้ำตาม DR-GRP-03 ระบบต้องให้แก้ไขก่อน และไม่บันทึกรายการซ้ำ   <- UC-08 alt 3
- FR-GRP-07 ระบบต้องแสดงข้อมูลสมาชิกให้นักศึกษายืนยันก่อนบันทึก   <- UC-08 ขั้น 4
- FR-GRP-08 เมื่อยืนยัน ระบบต้องบันทึกความสัมพันธ์ของสมาชิกให้ผูกกับคำขอเดียวกัน   <- UC-08 ขั้น 5, Postcondition
- FR-GRP-09 หากเชื่อมโยงสมาชิกไม่สำเร็จ ระบบต้องไม่บันทึกความสัมพันธ์บางส่วน และแจ้งข้อผิดพลาดพร้อมให้ลองใหม่   <- UC-08 Exception
- FR-GRP-10 ระบบต้องแสดงเฉพาะข้อมูลสมาชิกเท่าที่จำเป็นต่อการยืนยันตัวสมาชิก   <- UC-08 NFR (Privacy) (ขอบเขตข้อมูลรอยืนยัน ดู OQ-GRP-03)

## Quality Requirements
- NFR-GRP-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-GRP-02 [Security] นักศึกษาแก้ไขสมาชิกของกลุ่มที่ตนไม่ได้เป็นสมาชิกไม่ได้ ต้องได้ HTTP 403
- NFR-GRP-03 [Privacy] ระบบต้องไม่เปิดเผยข้อมูลส่วนบุคคลของนักศึกษาคนอื่นเกินกว่าที่ FR-GRP-10 กำหนด แม้ในกรณีค้นหาไม่พบ
- NFR-GRP-04 [Data Integrity] การบันทึกความสัมพันธ์ของสมาชิกต้องเป็นธุรกรรมเดียว ไม่เกิดกลุ่มที่มีสมาชิกค้างบางส่วน
- NFR-GRP-05 [Usability] ข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย และระบุช่องที่ต้องแก้ไข   <- ข้อ 10
- NFR-GRP-06 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-GRP-01)

## Acceptance Criteria
- [ ] AC-GRP-01 (FR-GRP-03, FR-GRP-08, CON-GRP-01)
      Given นักศึกษาเลือกทำงานแบบกลุ่ม/คู่ และระบุสมาชิกที่มีอยู่ในระบบและยังไม่อยู่กลุ่มอื่น
      When  กรอกข้อมูลสมาชิกถูกต้องและยืนยัน
      Then  ระบบบันทึกและเชื่อมโยงสมาชิกกับคำขอเดียวกัน
- [ ] AC-GRP-02 (FR-GRP-04, CON-GRP-03)
      Given ระบุสมาชิกด้วยข้อมูลที่ไม่มีอยู่ในระบบ
      When  กดตรวจสอบหรือยืนยัน
      Then  ระบบไม่บันทึก และแจ้งให้ตรวจสอบข้อมูล
- [ ] AC-GRP-03 (FR-GRP-05, CON-GRP-01)
      Given สมาชิกที่ระบุอยู่ในกลุ่มอื่นของภาคการศึกษาเดียวกันแล้ว
      When  กดยืนยัน
      Then  ระบบแจ้งเตือน และไม่ผูกสมาชิกนั้นเข้ากลุ่มใหม่
- [ ] AC-GRP-04 (FR-GRP-06, DR-GRP-03, CON-GRP-02)
      Given ระบุนักศึกษาคนเดียวกัน 2 ครั้งในกลุ่มเดียวกัน
      When  กดยืนยัน
      Then  ระบบให้แก้ไขก่อน และไม่บันทึกรายการซ้ำ
- [ ] AC-GRP-05 (FR-GRP-09, NFR-GRP-04)
      Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึกความสัมพันธ์
      When  กดยืนยัน
      Then  ไม่มีความสัมพันธ์ของสมาชิกถูกสร้างบางส่วน และระบบแจ้งข้อผิดพลาดพร้อมให้ลองใหม่
- [ ] AC-GRP-06 (FR-GRP-10, NFR-GRP-03)
      Given ระบุสมาชิกด้วยข้อมูลที่ใช้เชื่อมโยง
      When  ระบบแสดงผลการค้นหาสมาชิก
      Then  ระบบแสดงเฉพาะข้อมูลเท่าที่จำเป็นต่อการยืนยันตัวสมาชิก
- [ ] AC-GRP-07 (NFR-GRP-02)
      Given นักศึกษา A ไม่ได้เป็นสมาชิกของกลุ่ม G
      When  ส่ง request แก้ไขสมาชิกของกลุ่ม G ด้วย session ของ A
      Then  ระบบตอบ HTTP 403 และข้อมูลกลุ่ม G ไม่เปลี่ยนแปลง

## Assumptions & Open Questions
- ASM-GRP-01 UC-08 ระบุ NFR เป็นหมวด (Security, Data Integrity, Privacy) ค่าตัวเลขใน NFR-GRP-06 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-GRP-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-GRP-03 "คำขอ" ที่สมาชิกถูกผูกเข้าด้วยกันคือคำขอส่งผลการศึกษาตาม UC-01
- OQ-GRP-01 ข้อมูลที่ใช้ระบุและเชื่อมโยงสมาชิกคือฟิลด์ใด (รหัสนักศึกษา อีเมลมหาวิทยาลัย หรืออื่น) และต้องกรอกข้อมูลสมาชิกเองหรือค้นหาจากระบบ
- OQ-GRP-02 จำนวนสมาชิกต่อกลุ่มต่ำสุดและสูงสุดเท่าไร และ "คู่" หมายถึง 2 คนเสมอหรือไม่
- OQ-GRP-03 ข้อมูลของสมาชิกที่แสดงให้ผู้กรอกเห็นได้มีแค่ไหน (เช่น ชื่อย่อ ชื่อเต็ม สาขา) เพื่อไม่ขัดกับ NFR หมวด Privacy ของ UC-08
- OQ-GRP-04 สมาชิกที่ถูกระบุต้องยืนยันการเข้ากลุ่มเองหรือไม่ และถ้าต้องยืนยัน ใช้ช่องทางใด (UC-17 หรืออื่น)
- OQ-GRP-05 ใครเป็นผู้แก้ไขหรือถอนสมาชิกออกจากกลุ่มได้ และทำได้จนถึงเมื่อใด
- OQ-GRP-06 สมาชิกทุกคนต้องส่งผลการศึกษาของตนเองตาม UC-01 ด้วยหรือไม่ หรือใช้คำขอร่วมกัน 1 ชุด
