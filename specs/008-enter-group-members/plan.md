# Plan: SPEC-GRP-008 กรอกข้อมูลสมาชิกกลุ่ม / คู่

## 1. สรุปแนวทาง (5 บรรทัด)

- ให้นักศึกษาที่เลือกทำงานแบบกลุ่ม/คู่เปิดช่องกรอกข้อมูลสมาชิกตาม FR-GRP-01 และ DR-GRP-02
- รับรหัสนักศึกษาของสมาชิกเพื่อค้นหาจากข้อมูลนักศึกษาในระบบ โดยไม่ให้กรอกข้อมูลส่วนตัวเองตาม FR-GRP-02 และ DR-GRP-01
- แสดงเฉพาะรหัสนักศึกษา ชื่อ–นามสกุล และสาขาให้ตรวจสอบก่อนบันทึกตาม FR-GRP-07, FR-GRP-10 และ NFR-GRP-03
- ตรวจสมาชิกที่มีอยู่แล้ว กลุ่ม/ภาคการศึกษา และรายการซ้ำตาม FR-GRP-03 ถึง FR-GRP-06 และ CON-GRP-01 ถึง CON-GRP-03
- เมื่อยืนยัน ให้บันทึกความสัมพันธ์เข้ากับคำขอเดียวกันแบบธุรกรรมเดียว พร้อมคงข้อกำหนดด้าน session ตาม FR-GRP-08, FR-GRP-09, NFR-GRP-04 และ IF-AUTH-01

## 2. เทคโนโลยีที่ใช้

|---|---|---|

| Vite | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้ค่าเริ่มต้นของรายวิชาสำหรับ React; ไม่ใช่ requirement |
| PostgreSQL | IF-TECH-01 | ใช้เก็บความสัมพันธ์สมาชิกตามข้อกำหนด |
| Browser | IF-WEB-01 | หน้าจอต้องใช้งานได้โดยไม่ติดตั้งโปรแกรมเพิ่ม |
| Backend/API framework | ทีมเลือกเอง ไม่ได้มาจาก spec | เว้นการเลือกไว้ตามคำตอบของทีม; ไม่กำหนด FastAPI หรือ framework อื่นในแผนนี้ |

## 3. โมเดลข้อมูล

เป็นโมเดลเชิงแนวคิดเพื่อวางแผน ไม่กำหนด schema ของระบบคำขอเดิมหรือแหล่งข้อมูลนักศึกษาเกินกว่าที่ระบุใน spec

| Entity / DTO | ฟิลด์หลัก | รองรับ FR / Constraint |
|---|---|---|
| `MemberRelation` | การอ้างอิงคำขอเดียวกัน และรหัสนักศึกษาของสมาชิก; ใช้บริบทภาคการศึกษาของคำขอเพื่อตรวจการอยู่ได้กลุ่มเดียวตาม CON-GRP-01 โดยรูปแบบการเชื่อมกับโมเดลคำขอเดิมต้องตรวจสอบก่อน | FR-GRP-08, DR-GRP-01, CON-GRP-01, CON-GRP-02 |
| `StudentLookupResult` (ข้อมูลอ่านอย่างเดียว) | รหัสนักศึกษา ชื่อ–นามสกุล และสาขาเท่านั้น; ไม่มีฟิลด์เบอร์โทรหรือข้อมูลติดต่ออื่น และไม่สร้างสำเนาข้อมูลส่วนบุคคลเกิน FR-GRP-10 | FR-GRP-02, FR-GRP-03, FR-GRP-10, NFR-GRP-03, CON-GRP-03 |

ยังไม่กำหนดโครงสร้างกลุ่ม/คำขอร่วมกัน หรือการเก็บข้อมูลสมาชิกผู้กรอกเพิ่มเติม จนกว่าจะได้คำตอบ Q-01 และ Q-02; ไม่เพิ่มข้อมูลติดต่อของสมาชิก (FR-GRP-10, NFR-GRP-03).

## 4. API / หน้าจอ

ชื่อ path เป็นข้อเสนอทางเทคนิคสำหรับแผน ไม่ใช่ requirement จาก spec; รายละเอียดส่วนที่ขึ้นกับ Open Questions จะยังไม่กำหนด

| รายการ | รายละเอียด | รองรับ ID ใน spec |
|---|---|---|
| `GET /api/students?studentId={studentId}` | Input: รหัสนักศึกษา; Output: ข้อมูลค้นหาที่อนุญาตตาม `StudentLookupResult`, หรือผลไม่พบโดยไม่เปิดเผยข้อมูลส่วนบุคคล (FR-GRP-02, FR-GRP-03, FR-GRP-04, FR-GRP-10, NFR-GRP-03) | FR-GRP-02, FR-GRP-03, FR-GRP-04, FR-GRP-10 |
| `POST /api/requests/{requestId}/members` | Input: รหัสนักศึกษาที่เลือกและการยืนยัน; Output: ผลการบันทึกความสัมพันธ์กับคำขอเดียวกัน; ตรวจนักศึกษามีอยู่ ไม่อยู่กลุ่มอื่นในภาคการศึกษาเดียวกัน และไม่ซ้ำ; บันทึกแบบ all-or-nothing (FR-GRP-03 ถึง FR-GRP-09, CON-GRP-01 ถึง CON-GRP-03, NFR-GRP-04) | FR-GRP-03, FR-GRP-05, FR-GRP-06, FR-GRP-08, FR-GRP-09 |
| API สำหรับแก้ไขสมาชิก | Method/path และรายละเอียดการแก้ไขยังไม่กำหนดจนกว่าจะตอบ Q-03; ทุก request ต้องปฏิเสธผู้ที่ไม่ใช่สมาชิกของกลุ่มด้วย HTTP 403 และไม่เปลี่ยนข้อมูล (NFR-GRP-02, AC-GRP-07) | NFR-GRP-02, AC-GRP-07 |
| หน้าจอกรอกสมาชิกในขั้นตอนคำขอ | แสดงช่องตามการเลือกกลุ่ม/คู่, รับรหัสนักศึกษา, แสดงผลค้นหาตามรายการอนุญาต และให้ตรวจสอบ/ยืนยันก่อนบันทึก; ข้อความผิดพลาดเป็นภาษาไทยและระบุช่องตาม NFR-GRP-05; ทำงานใน browser ตาม IF-WEB-01 | FR-GRP-01, FR-GRP-02, FR-GRP-07, FR-GRP-10 |

ทุก API ตรวจ session ตาม IF-AUTH-01; session ที่ไม่ผ่านต้องได้ HTTP 401. การจัดการเมื่อระบบบัญชีมหาวิทยาลัยหรือ PostgreSQL ไม่ตอบสนองยังรอ Q-05.

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-GRP-01 | `test_AC_GRP_01_confirm_and_link_member_to_same_request` | เตรียมนักศึกษาที่มีอยู่และยังไม่อยู่กลุ่มอื่น ให้ยืนยัน แล้วตรวจว่าความสัมพันธ์ถูกบันทึกกับคำขอเดียวกัน |
| AC-GRP-02 | `test_AC_GRP_02_unknown_student_is_not_saved` | ค้นหารหัสที่ไม่มีในระบบ ตรวจว่าไม่บันทึกและแจ้งให้ตรวจข้อมูล |
| AC-GRP-03 | `test_AC_GRP_03_member_in_other_group_is_rejected` | เตรียมสมาชิกที่อยู่กลุ่มอื่นในภาคการศึกษาเดียวกัน ตรวจว่ามีการแจ้งเตือนและไม่มีความสัมพันธ์ใหม่ |
| AC-GRP-04 | `test_AC_GRP_04_duplicate_member_is_rejected` | ส่งรหัสนักศึกษาคนเดิมซ้ำในกลุ่มเดียวกัน ตรวจว่าให้แก้ไขและไม่บันทึกรายการซ้ำ |
| AC-GRP-05 | `test_AC_GRP_05_save_is_atomic_on_database_failure` | จำลองฐานข้อมูลล้มเหลวระหว่างบันทึก ตรวจว่าไม่มีความสัมพันธ์บางส่วนและระบบแจ้งข้อผิดพลาดพร้อมให้ลองใหม่ |
| AC-GRP-06 | `test_AC_GRP_06_lookup_shows_only_allowed_student_fields` | ค้นหาสมาชิกที่มีอยู่ ตรวจว่าผลแสดงเฉพาะรหัสนักศึกษา ชื่อ–นามสกุล และสาขา ไม่มีเบอร์โทรหรือข้อมูลติดต่อ |
| AC-GRP-07 | `test_AC_GRP_07_non_member_edit_returns_403` | ส่ง request แก้ไขด้วย session ของผู้ที่ไม่ใช่สมาชิกกลุ่ม ตรวจ HTTP 403 และข้อมูลไม่เปลี่ยน |

AC-GRP-05 ต้องจำลอง database failure ในสภาพแวดล้อมทดสอบ; การตรวจข้อความ/สถานะของแต่ละ dependency ที่ไม่ตอบยังต้องรอ Q-05. NFR-GRP-01, NFR-GRP-05 และ NFR-GRP-06 ยังไม่มี AC ตรวจโดยตรงตาม Q-07.

## 7. ลำดับงาน

1. ตรวจสัญญาข้อมูลคำขอเดิมและบริบทภาคการศึกษา ก่อนกำหนดการเชื่อม `MemberRelation` (FR-GRP-08, ASM-GRP-03, CON-GRP-01, Q-01, Q-02).
2. สร้างหน้าจอเลือกกลุ่ม/คู่และกรอกรหัสนักศึกษาบน React/browser (FR-GRP-01, FR-GRP-02, IF-WEB-01, IF-TECH-01).
3. เชื่อมการค้นหาข้อมูลนักศึกษาด้วยรหัสและจำกัดผลลัพธ์เป็นฟิลด์ที่อนุญาต (FR-GRP-02, FR-GRP-03, FR-GRP-04, FR-GRP-10, NFR-GRP-03, CON-GRP-03).
4. เพิ่มการตรวจสอบการมีอยู่ สมาชิกกลุ่ม/ภาคการศึกษา และรายการซ้ำก่อนยืนยัน (FR-GRP-03 ถึง FR-GRP-07, CON-GRP-01 ถึง CON-GRP-03).
5. แสดงข้อมูลสมาชิกให้ตรวจสอบและยืนยันก่อนบันทึก พร้อมข้อความผิดพลาดภาษาไทยที่ระบุช่อง (FR-GRP-07, FR-GRP-10, NFR-GRP-05).
6. บันทึกความสัมพันธ์ไปยังคำขอเดียวกันใน PostgreSQL แบบธุรกรรมเดียว และจัดการกรณีบันทึกล้มเหลว (FR-GRP-08, FR-GRP-09, NFR-GRP-04, IF-TECH-01, Q-05).
7. บังคับใช้ session และสิทธิ์แก้ไขกลุ่ม รวมถึง timeout ตามข้อกำหนด (IF-AUTH-01, NFR-GRP-01, NFR-GRP-02, AC-GRP-07, Q-03, Q-05).
8. ปรับหน้าจอให้รองรับมือถือและตรวจ AC-GRP-01 ถึง AC-GRP-07; รอการยืนยันค่าหน้าจอและการตามรอย AC ที่ยังขาด (NFR-GRP-06, Q-06, Q-07).

## 8. สิ่งที่ยังไม่ทำ

- Q-01 (เดิม OQ-GRP-02) จำนวนสมาชิกต่อกลุ่มต่ำสุดและสูงสุดเท่าไร, "คู่" หมายถึง 2 คนเสมอหรือไม่ และนับผู้กรอกเป็นสมาชิกหรือไม่; ต้องรอคำตอบจากคณะหรือทีม — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-02 (เดิม OQ-GRP-06) สมาชิกทุกคนต้องส่งผลการศึกษาของตนเองตาม UC-01 ด้วยหรือไม่ หรือใช้คำขอร่วมกัน 1 ชุด; ต้องรอคำตอบจากทีมและผู้รับผิดชอบ UC-01 — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-03 (เดิม OQ-GRP-05) ใครเป็นผู้แก้ไขหรือถอนสมาชิกออกจากกลุ่มได้ และทำได้จนถึงเมื่อใด; ต้องรอคำตอบจากทีมและเจ้าหน้าที่ผู้ดูแลคำขอ — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-04 (เดิม OQ-GRP-04) สมาชิกที่ถูกระบุต้องยืนยันการเข้ากลุ่มเองหรือไม่ และถ้าต้องยืนยัน ใช้ช่องทางใด (UC-17 หรืออื่น); ต้องรอคำตอบจากทีมและผู้รับผิดชอบ UC-17 — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-05 (IF-AUTH-01, FR-GRP-09, AC-GRP-05) เมื่อระบบบัญชีมหาวิทยาลัยหรือ PostgreSQL ไม่ตอบสนอง ต้องตอบสถานะ/ข้อความและจัดการการลองใหม่อย่างไรในแต่ละกรณี; ต้องรอคำตอบจากทีมและผู้ดูแลระบบที่เกี่ยวข้อง — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-06 (ASM-GRP-01, NFR-GRP-06) ทีมยืนยันเกณฑ์หน้าจอ 360 px หรือไม่; ต้องรอคำตอบจากทีม — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-07 (FR-GRP-01, FR-GRP-02, FR-GRP-07, NFR-GRP-01, NFR-GRP-05, NFR-GRP-06) AC ที่มีอยู่ยังไม่ระบุการตรวจช่องกรอก/หน้าจอยืนยัน, timeout, ข้อความภาษาไทยและช่องที่ต้องแก้ หรือการใช้งานบนมือถือโดยตรง; ทีมจะปรับการตามรอยให้ตรงกับ AC ที่มีอยู่หรือไม่ โดยไม่เพิ่ม ID ใหม่; ต้องรอคำตอบจากทีม — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ

## หมายเหตุสำหรับการตรวจ

- React และ PostgreSQL มาจาก IF-TECH-01; Vite ระบุเป็นตัวเลือกทีมที่ไม่ได้มาจาก spec; backend ยังเว้นไว้ตามคำตอบทีม
- ไม่มีการกำหนดจำนวนสมาชิก, รูปแบบคำขอร่วมกัน, การยืนยันสมาชิก, สิทธิ์เพิ่ม/ถอนสมาชิก, retry policy หรือการขยาย Acceptance Criteria แทนทีม (Q-01 ถึง Q-07)
