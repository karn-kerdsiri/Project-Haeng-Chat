# Task Breakdown: SPEC-EDU-001

## วัตถุประสงค์
เอกสารนี้เป็นแผนงานตาม spec ของฟีเจอร์ "กรอกข้อมูลผลการศึกษา" และใช้เป็นรายการงานที่ต้องปฏิบัติตามข้อกำหนดใน `spec.md` โดยตรง ไม่เพิ่มความต้องการใหม่

## ข้อมูลอ้างอิงจาก spec
- Spec ID: SPEC-EDU-001
- Use case: UC-01 กรอกข้อมูลผลการศึกษา
- ข้อกำหนดสำคัญ: FR-EDU-01 ถึง FR-EDU-14, DR-EDU-01 ถึง DR-EDU-07, IF-AUTH-01, IF-FORM-01, IF-FILE-01, IF-FILE-02, IF-MAIL-01, DOM-PDPA-01, DOM-PDPA-02, CON-DATA-01
- Acceptance Criteria: AC-EDU-01 ถึง AC-EDU-14

## ลำดับงาน

### 1. เตรียมการเปิดฟอร์มและตรวจสิทธิ์
- ตรวจสอบ session ที่ยืนยันตัวตนก่อนเข้าใช้งานทุก request ตาม IF-AUTH-01
- อ่านสถานะรอบแบบฟอร์ม (open/closed) จากข้อมูลตั้งค่ารอบก่อนแสดงฟอร์มและก่อนบันทึกทุกครั้ง ตาม IF-FORM-01
- หากรอบปิด ให้แสดงฟอร์มแบบอ่านอย่างเดียวและปฏิเสธการบันทึกด้วย HTTP 409 ตาม FR-EDU-02
- อ้างอิง: IF-AUTH-01, IF-FORM-01, FR-EDU-02, AC-EDU-07

### 2. แสดงฟอร์มและฟิลด์บังคับ
- แสดงแบบฟอร์มผลการศึกษาตาม DR-EDU-01 พร้อมทำเครื่องหมาย * ทุกฟิลด์บังคับ รวมช่องแนบ Transcript ตาม FR-EDU-01
- ถ้ามีข้อมูลเดิมของรอบนั้นอยู่แล้ว ให้แสดงข้อมูลเดิมในฟอร์มเพื่อแก้ไขตาม FR-EDU-12 และ CON-DATA-01
- อ้างอิง: FR-EDU-01, FR-EDU-12, DR-EDU-01, CON-DATA-01, AC-EDU-12, AC-EDU-08

### 3. ตรวจความครบถ้วนและรูปแบบข้อมูลก่อนบันทึก
- ตรวจว่าฟิลด์บังคับครบตาม DR-EDU-01
- ตรวจรูปแบบข้อมูลตาม DR-EDU-02 ถึง DR-EDU-05
  - GPAX 0.00-4.00, ทศนิยมไม่เกิน 2 ตำแหน่ง
  - หน่วยกิตสะสมเป็นจำนวนเต็ม 0-999
  - ปีการศึกษาเป็นเลข 4 หลัก และไม่มากกว่าปีปัจจุบัน
  - ภาคเรียนเป็น 1, 2 หรือ 3
- ถ้าข้อมูลไม่ครบหรือรูปแบบผิด ให้ไม่บันทึกและแจ้งช่องที่ผิดพร้อมรูปแบบที่ถูกต้องตาม FR-EDU-05 และ FR-EDU-06
- อ้างอิง: DR-EDU-02 ถึง DR-EDU-05, FR-EDU-05, FR-EDU-06, AC-EDU-02, AC-EDU-03, AC-EDU-13

### 4. ตรวจไฟล์แนบ Transcript
- รับไฟล์แนบตาม DR-EDU-06 และปฏิเสธไฟล์ที่ไม่ตรงเงื่อนไขโดยไม่ล้างข้อมูลที่กรอกไว้ ตาม FR-EDU-03
- ตรวจชนิดไฟล์: .pdf .jpg .png เท่านั้น
- ตรวจขนาดไฟล์: ไม่เกิน 5 MB ต่อไฟล์ และไม่เกิน 5 ไฟล์ต่อการส่ง 1 ครั้ง
- บังคับว่าต้องมี Transcript อย่างน้อย 1 ไฟล์ หากไม่มี ให้ปฏิเสธและแจ้งว่าต้องแนบ Transcript ก่อนส่ง ตาม FR-EDU-13 และ DR-EDU-07
- ถ้าไฟล์ผิดเงื่อนไข ให้แจ้งเหตุผลและให้อัปโหลดใหม่เฉพาะไฟล์นั้น ตาม FR-EDU-07
- อ้างอิง: DR-EDU-06, DR-EDU-07, FR-EDU-03, FR-EDU-07, FR-EDU-13, AC-EDU-04, AC-EDU-13, AC-EDU-14

### 5. หน้าสรุปข้อมูลก่อนยืนยันส่ง
- แสดงหน้าสรุปข้อมูลและรายชื่อไฟล์แนบให้ตรวจสอบก่อนยืนยันส่ง ตาม FR-EDU-04
- ตรวจให้ตรงกับข้อมูลที่กรอกและชื่อไฟล์แนบที่เลือกในรูปแบบสรุปตาม AC-EDU-12
- อ้างอิง: FR-EDU-04, AC-EDU-12

### 6. บันทึกข้อมูลเข้าสู่ฐานข้อมูลและจัดการสถานะ
- เมื่อผ่านการตรวจทั้งหมด ให้บันทึกข้อมูลและตั้งสถานะเป็น "รอตรวจสอบคุณสมบัติ" ตาม FR-EDU-08
- การบันทึกต้องเป็นการ update หรือ insert ตามข้อมูลเดิมของรอบนั้น ตาม CON-DATA-01 และ FR-EDU-12
- กรณีข้อมูล DB ไม่พร้อมใช้งาน ให้ rollback ทั้งชุด และแสดงรหัสข้อผิดพลาดพร้อมปุ่ม "ลองใหม่" ตาม FR-EDU-11
- กรณีอัปโหลดไฟล์ลง Supabase Storage สำเร็จแต่บันทึก DB ไม่สำเร็จ ต้องลบไฟล์ที่เพิ่งอัปโหลดออกตาม FR-EDU-14
- อ้างอิง: FR-EDU-08, FR-EDU-11, FR-EDU-12, FR-EDU-14, CON-DATA-01, AC-EDU-01, AC-EDU-05, AC-EDU-08

### 7. แจ้งเตือนในระบบและส่งอีเมลแบบ asynchronous
- หลังบันทึกสำเร็จ ต้องสร้างการแจ้งเตือนในระบบ และส่งคำขอส่งอีเมลเข้าคิวภายในธุรกรรมเดียวกัน ตาม FR-EDU-09
- การบันทึกต้องไม่รอผลการส่งอีเมล ตาม IF-MAIL-01
- หากส่งอีเมลไม่สำเร็จ ให้คงข้อมูลที่บันทึกไว้ และนำอีเมลเข้าคิวส่งซ้ำ ตาม FR-EDU-10 และ NFR-REL-01
- อ้างอิง: FR-EDU-09, FR-EDU-10, IF-MAIL-01, NFR-REL-01, AC-EDU-06

### 8. จัดการ audit log และความปลอดภัย
- บันทึก audit log ทุกครั้งที่สร้าง แก้ไข หรือเปิดดูข้อมูลผลการศึกษา ตาม DOM-PDPA-01
- audit log ต้องมี ผู้กระทำ เวลา รหัสนักศึกษา และชนิดการกระทำ และเก็บไม่น้อยกว่า 1 ปี ตาม DOM-PDPA-02
- ป้องกันไม่ให้นักศึกษาคนอื่นเรียกดูหรือแก้ไขข้อมูลของคนอื่นได้ ต้องตอบ HTTP 403 ตาม NFR-SEC-02
- ป้องกันการเรียก storage path ของ Transcript โดยตรงโดยไม่มี signed URL ต้องได้ HTTP 401 หรือ 403 ตาม NFR-SEC-03
- อ้างอิง: DOM-PDPA-01, DOM-PDPA-02, NFR-SEC-02, NFR-SEC-03, AC-EDU-09, AC-EDU-10, AC-EDU-14

### 9. จัดเก็บไฟล์ใน Supabase Storage ตามข้อจำกัด
- ไฟล์แนบเก็บใน Supabase Storage และตารางข้อมูลผลการศึกษาอ้างอิงด้วย bucket + storage path เท่านั้น ตาม IF-FILE-01
- bucket ของ Transcript ต้องเป็น private และเข้าถึงผ่าน signed URL อายุไม่เกิน 15 นาที ตาม IF-FILE-02
- ตรวจให้ตรงกับเงื่อนไขการเข้าถึงแบบ direct path ตาม AC-EDU-14
- อ้างอิง: IF-FILE-01, IF-FILE-02, NFR-SEC-03, AC-EDU-14

### 10. ทดสอบและตรวจสอบความครอบคลุม
- ตรวจสอบให้ครอบคลุม AC-EDU-01 ถึง AC-EDU-14
- ตรวจวัดประสิทธิภาพตาม NFR-PERF-01 และ NFR-PERF-02
- ตรวจสอบความถูกต้องของการยืนยันสิทธิ์และ permission
- อ้างอิง: NFR-PERF-01, NFR-PERF-02, NFR-SEC-01, NFR-SEC-02, NFR-SEC-03, NFR-USE-01

## ลำดับความสำคัญของงาน
1. ตรวจสิทธิ์และสถานะรอบฟอร์ม
2. ตรวจข้อมูลและไฟล์แนบ
3. แสดงหน้าสรุปและยืนยันก่อนส่ง
4. บันทึกข้อมูลและสถานะ
5. แจ้งเตือนในระบบและส่งอีเมลแบบ asynchronous
6. จัดการ rollback, audit log และความปลอดภัย
7. ทดสอบตาม Acceptance Criteria
