# Feature: จัดทำตารางเวลาประจำเทอม (Manage Term Schedule)
Spec ID: SPEC-SCH-015 | Source: Use Case Specification UC-15 จัดทำตารางเวลาประจำเทอม + รายการความต้องการของทีม ข้อ 6 | Use case: UC-15
Owner: ทีม B | Status: Draft v1 | Updated: 2569-10-21

## Goal
เจ้าหน้าที่กำหนดช่วงเวลาการดำเนินงานของแต่ละภาคการศึกษาได้
และระบบนำตารางเวลานั้นไปควบคุมการเปิด/ปิดแบบฟอร์มยื่นคำร้องโดยอัตโนมัติ

## Scope
### In scope
- IN-SCH-01 เลือกภาคการศึกษาที่จะจัดทำตารางเวลา                       <- UC-15 ขั้น 1
- IN-SCH-02 กำหนดกิจกรรมและช่วงเวลาของแต่ละกิจกรรม                   <- UC-15 ขั้น 2
- IN-SCH-03 ตรวจสอบความถูกต้องของช่วงเวลา รวมถึงกรณีซ้อนทับ            <- UC-15 ขั้น 3, alt 1-2
- IN-SCH-04 บันทึกและเผยแพร่กำหนดการตามสิทธิ์                        <- UC-15 ขั้น 4-5
- IN-SCH-05 ให้ระบบใช้ตารางเวลาควบคุมการเปิด/ปิดแบบฟอร์มอัตโนมัติ        <- ข้อ 6, UC-15 Goal
### Out of scope
- OUT-SCH-01 การแสดงตารางเวลาให้นักศึกษาดู - เป็นของ UC-05
- OUT-SCH-02 การจัดการข้อมูลรายวิชา อาจารย์ และเงื่อนไขการผ่าน - เป็นของ UC-12
- OUT-SCH-03 การแจ้งเตือนเมื่อกำหนดการเปลี่ยน - เป็นของ UC-17 (ดู OQ-SCH-05)
- OUT-SCH-04 การตรวจสอบและยืนยันคำร้อง - เป็นของ UC-13
- OUT-SCH-05 การนำเข้าปฏิทินการศึกษาจากระบบภายนอก - UC-15 ไม่ระบุ

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และตารางเวลาเก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- IF-AUDIT-01 การสร้างและแก้ไขตารางเวลาต้องบันทึกประวัติพร้อมผู้ดำเนินการและเวลา   <- ข้อ 8
- IF-FORM-01 ระบบต้องใช้ตารางเวลาที่บันทึกไว้เปิดและปิดแบบฟอร์มยื่นคำร้องโดยอัตโนมัติ   <- ข้อ 6
- CON-SCH-01 เฉพาะผู้ใช้บทบาทเจ้าหน้าที่ที่มีสิทธิ์จัดการตารางเวลาจึงจะสร้างหรือแก้ไขได้   <- UC-15 Precondition
- CON-SCH-02 ช่วงเวลาของกิจกรรมประเภทเดียวกันในภาคการศึกษาเดียวกันต้องไม่ซ้อนทับกัน   <- UC-15 alt 1

## Data Rules
- DR-SCH-01 ฟิลด์บังคับต่อ 1 รายการกิจกรรม: ภาคการศึกษา ชื่อกิจกรรม วันเวลาเริ่ม และวันเวลาสิ้นสุด   <- UC-15 ขั้น 1-2
- DR-SCH-02 วันเวลาสิ้นสุดต้องไม่มาก่อนวันเวลาเริ่ม   <- UC-15 alt 2
- DR-SCH-03 กิจกรรมที่ระบบใช้ควบคุมแบบฟอร์มต้องระบุได้ว่าเป็นช่วงเปิดรับข้อมูลหรือช่วงตรวจสอบ   <- UC-15 Description + ข้อ 6 (รายการประเภทกิจกรรมรอยืนยัน ดู OQ-SCH-01)
- DR-SCH-04 ประวัติที่บันทึกต่อ 1 การกระทำ: ผู้ดำเนินการ เวลา และค่าก่อน/หลัง   <- ข้อ 8

## Requirements
- FR-SCH-01 ระบบต้องให้เจ้าหน้าที่เลือกภาคการศึกษาที่จะจัดทำตารางเวลา   <- UC-15 ขั้น 1
- FR-SCH-02 ระบบต้องให้กำหนดกิจกรรมและช่วงเวลาตาม DR-SCH-01 และ DR-SCH-03   <- UC-15 ขั้น 2
- FR-SCH-03 ระบบต้องตรวจความถูกต้องของช่วงเวลาตาม DR-SCH-02 ก่อนบันทึก และแจ้งช่องที่ต้องแก้ไข   <- UC-15 ขั้น 3, alt 2
- FR-SCH-04 เมื่อพบช่วงเวลาซ้อนทับตาม CON-SCH-02 ระบบต้องแจ้งเตือนและไม่บันทึกทับโดยอัตโนมัติ   <- UC-15 alt 1
- FR-SCH-05 เมื่อผ่านการตรวจสอบ ระบบต้องบันทึกตารางเวลาและเผยแพร่กำหนดการตามสิทธิ์   <- UC-15 ขั้น 4-5
- FR-SCH-06 ระบบต้องเปิดแบบฟอร์มยื่นคำร้องเมื่อถึงเวลาเริ่มของช่วงเปิดรับข้อมูล และปิดเมื่อพ้นเวลาสิ้นสุด โดยอัตโนมัติ   <- ข้อ 6, IF-FORM-01
- FR-SCH-07 เมื่อเจ้าหน้าที่แก้ไขช่วงเวลา ระบบต้องนำค่าที่แก้ไขไปใช้ควบคุมแบบฟอร์มทันทีหลังบันทึกสำเร็จ   <- UC-15 Postcondition + ข้อ 6
- FR-SCH-08 หากบันทึกไม่สำเร็จ ระบบต้องแจ้งข้อผิดพลาด และไม่บันทึกตารางเวลาบางส่วน   <- UC-15 Exception
- FR-SCH-09 ระบบต้องบันทึกประวัติการสร้างและแก้ไขตารางเวลาตาม DR-SCH-04   <- ข้อ 8
- FR-SCH-10 ระบบต้องปฏิเสธการสร้างหรือแก้ไขตารางเวลาโดยผู้ใช้ที่ไม่มีสิทธิ์ด้วย HTTP 403   <- CON-SCH-01
- FR-SCH-11 ตารางเวลาที่เผยแพร่ต้องเป็นชุดเดียวกับที่ UC-05 แสดงให้นักศึกษาเห็น   <- UC-15 ขั้น 5

## Quality Requirements
- NFR-SCH-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-SCH-02 [Security] เฉพาะบทบาทเจ้าหน้าที่ที่มีสิทธิ์จัดการตารางเวลาจึงจะเรียก API สร้าง/แก้ไขได้   <- CON-SCH-01
- NFR-SCH-03 [Data Integrity] การเปิด/ปิดแบบฟอร์มอัตโนมัติต้องตรงตามช่วงเวลาที่บันทึก โดยคลาดเคลื่อนไม่เกิน 1 นาที   <- UC-15 NFR (Data Integrity) + ค่าที่เสนอไว้ ดู ASM-SCH-01
- NFR-SCH-04 [Usability] ข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย และระบุช่องที่ต้องแก้ไข   <- ข้อ 10
- NFR-SCH-05 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-SCH-01)
- NFR-SCH-06 [Auditability] ประวัติการเปลี่ยนแปลงตารางเวลาต้องเก็บไว้ไม่น้อยกว่า 1 ปี   <- ข้อ 8 (ระยะเวลา 1 ปีเป็นค่าที่เสนอไว้ ดู ASM-SCH-01)

## Acceptance Criteria
- [ ] AC-SCH-01 (FR-SCH-05, DR-SCH-01)
      Given เจ้าหน้าที่มีสิทธิ์จัดการตารางเวลา
      When  กำหนดช่วงเวลาครบถ้วนถูกต้องและบันทึก
      Then  ระบบบันทึกตารางเวลา และนำไปใช้งานได้
- [ ] AC-SCH-02 (FR-SCH-04, CON-SCH-02)
      Given มีช่วงเปิดรับข้อมูลของภาคการศึกษานั้นอยู่แล้ว
      When  เพิ่มช่วงเปิดรับข้อมูลที่ซ้อนทับกับช่วงเดิม
      Then  ระบบแจ้งเตือนช่วงเวลาซ้อนทับ และไม่บันทึก
- [ ] AC-SCH-03 (FR-SCH-03, DR-SCH-02, NFR-SCH-04)
      Given กำหนดวันเวลาสิ้นสุดก่อนวันเวลาเริ่ม
      When  กดบันทึก
      Then  ระบบไม่บันทึก และแสดงข้อความภาษาไทยที่ช่องวันเวลาที่ผิด
- [ ] AC-SCH-04 (FR-SCH-06, IF-FORM-01, NFR-SCH-03)
      Given ตารางเวลาระบุช่วงเปิดรับข้อมูลสิ้นสุดเวลา T
      When  เวลาปัจจุบันผ่าน T ไปแล้ว
      Then  แบบฟอร์มยื่นคำร้องถูกปิดอัตโนมัติ และการส่งข้อมูลถูกปฏิเสธ
- [ ] AC-SCH-05 (FR-SCH-07)
      Given เจ้าหน้าที่ขยายวันสิ้นสุดของช่วงเปิดรับข้อมูล
      When  บันทึกสำเร็จ
      Then  แบบฟอร์มเปิดรับข้อมูลตามช่วงเวลาใหม่ทันที
- [ ] AC-SCH-06 (FR-SCH-10, NFR-SCH-02)
      Given ผู้ใช้ที่ไม่มีสิทธิ์จัดการตารางเวลา
      When  เรียก API สร้างหรือแก้ไขตารางเวลา
      Then  ระบบตอบ HTTP 403 และตารางเวลาไม่เปลี่ยนแปลง
- [ ] AC-SCH-07 (FR-SCH-08)
      Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึก
      When  กดบันทึก
      Then  ระบบแจ้งข้อผิดพลาด และไม่มีรายการกิจกรรมถูกสร้างบางส่วน
- [ ] AC-SCH-08 (FR-SCH-11)
      Given ตารางเวลาถูกบันทึกและเผยแพร่แล้ว
      When  นักศึกษาเปิดหน้าตารางเวลาตาม UC-05
      Then  ข้อมูลที่นักศึกษาเห็นตรงกับที่เจ้าหน้าที่บันทึก
- [ ] AC-SCH-09 (FR-SCH-09, NFR-SCH-06)
      Given เจ้าหน้าที่แก้ไขช่วงเวลา 1 ครั้ง
      When  บันทึกสำเร็จ
      Then  มีประวัติ 1 รายการที่ระบุผู้ดำเนินการ เวลา และค่าก่อน/หลัง

## Assumptions & Open Questions
- ASM-SCH-01 UC-15 ระบุ NFR เป็นหมวด (Usability, Data Integrity) ค่าตัวเลขใน NFR-SCH-03, NFR-SCH-05 และ NFR-SCH-06 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-SCH-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-SCH-03 "แบบฟอร์มยื่นคำร้อง" ในข้อ 6 คือแบบฟอร์มส่งผลการศึกษาตาม UC-01 และการส่งผลเพิ่มเติมตาม UC-02
- OQ-SCH-01 กิจกรรมในตารางเวลามีประเภทอะไรบ้าง และประเภทใดที่ใช้ควบคุมการเปิด/ปิดแบบฟอร์ม (UC-15 ยกตัวอย่างเพียงช่วงเปิดรับข้อมูลและช่วงตรวจสอบ)
- OQ-SCH-02 ช่วงส่งผลการเรียนเพิ่มเติมตาม UC-02 เป็นกิจกรรมแยกในตารางเวลาหรือใช้ช่วงเดียวกับการส่งผลการศึกษา
- OQ-SCH-03 "เผยแพร่กำหนดการตามสิทธิ์" ใน UC-15 ขั้น 5 หมายถึงบทบาทใดเห็นอะไร และมีสถานะร่างก่อนเผยแพร่หรือไม่
- OQ-SCH-04 แก้ไขตารางเวลาของภาคการศึกษาที่กำลังดำเนินอยู่ได้หรือไม่ และถ้าย่อระยะเวลาให้สั้นลงจนปิดฟอร์มทันที จะจัดการคำร้องที่ค้างอยู่อย่างไร
- OQ-SCH-05 เมื่อตารางเวลาเปลี่ยน ต้องแจ้งเตือนนักศึกษาผ่าน UC-17 หรือไม่ UC-15 ไม่ระบุ
- OQ-SCH-06 ใช้เขตเวลาใดและนับเวลาสิ้นสุดแบบรวมหรือไม่รวมวันสุดท้าย
