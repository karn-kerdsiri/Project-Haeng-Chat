# Plan: จัดทำตารางเวลาประจำเทอม

## 1. สรุปแนวทาง
ฟีเจอร์นี้ให้เจ้าหน้าที่จัดทำตารางเวลาประจำภาคการศึกษาและใช้ตารางเวลาดังกล่าวควบคุมการเปิด/ปิดแบบฟอร์มยื่นคำร้องโดยอัตโนมัติ
ระบบประกอบด้วยส่วนจัดการตารางเวลา การตรวจความถูกต้องของช่วงเวลา การบันทึกและเผยแพร่ข้อมูล และการบันทึกประวัติต่าง ๆ ตามบทบาทและสิทธิ์
ผู้ใช้หลักคือเจ้าหน้าที่ที่มีสิทธิ์จัดการตารางเวลา โดยนักศึกษาได้รับผลลัพธ์ผ่านแบบฟอร์มที่เปิด/ปิดตามช่วงเวลาในตาราง
แนวทางการสร้างจะแยกเป็น 4 ส่วนหลักคือ: หน้าจอจัดการตารางเวลา, API บันทึกและตรวจสอบข้อมูล, Scheduler ควบคุมการเปิด/ปิดฟอร์ม, และประวัติการเปลี่ยนแปลงตารางเวลา

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าจอจัดการตารางเวลา | IF-TECH-01 | ระบุชัดว่า front-end พัฒนาด้วย React |
| PostgreSQL สำหรับเก็บตารางเวลาและประวัติ | IF-TECH-01 | ระบุชัดว่าเก็บข้อมูลใน PostgreSQL |
| Python FastAPI สำหรับ API ควบคุมตารางเวลา | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้ตามค่าเริ่มต้นของรายวิชาสำหรับ backend เมื่อ spec ไม่ระบุชัดเจน |
| Session-based auth และตรวจสอบบทบาทก่อนเข้าถึงฟังก์ชัน | IF-AUTH-01, CON-SCH-01, NFR-SCH-02 | ทุก request ต้องมี session ที่ยืนยันตัวตนและมีสิทธิ์เจ้าหน้าที่จัดการตารางเวลา |
| Scheduler / background job สำหรับเปิด/ปิดฟอร์มตามช่วงเวลา | IF-FORM-01, FR-SCH-06, FR-SCH-07 | ตรวจเวลาปัจจุบันและปรับสถานะฟอร์มให้สอดคล้องกับตารางเวลา |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ FR |
|---|---|---|
| AcademicTerm | id, semester_code, year, status | FR-SCH-01, FR-SCH-05, FR-SCH-11 |
| TermSchedule | id, term_id, published_at, created_by, updated_by, version | FR-SCH-05, FR-SCH-09, FR-SCH-11 |
| ScheduleActivity | id, term_schedule_id, activity_name, activity_type, start_at, end_at, form_control_type | FR-SCH-02, FR-SCH-03, FR-SCH-04, FR-SCH-06, FR-SCH-07, CON-SCH-02 |
| ScheduleAuditLog | id, term_schedule_id, action, actor_user_id, action_at, before_json, after_json | FR-SCH-09, DR-SCH-04, IF-AUDIT-01 |
| FormControlState | id, form_type, term_id, is_open, opened_at, closed_at, source_schedule_version | FR-SCH-06, FR-SCH-07, IF-FORM-01 |

ข้อควรระวัง:
- ไม่เพิ่มฟิลด์ที่เก็บข้อมูลส่วนบุคคลหรือข้อมูลที่ไม่อยู่ในขอบเขตของ UC-15 เช่น ข้อมูลรายวิชา/อาจารย์/เงื่อนไขการผ่าน ที่ระบุว่าเป็นของ UC-12
- ไม่บันทึกข้อมูลที่ขัดกับ out of scope ของฟีเจอร์นี้ เช่น การใช้ตารางเวลาเพื่อแจ้งเตือนนักศึกษาผ่าน UC-17

## 4. API / หน้าจอ

| รายการ | ชื่อ/ method / path | รองรับ FR | รายละเอียดหลัก |
|---|---|---|---|
| หน้าจอเลือกภาคการศึกษา | GET /terms | FR-SCH-01 | แสดงภาคการศึกษาที่พร้อมจัดทำตารางเวลา |
| หน้าเพิ่ม/แก้ไขตารางเวลา | GET /term-schedules/new, GET /term-schedules/:id | FR-SCH-02, FR-SCH-03, FR-SCH-04, FR-SCH-05 | ให้เจ้าหน้าที่ระบุกิจกรรม ช่วงเวลา และตรวจสอบการซ้อนทับ |
| API สร้างตารางเวลา | POST /api/term-schedules | FR-SCH-05, FR-SCH-08, FR-SCH-09, FR-SCH-10 | ตรวจสิทธิ์ ตรวจความถูกต้อง บันทึกพร้อมประวัติ |
| API แก้ไขตารางเวลา | PUT /api/term-schedules/:id | FR-SCH-07, FR-SCH-08, FR-SCH-09, FR-SCH-10 | อัปเดตช่วงเวลาและอัปเดตการควบคุมฟอร์มทันทีหลังบันทึกสำเร็จ |
| API ตรวจความถูกต้อง | POST /api/term-schedules/validate | FR-SCH-03, FR-SCH-04 | คืนข้อความแสดงช่องที่ผิดและการซ้อนทับ |
| API เปิด/ปิดฟอร์มตามเวลา | background scheduler /internal/form-control | FR-SCH-06, FR-SCH-07 | ตรวจเวลาปัจจุบันและสลับสถานะฟอร์มตามช่วงเวลา |
| API รายการเผยแพร่ | GET /api/term-schedules/published | FR-SCH-05, FR-SCH-11 | ส่งชุดตารางเวลาที่เผยแพร่ให้ UC-05 และระบบที่เกี่ยวข้องใช้ |

## 7. ลำดับงาน

1. วิเคราะห์และกำหนดแบบจำลองข้อมูลของตารางเวลาและประเภทกิจกรรมที่ใช้ควบคุมฟอร์ม (FR-SCH-01, FR-SCH-02, DR-SCH-01, DR-SCH-03)
2. สร้าง validation rules สำหรับวันที่เวลา การซ้อนทับ และการตรวจสิทธิ์ (FR-SCH-03, FR-SCH-04, CON-SCH-01, CON-SCH-02)
3. พัฒนา API create/update และบันทึกประวัติการเปลี่ยนแปลง (FR-SCH-05, FR-SCH-08, FR-SCH-09, FR-SCH-10)
4. พัฒนา Scheduler / background job เพื่อเปิด/ปิดฟอร์มตามช่วงเวลาและอัปเดตทันทีหลังปรับตารางเวลา (FR-SCH-06, FR-SCH-07, IF-FORM-01)
5. พัฒนาหน้าจอจัดการตารางเวลาและเชื่อมต่อกับ API (FR-SCH-01, FR-SCH-02, FR-SCH-03, FR-SCH-04, FR-SCH-05)
6. ทดสอบทั้งหมดตาม AC-SCH-01 ถึง AC-SCH-09 พร้อมปรับให้สอดคล้องกับข้อกำหนดที่ยังค้างอยู่

## 8. สิ่งที่ยังไม่ทำ

- OQ-SCH-01: กิจกรรมในตารางเวลามีประเภทอะไรบ้าง และประเภทใดที่ใช้ควบคุมการเปิด/ปิดแบบฟอร์ม
- OQ-SCH-02: ช่วงส่งผลการเรียนเพิ่มเติมตาม UC-02 เป็นกิจกรรมแยกในตารางเวลาหรือใช้ช่วงเดียวกับการส่งผลการศึกษา
- OQ-SCH-03: “เผยแพร่กำหนดการตามสิทธิ์” หมายถึงบทบาทใดสามารถเห็นกำหนดการ และมีสถานะร่างก่อนเผยแพร่หรือไม่
- OQ-SCH-04: การแก้ไขตารางเวลาของภาคการศึกษาที่กำลังดำเนินอยู่ และการจัดการคำร้องที่ค้างเมื่อฟอร์มปิดทันที
- OQ-SCH-05: เมื่อมีการเปลี่ยนตารางเวลา ต้องแจ้งเตือนนักศึกษาผ่าน UC-17 หรือไม่
- OQ-SCH-06: ใช้เขตเวลาใดในการคำนวณช่วงเวลา และเวลาสิ้นสุดนับรวมวันสุดท้ายหรือไม่
