# Feature: ส่งผลการเรียนเพิ่มเติม (Submit Additional Grades)
Spec ID: SPEC-ADD-002 | Source: Use Case Specification UC-02 ส่งผลการเรียนเพิ่มเติม (กรณีเกรดยังออกไม่ครบ) + รายการความต้องการของทีม ข้อ 3 | Use case: UC-02
Owner: ทีม B | Status: Draft v2 | Updated: 2569-11-13

## Goal
นักศึกษาที่เคยส่งผลการศึกษาแล้ว ส่งรายวิชาที่ประกาศเกรดเพิ่มเติมภายหลัง และแก้เกรดของรายวิชาที่ส่งไปแล้วเมื่อผลประกาศออกมา เข้าคำร้องเดิมได้
โดยไม่ต้องเริ่มกระบวนการใหม่ ระบบรวมข้อมูลกับชุดเดิมและปรับสถานะการตรวจสอบให้นักศึกษาเห็น

## Scope
### In scope
- IN-ADD-01 แสดงข้อมูลผลการศึกษาที่นักศึกษาคนนั้นเคยส่ง                        <- UC-02 ขั้น 1
- IN-ADD-02 เลือกรายวิชาที่มีผลการศึกษาเพิ่มเติมจากข้อมูลรายวิชาของระบบ พร้อมปีการศึกษา ภาคเรียน และเกรด   <- UC-02 ขั้น 2-3 + ASM-ADD-05, ASM-ADD-07
- IN-ADD-03 ตรวจสอบข้อมูลที่กรอก รวมถึงกรณีรายวิชาซ้ำ                         <- UC-02 ขั้น 4, alt 2-3
- IN-ADD-04 ยืนยันการส่งและบันทึกข้อมูลรวมเข้ากับคำร้องเดิม                     <- UC-02 ขั้น 5-6
- IN-ADD-05 ปรับสถานะการตรวจสอบของคำร้องและแสดงสถานะให้นักศึกษาเห็น          <- UC-02 ขั้น 6, Postcondition + ข้อ 7
- IN-ADD-06 แก้เกรดของรายวิชาที่ส่งไปแล้ว เมื่อผลการศึกษาประกาศออกมาภายหลัง      <- ASM-ADD-06
### Out of scope
- OUT-ADD-01 การส่งผลการศึกษาครั้งแรก - เป็นของ UC-01 และเป็น precondition ของ UC-02
- OUT-ADD-02 การเข้าสู่ระบบและยืนยันตัวตน - ถือว่าสำเร็จแล้ว (UC-02 Precondition, ข้อ 12)
- OUT-ADD-03 การกำหนดช่วงเวลาที่เปิดให้ส่งผลเพิ่มเติม - เป็นของ UC-15 และ ข้อ 6 spec นี้เพียงอ่านสถานะช่วงเวลา
- OUT-ADD-04 การตรวจสอบและอนุมัติโดยอาจารย์ที่ปรึกษาหรือเจ้าหน้าที่ - เป็นของ UC-09 และ UC-13
- OUT-ADD-05 การคำนวณผลการตรวจสอบคุณสมบัติ - เป็นของ UC-16
- OUT-ADD-06 การลบรายวิชาที่ส่งไปแล้ว - UC-02 ไม่ระบุขั้นตอนนี้ (การแก้เกรดย้ายเข้า scope แล้วตาม IN-ADD-06 และ ASM-ADD-06)

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลเก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- IF-SCHED-01 ระบบต้องอ่านช่วงเวลาที่เปิดรับข้อมูลจากตารางเวลาประจำเทอม ก่อนเปิดฟอร์มและก่อนบันทึกทุกครั้ง โดยใช้ช่วงเวลาชุดเดียวกับการส่งผลการศึกษาครั้งแรก (UC-01) ตาม ASM-ADD-08   <- ข้อ 6
- DOM-GRADE-01 เกรดที่ใช้ตรวจสอบต้องเป็นค่าตามระบบเกรดของมหาวิทยาลัย และรายวิชาที่ได้ผลไม่สมบูรณ์ต้องไม่ถูกนับว่าผ่าน   <- ข้อ 16
- DOM-COURSE-01 รายวิชาที่เลือกได้ต้องมาจากข้อมูลรายวิชาที่เจ้าหน้าที่จัดการไว้   <- ข้อ 4
- CON-ADD-01 ข้อมูลผลการเรียนเพิ่มเติมต้องผูกกับคำร้องเดิมของนักศึกษาคนนั้น ไม่สร้างคำร้องใหม่   <- UC-02 Postcondition
- CON-ADD-02 รายวิชาเดียวกันในปีการศึกษาและภาคเรียนเดียวกันมีได้เพียง 1 ระเบียนต่อ 1 คำร้อง   <- UC-02 alt 2 + ASM-ADD-07

## Data Rules
- DR-ADD-01 ฟิลด์บังคับต่อ 1 รายการ: ปีการศึกษา, ภาคเรียน, รายวิชา, เกรด   <- UC-02 ขั้น 3 + ASM-ADD-07
- DR-ADD-02 เกรดรับเฉพาะค่าในชุดนี้เท่านั้น: A, B+, B, C+, C, D+, D, F, W, I, T ค่าอื่นถือว่ารูปแบบไม่ถูกต้อง   <- ข้อ 16 + ASM-ADD-05
- DR-ADD-03 รายวิชาที่ผลยังไม่สมบูรณ์บันทึกได้ แต่ต้องถูกทำเครื่องหมายว่ายังไม่นับว่าผ่าน   <- ข้อ 16 (ค่าเกรดใดนับเป็นผลไม่สมบูรณ์ ยังไม่ทราบ ดู OQ-ADD-01)
- DR-ADD-04 รายวิชาต้องถูกเลือกจากข้อมูลรายวิชาของระบบตาม DOM-COURSE-01 ระบบไม่รับรายวิชาที่นักศึกษาพิมพ์ขึ้นเองและไม่มีในข้อมูลรายวิชา   <- ASM-ADD-05
- DR-ADD-05 นิยามรายวิชาซ้ำ: รายวิชาเดิม + ปีการศึกษาเดิม + ภาคเรียนเดิม ที่มีอยู่ในคำร้องนั้นแล้ว   <- UC-02 alt 2 + ASM-ADD-07
- DR-ADD-06 การแก้เกรดถือว่า "มีการเปลี่ยนแปลง" เมื่อค่าเกรดใหม่ต่างจากค่าเกรดที่บันทึกไว้เดิมของระเบียนนั้น รายการที่ค่าเกรดไม่ต่างจากเดิมถือว่าไม่มีการเปลี่ยนแปลง   <- ASM-ADD-06

## Requirements
- FR-ADD-01 ระบบต้องแสดงรายการผลการศึกษาที่นักศึกษาคนนั้นเคยส่ง พร้อมเกรดที่บันทึกไว้เดิมของแต่ละรายวิชา และสถานะคำร้องปัจจุบัน   <- UC-02 ขั้น 1 + ข้อ 7 + ASM-ADD-06
- FR-ADD-02 เมื่อนักศึกษายังไม่มีข้อมูลผลการศึกษาเดิม ระบบต้องไม่เปิดฟอร์มส่งเพิ่มเติม และแจ้งให้ดำเนินการส่งผลการศึกษาหลักก่อน   <- UC-02 alt 1
- FR-ADD-03 ระบบต้องให้นักศึกษาเลือกรายวิชาจากข้อมูลรายวิชาของระบบเท่านั้นตาม DR-ADD-04 และกรอกปีการศึกษา ภาคเรียน และเกรดตาม DR-ADD-01   <- UC-02 ขั้น 2-3 + ASM-ADD-05
- FR-ADD-04 เมื่อข้อมูลไม่ครบหรือรูปแบบไม่ถูกต้องตาม DR-ADD-01, DR-ADD-02 และ DR-ADD-04 ระบบต้องไม่บันทึก และแจ้งช่องที่ต้องแก้ไขเป็นรายช่อง   <- UC-02 ขั้น 4, alt 3 + ข้อ 10
- FR-ADD-05 เมื่อนักศึกษาแก้เกรดของรายวิชาที่มีอยู่แล้วตาม DR-ADD-06 ระบบต้องแสดงหน้าจอยืนยันที่ระบุรายวิชา เกรดเดิม และเกรดใหม่ และต้องไม่บันทึกทับข้อมูลเดิมก่อนได้รับการยืนยัน   <- UC-02 alt 2 + ASM-ADD-06
- FR-ADD-06 ระบบต้องแสดงข้อมูลที่กรอกให้นักศึกษายืนยันก่อนบันทึก   <- UC-02 ขั้น 5
- FR-ADD-07 เมื่อนักศึกษายืนยัน ระบบต้องบันทึกเฉพาะรายการที่เพิ่มใหม่และรายการที่เกรดมีการเปลี่ยนแปลงตาม DR-ADD-06 รวมเข้ากับคำร้องเดิมตาม CON-ADD-01 โดยรายการที่ไม่มีการเปลี่ยนแปลงต้องคงค่าเดิมไว้ และต้องปรับสถานะการตรวจสอบของคำร้องเป็น "รอตรวจสอบ"   <- UC-02 ขั้น 6 + ASM-ADD-04, ASM-ADD-06 (ข้อนี้รวม 2 พฤติกรรม การแยกข้อต้องสร้าง ID ใหม่ ดู OQ-ADD-11)
- FR-ADD-08 เมื่ออยู่นอกช่วงที่เปิดให้ส่งผลเพิ่มเติมตาม IF-SCHED-01 ระบบต้องไม่รับข้อมูล และแสดงช่วงเวลาที่กำหนด   <- UC-02 Precondition + ข้อ 6
- FR-ADD-09 หากบันทึกไม่สำเร็จ ระบบต้อง rollback ทุกรายการที่ส่งในครั้งนั้น คงข้อมูลเดิมของคำร้องไว้ครบ และแจ้งข้อผิดพลาดพร้อมให้ลองใหม่   <- UC-02 Exception
- FR-ADD-10 หลังบันทึกสำเร็จ ระบบต้องแสดงสถานะคำร้องล่าสุดให้นักศึกษาเห็น   <- ข้อ 7
- FR-ADD-11 รายวิชาที่บันทึกตาม DR-ADD-03 ต้องถูกส่งต่อให้ขั้นตอนตรวจสอบโดยไม่ถูกนับว่าผ่าน   <- ข้อ 16

## Quality Requirements
- NFR-ADD-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-ADD-02 [Security] นักศึกษาเรียกดู เพิ่ม หรือแก้ข้อมูลในคำร้องของนักศึกษาคนอื่นไม่ได้ ต้องได้ HTTP 403
- NFR-ADD-03 [Usability] ข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทย และระบุช่องที่ต้องแก้ไขอย่างชัดเจน   <- ข้อ 10
- NFR-ADD-04 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-ADD-01)
- NFR-ADD-05 [Data Integrity] การบันทึกรายการเพิ่มเติมและการแก้เกรดในการส่ง 1 ครั้งต้องเป็นธุรกรรมเดียว ไม่เกิดข้อมูลค้างบางส่วน
- NFR-ADD-06 [Performance] บันทึกผลการเรียนเพิ่มเติม: เวลาตอบสนอง p95 <= 2 วินาที   <- ค่าที่เสนอไว้ ดู ASM-ADD-01

## Acceptance Criteria
- [ ] AC-ADD-01 (FR-ADD-07, CON-ADD-01)
      Given นักศึกษามีข้อมูลผลการศึกษาเดิม อยู่ในช่วงที่เปิดรับ และกรอกรายวิชาใหม่ครบตาม DR-ADD-01
      When  กดยืนยันการส่ง
      Then  ระบบบันทึกรายการเพิ่มเติมเข้าคำร้องเดิม ไม่มีคำร้องใหม่เกิดขึ้น และสถานะการตรวจสอบเป็น "รอตรวจสอบ"
- [ ] AC-ADD-02 (FR-ADD-02)
      Given นักศึกษายังไม่เคยส่งผลการศึกษา
      When  เปิดเมนูส่งผลการเรียนเพิ่มเติม
      Then  ระบบไม่เปิดฟอร์ม และแจ้งให้ส่งผลการศึกษาหลักก่อน
- [ ] AC-ADD-03 (FR-ADD-05, DR-ADD-05, DR-ADD-06, CON-ADD-02)
      Given คำร้องมีรายวิชา A ปีการศึกษา 2568 ภาคเรียน 1 เกรด I อยู่แล้ว
      When  นักศึกษาแก้เกรดของรายวิชานั้นเป็น B แล้วกดส่ง
      Then  ระบบแสดงหน้าจอยืนยันที่ระบุว่ารายวิชา A จากเกรด I เป็นเกรด B และเมื่อยืนยันแล้ว ระเบียนของรายวิชานั้นยังเท่ากับ 1 โดยเกรดเปลี่ยนเป็น B
- [ ] AC-ADD-04 (FR-ADD-04, DR-ADD-02, NFR-ADD-03)
      Given กรอกเกรดเป็นค่าที่ไม่อยู่ในชุดตาม DR-ADD-02
      When  กดส่ง
      Then  ระบบไม่บันทึก และแสดงข้อความภาษาไทยที่ช่องเกรด
- [ ] AC-ADD-05 (FR-ADD-08, IF-SCHED-01)
      Given ตารางเวลาประจำเทอมระบุว่าปิดรับผลการเรียนเพิ่มเติมแล้ว
      When  พยายามส่งข้อมูล
      Then  ระบบไม่รับข้อมูล ไม่มีการเปลี่ยนแปลงในคำร้อง และแสดงช่วงเวลาที่กำหนด
- [ ] AC-ADD-06 (FR-ADD-09, NFR-ADD-05)
      Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึก
      When  กดยืนยันการส่ง
      Then  ไม่มีรายการเพิ่มเติมถูกสร้าง ไม่มีเกรดใดถูกแก้ ข้อมูลเดิมของคำร้องยังครบ และหน้าจอแจ้งข้อผิดพลาดพร้อมให้ลองใหม่
- [ ] AC-ADD-07 (FR-ADD-11, DR-ADD-03, DOM-GRADE-01)
      Given บันทึกรายวิชาที่ผลยังไม่สมบูรณ์
      When  ขั้นตอนตรวจสอบอ่านข้อมูลคำร้องนั้น
      Then  รายวิชานั้นถูกระบุว่ายังไม่นับว่าผ่าน
- [ ] AC-ADD-08 (NFR-ADD-02)
      Given นักศึกษา A เรียกดูหรือส่งรายการเข้าคำร้องของนักศึกษา B
      When  ส่ง request ด้วย session ของ A
      Then  ระบบตอบ HTTP 403 และคำร้องของ B ไม่เปลี่ยนแปลง
- [ ] AC-ADD-09 (NFR-ADD-01)
      Given ผู้ใช้ไม่มีการใช้งานต่อเนื่องเกิน 30 นาที
      When  เรียกหน้าส่งผลการเรียนเพิ่มเติมอีกครั้ง
      Then  ระบบตัดการเชื่อมต่อและให้ยืนยันตัวตนใหม่

## Assumptions & Open Questions
- ASM-ADD-01 UC-02 ระบุ NFR เป็นหมวด (Usability, Data Integrity) และรายการความต้องการ 20 ข้อไม่ได้ให้ตัวเลขทุกข้อ ค่าตัวเลขใน NFR-ADD-04 และ NFR-ADD-06 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-ADD-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-ADD-03 "คำร้อง" ในข้อ 3 และ ข้อ 7 ถือว่าเป็นชุดข้อมูลผลการศึกษาที่นักศึกษาส่งตาม UC-01 รอยืนยันจากทีม
- ASM-ADD-04 ทีมตัดสินว่าสถานะการตรวจสอบหลังบันทึกสำเร็จคือ "รอตรวจสอบ" (คำตอบทีม 2569-11-13) UC-02 ระบุเพียง "ปรับสถานะการตรวจสอบ" ไม่ได้ระบุชื่อสถานะ
- ASM-ADD-05 ทีมตัดสินว่านักศึกษาเลือกรายวิชาจากรายการที่มีในระบบเท่านั้น (dropdown) ไม่รับรายวิชาที่พิมพ์ขึ้นเอง และชุดค่าเกรดที่รับได้คือ A, B+, B, C+, C, D+, D, F, W, I, T (คำตอบทีม 2569-11-13) ซึ่งทำให้ FR-ADD-03 เดิมที่เขียนว่า "หรือกรอก" ไม่ขัดกับ DR-ADD-04 อีก
- ASM-ADD-06 ทีมตัดสินว่าฟีเจอร์นี้รองรับทั้งการเพิ่มรายวิชาใหม่และการแก้เกรดของรายวิชาที่ส่งไปแล้ว โดยระบบบันทึกเฉพาะรายการที่เกรดเปลี่ยนแปลง และต้องมีหน้าจอยืนยันที่ระบุเกรดเดิมและเกรดใหม่ก่อนบันทึกทับ (คำตอบทีม 2569-11-13) จึงย้าย "การแก้ไขรายวิชาที่ส่งไปแล้ว" ออกจาก OUT-ADD-06 เข้ามาเป็น IN-ADD-06
- ASM-ADD-07 ทีมตัดสินว่าต้องเก็บภาคเรียนเพิ่มจากปีการศึกษาและเกรด (คำตอบทีม 2569-11-13) นิยามรายวิชาซ้ำใน DR-ADD-05 และ CON-ADD-02 จึงนับ รายวิชา + ปีการศึกษา + ภาคเรียน
- ASM-ADD-08 ทีมตัดสินว่าช่วงเวลาที่เปิดให้ส่งผลเพิ่มเติมเป็นช่วงเดียวกับการส่งผลการศึกษาครั้งแรก (UC-01) และยังแก้ได้ต่อไปจนถึงเทอมถัดไป (คำตอบทีม 2569-11-13) วันสิ้นสุดที่แน่นอนยังไม่ชัด ดู OQ-ADD-07
- ASM-ADD-09 ทีมตัดสินว่าส่งผลเพิ่มเติมได้ไม่จำกัดจำนวนครั้งภายในช่วงที่เปิดรับ แต่ส่งซ้ำได้เฉพาะเมื่อมีการเปลี่ยนแปลงผลเกรดตาม DR-ADD-06 เท่านั้น (คำตอบทีม 2569-11-13) ตรงกับ ASM-OWN-09 ใน specs/003
- ASM-ADD-10 ทีมยืนยันว่า I คือผลที่ยังไม่สมบูรณ์และยังไม่นับว่าผ่านตาม DR-ADD-03 และ W คือการถอนรายวิชา (คำตอบทีม 2569-11-13) ส่วนภาควิชากำหนดว่าค้างรายวิชาที่ยังไม่ออกผลได้ไม่เกิน 1 วิชาจึงยังถือว่าผ่านเงื่อนไข ซึ่งเป็นเงื่อนไขการผ่านของ UC-12 และ UC-16 ไม่ใช่ของ spec นี้ ดู OQ-OWN-09 ใน specs/003
- ASM-ADD-11 ทีมตัดสินว่านักศึกษาต้องกรอกเกรดให้ครบทุกรายวิชา ถ้าผลยังไม่ออกให้เลือก I ห้ามปล่อยช่องว่างหรือไม่เลือก (คำตอบทีม 2569-11-13) สอดคล้องกับ DR-ADD-01 ที่กำหนดให้เกรดเป็นฟิลด์บังคับ
- OQ-ADD-01 ค่าเกรด T หมายถึงอะไร และนับเป็นผลที่สมบูรณ์หรือไม่สมบูรณ์ตาม DR-ADD-03 (ต้องถาม: เจ้าหน้าที่งานทะเบียน) ส่วน I และ W ได้คำตอบแล้วตาม ASM-ADD-10
- OQ-ADD-03 ข้อ 18 ให้บันทึกคำร้องเป็นฉบับร่างได้ แต่ UC-02 ไม่ระบุ การส่งผลเพิ่มเติมรองรับฉบับร่างหรือไม่ (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
- OQ-ADD-04 ปิดแล้ว ทีมตัดสินว่ากระบวนการส่งผลเพื่อตรวจสอบเงื่อนไขไม่มีขั้นตอนให้อาจารย์ที่ปรึกษาอนุมัติ (คำตอบทีม 2569-11-13 ดู ASM-OWN-05 ใน specs/003) จึงไม่มีกรณีย้อนสถานะจากการอนุมัติของอาจารย์ แต่ยังเหลือคำถามว่าถ้าสถานะเป็น "เสร็จสิ้น" และเจ้าหน้าที่เผยแพร่ผลแล้ว การแก้เกรดจะย้อนสถานะกลับเป็น "รอตรวจสอบ" หรือไม่ (ต้องถาม: เจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
- OQ-ADD-07 "แก้ได้จนถึงเทอมถัดไป" ตาม ASM-ADD-08 สิ้นสุดเมื่อใดแน่ (วันเปิดเทอมถัดไป หรือวันสุดท้ายของช่วงรับข้อมูลของเทอมถัดไป) และตารางเวลาประจำเทอมต้องเก็บค่านี้เป็นฟิลด์แยกหรือไม่ (ต้องถาม: เจ้าหน้าที่ผู้จัดการตารางเวลาประจำเทอม UC-15)
- OQ-ADD-08 ถ้าระบบอ่านตารางเวลาประจำเทอมไม่ได้ หรือเจ้าหน้าที่ยังไม่ได้ตั้งช่วงเวลา ระบบต้องถือว่าเปิดรับหรือปิดรับ (ต้องถาม: เจ้าหน้าที่ผู้จัดการตารางเวลาประจำเทอม UC-15 และทีมเอง)
- OQ-ADD-09 ทีมตอบว่าต้องบันทึกเวลาทุกครั้งที่เกรดมีการเปลี่ยนแปลง ซึ่งเป็นพฤติกรรมใหม่ที่ไม่มีใน UC-02 และรายการความต้องการ 20 ข้อ ผมจึงไม่ได้เขียนเป็น FR เอง เสนอให้ทีมอนุมัติเพิ่ม FR-ADD-12 "ระบบต้องบันทึกเวลาที่แก้เกรดของแต่ละระเบียนที่มีการเปลี่ยนแปลงตาม DR-ADD-06" และต้องตอบด้วยว่าเก็บเฉพาะเวลา หรือเก็บเกรดเดิมกับเกรดใหม่ด้วย และใครดูประวัตินี้ได้ (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
- OQ-ADD-10 ทีมตอบว่าการส่งผลเพิ่มเติมต้องมีการตรวจสอบเงื่อนไขเบื้องต้น (UC-07) ซึ่ง UC-02 ไม่ได้ระบุ include UC-07 ผมจึงไม่ได้เขียนเป็น FR เอง เสนอให้ทีมอนุมัติเพิ่ม FR-ADD-13 "เมื่อนักศึกษากดส่ง ระบบต้องเรียกการตรวจสอบเงื่อนไขเบื้องต้นอัตโนมัติตาม SPEC-PRE-007 และแสดงผลเบื้องต้นก่อนบันทึก" พร้อมตอบว่าผลเบื้องต้นที่ไม่ผ่านปิดกั้นการบันทึกหรือไม่ (เทียบ FR-PRE-10 และ OQ-PRE-03) (ต้องถาม: ทีมเอง)
- OQ-ADD-11 ข้อที่ยังตามรอยไม่ได้ ผมสร้าง AC ID ใหม่เองไม่ได้ จึงเสนอให้ทีมอนุมัติเพิ่ม AC ตามนี้ (ต้องถาม: ทีมเอง)
  - AC-ADD-10 (FR-ADD-07, DR-ADD-06): แก้เฉพาะรายวิชา B รายวิชา A ต้องคงเกรดเดิม
  - AC-ADD-11 (FR-ADD-01): เปิดหน้าแล้วเห็นรายวิชา ปีการศึกษา ภาคเรียน เกรดเดิมทุกรายการ พร้อมสถานะคำร้อง
  - AC-ADD-12 (FR-ADD-03, DR-ADD-04, DOM-COURSE-01): เลือกรายวิชาได้เฉพาะที่มีในข้อมูลรายวิชาของระบบ

  - AC-ADD-15 (NFR-ADD-04): ไม่มีการเลื่อนแนวนอนที่ความกว้างจอ 360 px
  - AC-ADD-16 (NFR-ADD-06): บันทึกผลเพิ่มเติม p95 <= 2 วินาที (ต้องระบุจำนวนผู้ใช้พร้อมกันที่ใช้วัด)

- OQ-ADD-12 ทีมเสนอเพิ่มว่านักศึกษาควรแนบไฟล์ภาพหน้าจอผลการเรียนจากระบบของมหาวิทยาลัย เพื่อให้เจ้าหน้าที่ตรวจว่าเกรดที่กรอกถูกต้อง (คำตอบทีม 2569-11-13) ซึ่งเป็นความต้องการใหม่ที่ไม่มีใน UC-02 และไม่มีในรายการความต้องการ 20 ข้อ ผมจึงไม่ได้เขียนเป็น FR เอง ต้องให้ทีมตัดสินก่อนว่า (ก) เป็นของ spec นี้ หรือเป็นของ specs/001 ที่มีช่องแนบ Transcript อยู่แล้ว (ข) บังคับแนบทุกครั้งที่ส่ง หรือแนบเฉพาะเมื่อมีการแก้เกรด (ค) รับไฟล์ชนิดใดและขนาดไม่เกินเท่าไร (ง) ใครเปิดดูไฟล์นี้ได้ และถ้าตกลงให้อยู่ใน spec นี้ ต้องอนุมัติ FR ID ใหม่ด้วย (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
