# แผนทางเทคนิค: SPEC-ADD-002 ส่งผลการเรียนเพิ่มเติม

สถานะ: ร่างเพื่อให้ทีมตรวจ

## 1. สรุปแนวทาง
- ฟีเจอร์นี้ให้นักศึกษาที่มีคำร้องเดิมเพิ่มรายวิชาที่ได้ผลภายหลัง หรือแก้เกรดในระเบียนเดิม โดยผูกข้อมูลเข้าคำร้องเดิม (FR-ADD-03, FR-ADD-07, CON-ADD-01)
- นักศึกษาเลือกวิชาจากรายการรายวิชาของระบบ และกรอกปีการศึกษา ภาคเรียน และเกรด (FR-ADD-03, DR-ADD-01, DR-ADD-04)
- ก่อนบันทึก ระบบตรวจช่วงเวลาและข้อมูล แล้วแสดงสรุปให้ยืนยัน โดยการแก้เกรดต้องแสดงค่าเดิมและค่าใหม่ (FR-ADD-04, FR-ADD-05, FR-ADD-06, FR-ADD-08)
- การยืนยันบันทึกรายการที่เพิ่มหรือเปลี่ยนเกรดเป็นธุรกรรมเดียว พร้อมปรับสถานะคำร้องตามข้อกำหนด (FR-ADD-07, FR-ADD-09, NFR-ADD-05)
- ทุก request ผูกกับ session และคำร้องของนักศึกษาผู้เรียก; ใช้หน้าจอเว็บแบบ responsive และอ้างอิงตารางเวลาเดิม (IF-AUTH-01, IF-WEB-01, IF-SCHED-01, NFR-ADD-02, NFR-ADD-04)

## 4. API / หน้าจอ

ชื่อ path เป็นข้อเสนอทางเทคนิคเพื่ออธิบายขอบเขต API; ปรับให้เข้ากับ convention ของระบบได้โดยไม่เปลี่ยนพฤติกรรมตาม FR

| รายการ | Method / path หรือหน้าจอ | Input / Output หลัก | รองรับ |
|---|---|---|---|
| อ่านผลการเรียนเดิม สถานะ และช่วงเวลา | `GET /api/additional-grades` | Input: session; Output: ระเบียนผลการเรียนของคำร้องเดิม, สถานะปัจจุบัน และช่วงเวลาจากตารางประจำเทอม; ไม่มีผลเดิมให้หน้าจอแจ้งให้ส่งผลหลักก่อน | FR-ADD-01, FR-ADD-02, FR-ADD-08, FR-ADD-10, IF-SCHED-01, NFR-ADD-02 |
| อ่านรายการรายวิชา | `GET /api/courses` | Input: session; Output: รายการรายวิชาจากข้อมูลกลางที่เลือกได้ | FR-ADD-03, DOM-COURSE-01 |
| ตรวจ/แสดงตัวอย่างก่อนยืนยัน | `POST /api/additional-grades/preview` | Input: รายการวิชา, ปีการศึกษา, ภาคเรียน, เกรด; Output: ข้อผิดพลาดรายช่อง, รายการซ้ำ, และสรุปเพิ่มใหม่/แก้เกรดเดิม โดยยังไม่บันทึก | FR-ADD-03, FR-ADD-04, FR-ADD-05, FR-ADD-06 |
| ยืนยันและบันทึก | `POST /api/additional-grades/confirm` | Input: รายการที่ผู้ใช้ยืนยัน; Output: สถานะคำร้องล่าสุดหรือข้อผิดพลาด; ตรวจ session, เจ้าของคำร้อง, ช่วงเวลา และข้อมูลซ้ำก่อนทำธุรกรรม | FR-ADD-07, FR-ADD-08, FR-ADD-09, FR-ADD-10, FR-ADD-11, CON-ADD-01, CON-ADD-02, NFR-ADD-02, NFR-ADD-05 |
| หน้ารายการ/สถานะ | หน้าเว็บแสดงผลเดิม สถานะ และกรณีไม่มีข้อมูลเดิม | อ่านข้อมูลเฉพาะเจ้าของ session; ไม่เปิดฟอร์มเมื่อไม่มีผลหลัก | FR-ADD-01, FR-ADD-02, FR-ADD-10, IF-AUTH-01 |
| หน้ากรอกและยืนยัน | หน้าเว็บเลือกรายวิชา ระบุปี/ภาค/เกรด แสดงข้อผิดพลาดและสรุปก่อนบันทึก | แสดงเกรดเดิม/ใหม่เมื่อแก้ระเบียน; ปรับการแสดงผลสำหรับจอตั้งแต่ 360 px | FR-ADD-03, FR-ADD-04, FR-ADD-05, FR-ADD-06, FR-ADD-08, NFR-ADD-03, NFR-ADD-04 |

## 7. ลำดับงาน

1. ตรวจ entity คำร้องเดิม, ระเบียนผลการเรียน, ข้อมูลรายวิชา และแหล่งตารางเวลา โดยไม่สร้างโครงสร้างซ้ำ (CON-ADD-01, DOM-COURSE-01, IF-SCHED-01)
2. วางการตรวจ session และการจำกัดเจ้าของคำร้องในทุก API (IF-AUTH-01, FR-ADD-01, NFR-ADD-02, AC-ADD-08, AC-ADD-09)
3. สร้างการอ่านรายการเดิม/สถานะและกรณีไม่มีผลการศึกษาหลัก (FR-ADD-01, FR-ADD-02, FR-ADD-10, AC-ADD-02)
4. สร้างการอ่านรายวิชาและฟอร์มกรอกปีการศึกษา ภาคเรียน และเกรด พร้อมตรวจชุดข้อมูลและการซ้ำ (FR-ADD-03, FR-ADD-04, DR-ADD-01 ถึง DR-ADD-05, AC-ADD-04)
5. สร้างสรุปยืนยันก่อนบันทึก รวมการแสดงเกรดเดิม/ใหม่สำหรับการแก้ไข (FR-ADD-05, FR-ADD-06, AC-ADD-03)
6. เชื่อมตารางเวลาประจำเทอม และตรวจช่วงเวลาอีกครั้งก่อนบันทึก (IF-SCHED-01, FR-ADD-08, AC-ADD-05)
7. บันทึกการเพิ่ม/แก้เกรดและปรับสถานะคำร้องในธุรกรรมเดียว พร้อมจัดการ rollback และผลไม่สมบูรณ์ (FR-ADD-07, FR-ADD-09, FR-ADD-10, FR-ADD-11, NFR-ADD-05, AC-ADD-01, AC-ADD-06, AC-ADD-07)
8. ตรวจข้อความภาษาไทย, responsive 360 px, timeout และ p95 ตาม AC/NFR ที่เกี่ยวข้อง; ทดสอบ integration และสิทธิ์ข้ามเจ้าของ (NFR-ADD-01, NFR-ADD-03, NFR-ADD-04, NFR-ADD-06, AC-ADD-08, AC-ADD-09)

## 8. สิ่งที่ยังไม่ทำ

- OQ-ADD-01 ค่าเกรด T หมายถึงอะไร และนับเป็นผลที่สมบูรณ์หรือไม่สมบูรณ์ตาม DR-ADD-03 (ต้องถาม: เจ้าหน้าที่งานทะเบียน) ส่วน I และ W ได้คำตอบแล้วตาม ASM-ADD-10
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-03 ข้อ 18 ให้บันทึกคำร้องเป็นฉบับร่างได้ แต่ UC-02 ไม่ระบุ การส่งผลเพิ่มเติมรองรับฉบับร่างหรือไม่ (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-04 ปิดแล้ว ทีมตัดสินว่ากระบวนการส่งผลเพื่อตรวจสอบเงื่อนไขไม่มีขั้นตอนให้อาจารย์ที่ปรึกษาอนุมัติ (คำตอบทีม 2569-11-13 ดู ASM-OWN-05 ใน specs/003) จึงไม่มีกรณีย้อนสถานะจากการอนุมัติของอาจารย์ แต่ยังเหลือคำถามว่าถ้าสถานะเป็น "เสร็จสิ้น" และเจ้าหน้าที่เผยแพร่ผลแล้ว การแก้เกรดจะย้อนสถานะกลับเป็น "รอตรวจสอบ" หรือไม่ (ต้องถาม: เจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-07 "แก้ได้จนถึงเทอมถัดไป" ตาม ASM-ADD-08 สิ้นสุดเมื่อใดแน่ (วันเปิดเทอมถัดไป หรือวันสุดท้ายของช่วงรับข้อมูลของเทอมถัดไป) และตารางเวลาประจำเทอมต้องเก็บค่านี้เป็นฟิลด์แยกหรือไม่ (ต้องถาม: เจ้าหน้าที่ผู้จัดการตารางเวลาประจำเทอม UC-15)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-08 ถ้าระบบอ่านตารางเวลาประจำเทอมไม่ได้ หรือเจ้าหน้าที่ยังไม่ได้ตั้งช่วงเวลา ระบบต้องถือว่าเปิดรับหรือปิดรับ (ต้องถาม: เจ้าหน้าที่ผู้จัดการตารางเวลาประจำเทอม UC-15 และทีมเอง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-09 ทีมตอบว่าต้องบันทึกเวลาทุกครั้งที่เกรดมีการเปลี่ยนแปลง ซึ่งเป็นพฤติกรรมใหม่ที่ไม่มีใน UC-02 และรายการความต้องการ 20 ข้อ ผมจึงไม่ได้เขียนเป็น FR เอง เสนอให้ทีมอนุมัติเพิ่ม FR-ADD-12 "ระบบต้องบันทึกเวลาที่แก้เกรดของแต่ละระเบียนที่มีการเปลี่ยนแปลงตาม DR-ADD-06" และต้องตอบด้วยว่าเก็บเฉพาะเวลา หรือเก็บเกรดเดิมกับเกรดใหม่ด้วย และใครดูประวัตินี้ได้ (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-10 ทีมตอบว่าการส่งผลเพิ่มเติมต้องมีการตรวจสอบเงื่อนไขเบื้องต้น (UC-07) ซึ่ง UC-02 ไม่ได้ระบุ include UC-07 ผมจึงไม่ได้เขียนเป็น FR เอง เสนอให้ทีมอนุมัติเพิ่ม FR-ADD-13 "เมื่อนักศึกษากดส่ง ระบบต้องเรียกการตรวจสอบเงื่อนไขเบื้องต้นอัตโนมัติตาม SPEC-PRE-007 และแสดงผลเบื้องต้นก่อนบันทึก" พร้อมตอบว่าผลเบื้องต้นที่ไม่ผ่านปิดกั้นการบันทึกหรือไม่ (เทียบ FR-PRE-10 และ OQ-PRE-03) (ต้องถาม: ทีมเอง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-11 ข้อที่ยังตามรอยไม่ได้ ผมสร้าง AC ID ใหม่เองไม่ได้ จึงเสนอให้ทีมอนุมัติเพิ่ม AC ตามนี้ (ต้องถาม: ทีมเอง)
  - AC-ADD-10 (FR-ADD-07, DR-ADD-06): แก้เฉพาะรายวิชา B รายวิชา A ต้องคงเกรดเดิม
  - AC-ADD-11 (FR-ADD-01): เปิดหน้าแล้วเห็นรายวิชา ปีการศึกษา ภาคเรียน เกรดเดิมทุกรายการ พร้อมสถานะคำร้อง
  - AC-ADD-12 (FR-ADD-03, DR-ADD-04, DOM-COURSE-01): เลือกรายวิชาได้เฉพาะที่มีในข้อมูลรายวิชาของระบบ
  - AC-ADD-13 (FR-ADD-10): หลังบันทึกสำเร็จ หน้าจอแสดงสถานะคำร้องล่าสุด
  - AC-ADD-14 (FR-ADD-06): ระบบแสดงข้อมูลที่กรอกให้ยืนยันก่อนบันทึก
  - AC-ADD-15 (NFR-ADD-04): ไม่มีการเลื่อนแนวนอนที่ความกว้างจอ 360 px
  - AC-ADD-16 (NFR-ADD-06): บันทึกผลเพิ่มเติม p95 <= 2 วินาที (ต้องระบุจำนวนผู้ใช้พร้อมกันที่ใช้วัด)
  - และเสนอให้แยก FR-ADD-07 เป็น 2 ข้อ (บันทึกข้อมูล / ปรับสถานะ) ซึ่งต้องสร้าง FR ID ใหม่ รอทีมตัดสิน
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- OQ-ADD-12 ทีมเสนอเพิ่มว่านักศึกษาควรแนบไฟล์ภาพหน้าจอผลการเรียนจากระบบของมหาวิทยาลัย เพื่อให้เจ้าหน้าที่ตรวจว่าเกรดที่กรอกถูกต้อง (คำตอบทีม 2569-11-13) ซึ่งเป็นความต้องการใหม่ที่ไม่มีใน UC-02 และไม่มีในรายการความต้องการ 20 ข้อ ผมจึงไม่ได้เขียนเป็น FR เอง ต้องให้ทีมตัดสินก่อนว่า (ก) เป็นของ spec นี้ หรือเป็นของ specs/001 ที่มีช่องแนบ Transcript อยู่แล้ว (ข) บังคับแนบทุกครั้งที่ส่ง หรือแนบเฉพาะเมื่อมีการแก้เกรด (ค) รับไฟล์ชนิดใดและขนาดไม่เกินเท่าไร (ง) ใครเปิดดูไฟล์นี้ได้ และถ้าตกลงให้อยู่ใน spec นี้ ต้องอนุมัติ FR ID ใหม่ด้วย (ต้องถาม: ทีมเอง ร่วมกับเจ้าหน้าที่ผู้ตรวจสอบคำร้อง)
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ

## หมายเหตุสำหรับทีม

- ข้อจำกัด IF/DOM/CON ทั้ง 8 ข้อถูกนำไปใช้ในแผน; IF-SCHED-01 ยังต้องรอคำตอบเรื่องพฤติกรรมเมื่อไม่มีข้อมูลตาราง (OQ-ADD-08)
- AC-ADD-06 ต้องจำลองความล้มเหลวของฐานข้อมูล/ธุรกรรม; AC-ADD-07 ต้องทดสอบร่วมกับขั้นตอนตรวจสอบ; AC-ADD-09 ต้องใช้การทดสอบ session timeout; NFR-ADD-04 และ NFR-ADD-06 ต้องตรวจจอ 360 px และวัด p95
- ไม่เดาความหมายของ T, การรองรับ draft, การย้อนสถานะหลังเผยแพร่, ขอบเขตวันเปิดรับ, พฤติกรรมเมื่ออ่านตารางไม่ได้, ประวัติแก้เกรด, การเรียก UC-07, AC/FR ID ใหม่ หรือข้อกำหนดไฟล์แนบ
