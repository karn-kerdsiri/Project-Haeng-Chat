# Feature: ลงนาม / รับรองเอกสาร (Sign and Certify Document)
Spec ID: SPEC-SGN-011 | Source: Use Case Specification UC-11 ลงนาม / รับรองเอกสาร (Included by UC-09) + รายการความต้องการของทีม ข้อ 8, ข้อ 15 | Use case: UC-11
Owner: ทีม B | Status: Draft v1 | Updated: 2569-10-21

## Goal
อาจารย์ที่ปรึกษาลงนามหรือรับรองเอกสารของรายการที่ผ่านการอนุมัติแล้วได้
และระบบบันทึกสถานะการรับรองพร้อมข้อมูลการลงนามไว้ตรวจสอบย้อนหลังได้

## Scope
### In scope
- IN-SGN-01 ตรวจสอบว่ารายการผ่านการอนุมัติก่อนให้ลงนาม               <- UC-11 ขั้น 1, Precondition
- IN-SGN-02 แสดงเอกสารที่ต้องลงนาม                                 <- UC-11 ขั้น 2
- IN-SGN-03 ให้อาจารย์ลงนาม/รับรอง                                 <- UC-11 ขั้น 3
- IN-SGN-04 บันทึกการรับรองพร้อมวันที่และผู้ลงนาม                     <- UC-11 ขั้น 4 + ข้อ 8
- IN-SGN-05 อัปเดตสถานะของรายการเป็นรับรองแล้ว                      <- UC-11 ขั้น 5, Postcondition
- IN-SGN-06 แจ้งกรณียังไม่อนุมัติ และกรณีเอกสารไม่ครบ                 <- UC-11 alt 1-2
### Out of scope
- OUT-SGN-01 การตรวจสอบและอนุมัติผลการศึกษา - เป็นของ UC-09 ซึ่งเรียกใช้ use case นี้
- OUT-SGN-02 การตรวจสอบและยืนยันโดยเจ้าหน้าที่ - เป็นของ UC-13
- OUT-SGN-03 การเผยแพร่ผล - เป็นของ UC-14
- OUT-SGN-04 การให้นักศึกษาดาวน์โหลดเอกสารที่รับรองแล้ว - เป็นของ UC-04
- OUT-SGN-05 การสร้างเนื้อหาเอกสารที่นำมาลงนาม - UC-11 ไม่ระบุ (ดู OQ-SGN-02)

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนด้วยบัญชีเดียวกับระบบของมหาวิทยาลัย มิฉะนั้นตอบ HTTP 401   <- ข้อ 12
- IF-WEB-01 ทุกหน้าจอของฟีเจอร์นี้ต้องทำงานบนเบราว์เซอร์โดยไม่ต้องติดตั้งโปรแกรมเพิ่ม   <- ข้อ 13
- IF-TECH-01 ส่วนหน้าจอพัฒนาด้วย React และข้อมูลการลงนามเก็บในฐานข้อมูล PostgreSQL   <- ข้อ 19
- IF-AUDIT-01 ทุกการลงนามและการเปลี่ยนสถานะต้องบันทึกประวัติพร้อมผู้ดำเนินการให้เจ้าหน้าที่เรียกดูได้   <- ข้อ 8
- CON-FILE-01 ไฟล์เอกสารที่เกี่ยวข้องต้องเป็น PDF, JPG หรือ PNG ขนาดไม่เกิน 10 MB ต่อไฟล์   <- ข้อ 15
- CON-SGN-01 ระบบต้องไม่อนุญาตให้ลงนามรายการที่ยังไม่ผ่านการอนุมัติ   <- UC-11 ขั้น 1, alt 1
- CON-SGN-02 ข้อมูลการลงนามที่บันทึกแล้วต้องแก้ไขหรือลบย้อนหลังไม่ได้   <- UC-11 NFR (Auditability, Integrity)

## Data Rules
- DR-SGN-01 ข้อมูลการลงนามที่บันทึกต่อ 1 รายการ: ผู้ลงนาม วันที่และเวลาที่ลงนาม และรายการที่ถูกรับรอง   <- UC-11 ขั้น 4
- DR-SGN-02 เอกสารที่ถือว่าครบต้องมีเอกสารที่จำเป็นของรายการนั้นทั้งหมด (รายการเอกสารที่จำเป็นยังไม่ระบุ ดู OQ-SGN-01)
- DR-SGN-03 สถานะหลังลงนามสำเร็จคือ รับรองแล้ว   <- UC-11 Postcondition (ชื่อสถานะรอยืนยัน ดู OQ-SGN-03)

## Requirements
- FR-SGN-01 ระบบต้องตรวจสอบว่ารายการผ่านการอนุมัติตาม CON-SGN-01 ก่อนเปิดให้ลงนาม   <- UC-11 ขั้น 1
- FR-SGN-02 ระบบต้องแสดงเอกสารของรายการที่จะลงนามให้อาจารย์ตรวจดูก่อน   <- UC-11 ขั้น 2
- FR-SGN-03 ระบบต้องให้อาจารย์ลงนามหรือรับรองเอกสารของรายการที่เลือก   <- UC-11 ขั้น 3
- FR-SGN-04 เมื่อลงนาม ระบบต้องบันทึกข้อมูลการรับรองตาม DR-SGN-01   <- UC-11 ขั้น 4
- FR-SGN-05 เมื่อบันทึกการรับรองสำเร็จ ระบบต้องอัปเดตสถานะของรายการตาม DR-SGN-03   <- UC-11 ขั้น 5
- FR-SGN-06 เมื่อรายการยังไม่ได้รับการอนุมัติ ระบบต้องไม่อนุญาตให้ลงนาม และแจ้งเหตุผล   <- UC-11 alt 1
- FR-SGN-07 เมื่อเอกสารไม่ครบตาม DR-SGN-02 ระบบต้องแจ้งให้ดำเนินการแก้ไขก่อน และไม่บันทึกการลงนาม   <- UC-11 alt 2
- FR-SGN-08 หากบันทึกการลงนามไม่สำเร็จ ระบบต้องแจ้งข้อผิดพลาด และไม่เปลี่ยนสถานะของรายการ   <- UC-11 Exception
- FR-SGN-09 ระบบต้องบันทึกประวัติการลงนามและผู้ดำเนินการตาม IF-AUDIT-01   <- ข้อ 8
- FR-SGN-10 ระบบต้องปฏิเสธการลงนามโดยผู้ที่ไม่มีสิทธิ์ลงนามในรายการนั้นด้วย HTTP 403   <- UC-11 Precondition
- FR-SGN-11 ระบบต้องไม่ให้แก้ไขหรือลบข้อมูลการลงนามที่บันทึกแล้วตาม CON-SGN-02

## Quality Requirements
- NFR-SGN-01 [Security] ระบบต้องตัดการเชื่อมต่อของบัญชีผู้ใช้อัตโนมัติ เมื่อไม่มีการใช้งานต่อเนื่องเกิน 30 นาที   <- ข้อ 9
- NFR-SGN-02 [Security] เฉพาะผู้ใช้บทบาทอาจารย์ที่ปรึกษาที่มีสิทธิ์ในรายการนั้นจึงจะลงนามได้   <- UC-11 NFR (Security)
- NFR-SGN-03 [Auditability] ข้อมูลการลงนามต้องเก็บไว้ไม่น้อยกว่า 1 ปี และตรวจสอบย้อนหลังได้ว่าใครลงนามเมื่อใด   <- UC-11 NFR (Auditability) + ข้อ 8 (ระยะเวลา 1 ปีเป็นค่าที่เสนอไว้ ดู ASM-SGN-01)
- NFR-SGN-04 [Integrity] เอกสารที่รับรองแล้วต้องตรวจสอบได้ว่าไม่ถูกแก้ไขหลังการลงนาม   <- UC-11 NFR (Integrity) (วิธีตรวจสอบรอยืนยัน ดู OQ-SGN-04)
- NFR-SGN-05 [Usability] ข้อความแจ้งข้อผิดพลาดต้องเป็นภาษาไทยและระบุสิ่งที่ต้องแก้ไข   <- ข้อ 10
- NFR-SGN-06 [Usability] ทุกหน้าจอของฟีเจอร์นี้ต้องใช้งานได้บนจอโทรศัพท์มือถือ โดยไม่มีการเลื่อนแนวนอนที่ความกว้างจอตั้งแต่ 360 px   <- ข้อ 11 (ค่า 360 px เป็นค่าที่เสนอไว้ ดู ASM-SGN-01)

## Acceptance Criteria
- [ ] AC-SGN-01 (FR-SGN-04, FR-SGN-05, DR-SGN-01)
      Given รายการได้รับการอนุมัติแล้วและเอกสารครบ
      When  อาจารย์ลงนาม/รับรอง
      Then  ระบบบันทึกผู้ลงนามกับวันที่ และเปลี่ยนสถานะเป็นรับรองแล้ว
- [ ] AC-SGN-02 (FR-SGN-06, CON-SGN-01)
      Given รายการยังไม่ได้รับการอนุมัติ
      When  พยายามลงนาม
      Then  ระบบไม่อนุญาตให้ลงนาม และแจ้งเหตุผล
- [ ] AC-SGN-03 (FR-SGN-07, DR-SGN-02)
      Given เอกสารของรายการยังไม่ครบ
      When  พยายามลงนาม
      Then  ระบบแจ้งให้ดำเนินการแก้ไขก่อน และไม่บันทึกการลงนาม
- [ ] AC-SGN-04 (FR-SGN-08)
      Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึกการลงนาม
      When  อาจารย์กดลงนาม
      Then  ระบบแจ้งข้อผิดพลาด และสถานะของรายการยังเป็นสถานะเดิม
- [ ] AC-SGN-05 (FR-SGN-10, NFR-SGN-02)
      Given ผู้ใช้ไม่มีสิทธิ์ลงนามในรายการนั้น
      When  ส่ง request ลงนาม
      Then  ระบบตอบ HTTP 403 และไม่มีข้อมูลการลงนามถูกบันทึก
- [ ] AC-SGN-06 (FR-SGN-11, CON-SGN-02, NFR-SGN-03)
      Given มีข้อมูลการลงนามที่บันทึกแล้ว
      When  พยายามแก้ไขหรือลบข้อมูลการลงนามนั้น
      Then  ระบบไม่อนุญาต และประวัติยังระบุผู้ลงนามกับเวลาเดิม
- [ ] AC-SGN-07 (CON-FILE-01)
      Given เอกสารที่นำมาลงนามเป็นไฟล์ที่ไม่ใช่ PDF/JPG/PNG หรือมีขนาดเกิน 10 MB
      When  ระบบตรวจเอกสารก่อนลงนาม
      Then  ระบบไม่รับเอกสารนั้นและแจ้งเงื่อนไขไฟล์ที่รับได้
- [ ] AC-SGN-08 (FR-SGN-09, IF-AUDIT-01)
      Given มีการลงนาม 1 ครั้ง
      When  เจ้าหน้าที่เรียกดูประวัติของรายการนั้น
      Then  มีประวัติ 1 รายการที่ระบุผู้ดำเนินการและเวลา

## Assumptions & Open Questions
- ASM-SGN-01 UC-11 ระบุ NFR เป็นหมวด (Security, Auditability, Integrity) ค่าตัวเลขใน NFR-SGN-03 และ NFR-SGN-06 จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้ รอทีมยืนยัน
- ASM-SGN-02 ข้อ 19 ระบุ React + PostgreSQL spec นี้จึงยึดข้อ 19 ซึ่งต่างจาก plan.md ของ specs/001-Enter-educational-information ที่ใช้ Supabase ทีมต้องตัดสินและปรับ 001 ให้ตรงกัน
- ASM-SGN-03 ข้อ 15 กำหนดไฟล์ไม่เกิน 10 MB ต่างจาก DR-EDU-06 ใน specs/001 ที่กำหนด 5 MB spec นี้ยึดข้อ 15 ตามที่ทีมสั่ง และทีมต้องปรับ 001 ให้ตรงกัน
- ASM-SGN-04 "รายการที่อนุมัติ" คือคำร้องของนักศึกษาที่ผ่าน UC-09 แล้ว
- OQ-SGN-01 เอกสารที่จำเป็นสำหรับการลงนามมีอะไรบ้าง (UC-11 alt 2 ระบุเพียงว่า "เอกสารไม่ครบ")
- OQ-SGN-02 เอกสารที่นำมาลงนามมาจากไหน (ระบบสร้างจากข้อมูลคำร้อง เจ้าหน้าที่อัปโหลดตามข้อ 5 หรือนักศึกษาแนบมา)
- OQ-SGN-03 วิธีลงนามคือแบบใด (กดยืนยันพร้อมบันทึกชื่อผู้ลงนาม อัปโหลดภาพลายเซ็น หรือลายเซ็นดิจิทัลที่ตรวจสอบได้) ซึ่งกระทบ NFR-SGN-04
- OQ-SGN-04 ต้องตรวจสอบความไม่เปลี่ยนแปลงของเอกสารหลังลงนามด้วยวิธีใด (เช่น เก็บค่าแฮช หรือเก็บสำเนาเอกสารขณะลงนาม)
- OQ-SGN-05 ถอนการลงนามได้หรือไม่ ถ้าได้ ใครมีสิทธิ์และต้องบันทึกอย่างไรให้ไม่ขัดกับ CON-SGN-02
- OQ-SGN-06 กรณีคำร้องแบบกลุ่ม/คู่ตาม UC-08 ต้องลงนาม 1 ครั้งต่อกลุ่มหรือ 1 ครั้งต่อนักศึกษา
