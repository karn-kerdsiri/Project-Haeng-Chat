### Acceptance Criteria


**AC-EDU-01 (FR-EDU-08)**

- Given นักศึกษาเข้าสู่ระบบแล้ว รอบเปิดอยู่ กรอกฟิลด์ตาม DR-EDU-01 ครบถูกต้อง และแนบ Transcript 1 ไฟล์
- When  กดส่งข้อมูล
- Then  ระบบบันทึกสำเร็จ สถานะเป็น "รอตรวจสอบ" และแสดงข้อความยืนยันพร้อมวันเวลาที่บันทึก

**AC-EDU-02 (FR-EDU-05)**

- Given เว้นว่างฟิลด์ GPAX และ ภาคเรียน
- When  กดส่งข้อมูล
- Then  ระบบไม่สร้างข้อมูล และแสดงข้อความผิดพลาดที่ทั้ง 2 ช่องนั้น

**AC-EDU-03 (FR-EDU-06, DR-EDU-02)**

- Given กรอก GPAX = 4.50
- When  กดส่งข้อมูล
- Then  ระบบไม่สร้างข้อมูล และแจ้งว่า GPAX ต้องอยู่ระหว่าง 0.00-4.00

**AC-EDU-04 (FR-EDU-07, DR-EDU-06)**

- Given แนบไฟล์ .exe ขนาด 1 MB
- When  อัปโหลด
- Then  ระบบปฏิเสธไฟล์ แจ้งชนิดไฟล์ที่รับได้ และข้อมูลที่กรอกไว้ยังอยู่ครบ

**AC-EDU-05 (FR-EDU-11, FR-EDU-14)**

- Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึก และไฟล์ถูกอัปโหลดขึ้น Supabase Storage แล้ว
- When  กดส่งข้อมูล
- Then  ไม่มีแถวข้อมูลผลการศึกษาถูกสร้าง ไฟล์ที่เพิ่งอัปโหลดถูกลบออกจาก bucket และหน้าจอแสดงรหัสข้อผิดพลาดพร้อมปุ่ม "ลองใหม่"

**AC-EDU-06 (FR-EDU-09)**

- Given นักศึกษากรอกข้อมูลครบและแนบ Transcript แล้ว
- When  บันทึกข้อมูลสำเร็จ
- Then  มีการแจ้งเตือนในระบบของนักศึกษาคนนั้น 1 รายการในธุรกรรมเดียวกับการบันทึก และระบบไม่ส่งอีเมลใด ๆ

**AC-EDU-07 (FR-EDU-02, IF-FORM-01)**

- Given รอบแบบฟอร์มมีสถานะ closed
- When  เปิดหน้าฟอร์มและพยายามส่งข้อมูล
- Then  ฟอร์มแสดงแบบอ่านอย่างเดียว และ API ตอบ HTTP 409 โดยไม่แก้ไขข้อมูลใด

**AC-EDU-08 (FR-EDU-12, CON-DATA-01)**

- Given นักศึกษามีข้อมูลของรอบเดียวกันอยู่แล้ว
- When  ส่งข้อมูลอีกครั้ง
- Then  ข้อมูลเดิมถูกอัปเดต และจำนวนแถวของ student_id + round_id นั้นยังเท่ากับ 1

**AC-EDU-09 (NFR-SEC-02)**

- Given นักศึกษา A เรียก API ข้อมูลผลการศึกษาของนักศึกษา B
- When  ส่ง request ด้วย session ของ A
- Then  ระบบตอบ HTTP 403 และไม่คืนข้อมูลของ B

**AC-EDU-10 (DOM-PDPA-01, DOM-PDPA-02)**

- Given มีการบันทึกหรือเปิดดูข้อมูลผลการศึกษา 1 ครั้ง
- When  การกระทำเสร็จสิ้น
- Then  มี audit log 1 รายการที่ระบุผู้กระทำ เวลา รหัสนักศึกษา และชนิดการกระทำ

**AC-EDU-11 (NFR-PERF-01)**

- Given ผู้ใช้พร้อมกัน 300 คน
- When  กดส่งข้อมูลผลการศึกษา
- Then  p95 ของเวลาตอบสนอง <= 2 วินาที

**AC-EDU-12 (FR-EDU-01, FR-EDU-04)**

- Given เปิดหน้าแบบฟอร์มขณะรอบเปิดอยู่
- When  กรอกครบและกดถัดไป
- Then  ฟิลด์บังคับทุกช่องมีเครื่องหมาย * และหน้าสรุปแสดงค่าที่กรอกกับรายชื่อไฟล์แนบครบตรงกัน

**AC-EDU-13 (FR-EDU-13, DR-EDU-07)**

- Given กรอกข้อมูลครบทุกช่อง แต่ไม่แนบไฟล์ Transcript
- When  กดส่งข้อมูล
- Then  ระบบไม่สร้างข้อมูล และแจ้งว่าต้องแนบ Transcript อย่างน้อย 1 ไฟล์

**AC-EDU-14 (IF-FILE-01, IF-FILE-02, NFR-SEC-03)**

- Given มี Transcript ที่บันทึกไว้ใน Supabase Storage แล้ว
- When  เรียก storage path ของไฟล์นั้นโดยตรงโดยไม่มี signed URL
- Then  ระบบตอบ HTTP 401 หรือ 403 และไม่คืนไฟล์

### Acceptance Criteria


**AC-ADD-01 (FR-ADD-07, CON-ADD-01)**

- Given นักศึกษามีข้อมูลผลการศึกษาเดิม อยู่ในช่วงที่เปิดรับ และกรอกรายวิชาใหม่ครบตาม DR-ADD-01
- When  กดยืนยันการส่ง
- Then  ระบบบันทึกรายการเพิ่มเติมเข้าคำร้องเดิม ไม่มีคำร้องใหม่เกิดขึ้น และสถานะการตรวจสอบเป็น "รอตรวจสอบ"

**AC-ADD-02 (FR-ADD-02)**

- Given นักศึกษายังไม่เคยส่งผลการศึกษา
- When  เปิดเมนูส่งผลการเรียนเพิ่มเติม
- Then  ระบบไม่เปิดฟอร์ม และแจ้งให้ส่งผลการศึกษาหลักก่อน

**AC-ADD-03 (FR-ADD-05, DR-ADD-05, DR-ADD-06, CON-ADD-02)**

**AC-GRP-01 (FR-GRP-03, FR-GRP-08, CON-GRP-01)**

- Given นักศึกษาเลือกทำงานแบบกลุ่ม/คู่ และระบุสมาชิกที่มีอยู่ในระบบและยังไม่อยู่กลุ่มอื่น
- When  กรอกข้อมูลสมาชิกถูกต้องและยืนยัน
- Then  ระบบบันทึกและเชื่อมโยงสมาชิกกับคำขอเดียวกัน

**AC-GRP-02 (FR-GRP-04, CON-GRP-03)**

- Given ระบุสมาชิกด้วยข้อมูลที่ไม่มีอยู่ในระบบ
- When  กดตรวจสอบหรือยืนยัน
- Then  ระบบไม่บันทึก และแจ้งให้ตรวจสอบข้อมูล

**AC-GRP-03 (FR-GRP-05, CON-GRP-01)**

- Given สมาชิกที่ระบุอยู่ในกลุ่มอื่นของภาคการศึกษาเดียวกันแล้ว
- When  กดยืนยัน
- Then  ระบบแจ้งเตือน และไม่ผูกสมาชิกนั้นเข้ากลุ่มใหม่

**AC-GRP-04 (FR-GRP-06, DR-GRP-03, CON-GRP-02)**

- Given ระบุนักศึกษาคนเดียวกัน 2 ครั้งในกลุ่มเดียวกัน
- When  กดยืนยัน
- Then  ระบบให้แก้ไขก่อน และไม่บันทึกรายการซ้ำ

**AC-GRP-05 (FR-GRP-09, NFR-GRP-04)**

- Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึกความสัมพันธ์
- When  กดยืนยัน
- Then  ไม่มีความสัมพันธ์ของสมาชิกถูกสร้างบางส่วน และระบบแจ้งข้อผิดพลาดพร้อมให้ลองใหม่

**AC-GRP-06 (FR-GRP-10, NFR-GRP-03)**

- Given ระบุสมาชิกด้วยรหัสนักศึกษาที่มีอยู่ในระบบ
- When  ระบบแสดงผลการค้นหาสมาชิก
- Then  ระบบแสดงเฉพาะรหัสนักศึกษา ชื่อ–นามสกุล และสาขา ไม่แสดงเบอร์โทรหรือข้อมูลติดต่ออื่น

**AC-GRP-07 (NFR-GRP-02)**

- Given นักศึกษา A ไม่ได้เป็นสมาชิกของกลุ่ม G
- When  ส่ง request แก้ไขสมาชิกของกลุ่ม G ด้วย session ของ A
- Then  ระบบตอบ HTTP 403 และข้อมูลกลุ่ม G ไม่เปลี่ยนแปลง

### Acceptance Criteria


**AC-SCH-01 (FR-SCH-05, DR-SCH-01)**

- Given เจ้าหน้าที่มีสิทธิ์จัดการตารางเวลา
- When  กำหนดช่วงเวลาครบถ้วนถูกต้องและบันทึก
- Then  ระบบบันทึกตารางเวลา และนำไปใช้งานได้

**AC-SCH-02 (FR-SCH-04, CON-SCH-02)**

- Given มีช่วงเปิดรับข้อมูลของภาคการศึกษานั้นอยู่แล้ว
- When  เพิ่มช่วงเปิดรับข้อมูลที่ซ้อนทับกับช่วงเดิม
- Then  ระบบแจ้งเตือนช่วงเวลาซ้อนทับ และไม่บันทึก

**AC-SCH-03 (FR-SCH-03, DR-SCH-02, NFR-SCH-04)**

- Given กำหนดวันเวลาสิ้นสุดก่อนวันเวลาเริ่ม
- When  กดบันทึก
- Then  ระบบไม่บันทึก และแสดงข้อความภาษาไทยที่ช่องวันเวลาที่ผิด

**AC-SCH-04 (FR-SCH-06, IF-FORM-01, NFR-SCH-03)**

- Given ตารางเวลาระบุช่วงเปิดรับข้อมูลสิ้นสุดเวลา T
- When  เวลาปัจจุบันผ่าน T ไปแล้ว
- Then  แบบฟอร์มยื่นคำร้องถูกปิดอัตโนมัติ และการส่งข้อมูลถูกปฏิเสธ

**AC-SCH-05 (FR-SCH-07)**

- Given เจ้าหน้าที่ขยายวันสิ้นสุดของช่วงเปิดรับข้อมูล
- When  บันทึกสำเร็จ
- Then  แบบฟอร์มเปิดรับข้อมูลตามช่วงเวลาใหม่ทันที

**AC-SCH-06 (FR-SCH-10, NFR-SCH-02)**

- Given ผู้ใช้ที่ไม่มีสิทธิ์จัดการตารางเวลา
- When  เรียก API สร้างหรือแก้ไขตารางเวลา
- Then  ระบบตอบ HTTP 403 และตารางเวลาไม่เปลี่ยนแปลง

**AC-SCH-07 (FR-SCH-08)**

- Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึก
- When  กดบันทึก
- Then  ระบบแจ้งข้อผิดพลาด และไม่มีรายการกิจกรรมถูกสร้างบางส่วน

**AC-SCH-08 (FR-SCH-11)**

- Given ตารางเวลาถูกบันทึกและเผยแพร่แล้ว
- When  นักศึกษาเปิดหน้าตารางเวลาตาม UC-05
- Then  ข้อมูลที่นักศึกษาเห็นตรงกับที่เจ้าหน้าที่บันทึก

**AC-SCH-09 (FR-SCH-09, NFR-SCH-06)**

- Given เจ้าหน้าที่แก้ไขช่วงเวลา 1 ครั้ง
- When  บันทึกสำเร็จ
- Then  มีประวัติ 1 รายการที่ระบุผู้ดำเนินการ เวลา และค่าก่อน/หลัง

### Acceptance Criteria


**AC-NTF-01 (FR-NTF-02, FR-NTF-03, FR-NTF-04)**

- Given มีข่าวสารหรือผลที่เผยแพร่และมีผู้รับที่เกี่ยวข้อง
- When ระบบสร้างการแจ้งเตือน
- Then ผู้รับเห็นการแจ้งเตือนในระบบ และข้อมูลในการแจ้งเตือนถูกต้อง

**AC-NTF-02 (FR-NTF-06, CON-NTF-03)**

- Given ไม่มีผู้รับที่เกี่ยวข้องกับรายการนั้น
- When เกิดเหตุการณ์ที่ต้องแจ้งเตือน
- Then ระบบไม่สร้างการแจ้งเตือน

**AC-NTF-03 (FR-NTF-08, NFR-NTF-02, NFR-NTF-03)**

- Given การแจ้งเตือนครั้งแรกไม่สำเร็จ
- When ระบบพร้อมใช้งานอีกครั้ง
- Then ระบบแจ้งเตือนซ้ำตามจำนวนครั้งและระยะเวลาที่ทีมยืนยัน โดยผู้รับต้องไม่เห็นการแจ้งเตือนซ้ำสำหรับเหตุการณ์และผู้รับรายเดิม

**AC-NTF-04 (FR-NTF-10, CON-NTF-01)**

- Given ผู้ใช้ A ไม่ใช่ผู้รับของการแจ้งเตือน N
- When ผู้ใช้ A เรียกข้อมูลการแจ้งเตือน N
- Then ระบบตอบ HTTP 403 และไม่คืนข้อมูลการแจ้งเตือน

**AC-NTF-05 (FR-NTF-09, CON-NTF-02)**

- Given ผลการตรวจสอบของนักศึกษา B ถูกเผยแพร่
- When ระบบสร้างการแจ้งเตือนถึงผู้รับอื่นที่เกี่ยวข้อง
- Then เนื้อหาการแจ้งเตือนไม่เปิดเผยผลของ B ต่อผู้ที่ไม่มีสิทธิ์เห็น

**AC-NTF-06 (FR-NTF-05, DR-NTF-02)**

- Given การแจ้งเตือนถูกสร้างและผู้รับเปิดดูแล้ว
- When ตรวจสอบข้อมูลการแจ้งเตือนนั้น
- Then สถานะระบุได้ว่าสร้างแล้วและแสดงแล้ว โดยไม่สรุปว่าผู้รับอ่านแล้วจนกว่าจะมีการยืนยันนิยามสถานะตาม OQ-NTF-03

**AC-NTF-07 (FR-NTF-07)**

- Given ผู้ใช้ปิดการแจ้งเตือนตามการตั้งค่าที่ระบบรองรับ
- When เกิดเหตุการณ์ที่ต้องแจ้งเตือน
- Then ระบบแสดงการแจ้งเตือนตามการตั้งค่านั้น โดยรายละเอียดการตั้งค้ายังขึ้นกับคำตอบ OQ-NTF-02

**AC-NTF-08 (NFR-NTF-07)**

- Given เจ้าหน้าที่เผยแพร่ผลตาม UC-14
- When เวลาผ่านไปตามเกณฑ์เวลาที่ทีมยืนยัน
- Then ผู้รับที่เกี่ยวข้องเห็นการแจ้งเตือนในระบบ

**AC-NTF-09 (NFR-NTF-04)**

- Given ผู้ใช้เข้าสู่ระบบแล้วและไม่มีการใช้งานต่อเนื่อง
- When ไม่มีการใช้งานเกิน 30 นาที
- Then ระบบตัดการเชื่อมต่อบัญชีผู้ใช้โดยอัตโนมัติ

**AC-NTF-10 (NFR-NTF-05, IF-WEB-01)**

- Given ผู้ใช้เปิดดูการแจ้งเตือนผ่านเบราว์เซอร์
- When ระบบแสดงข้อความแจ้งเตือน
- Then ข้อความแจ้งเตือนแสดงเป็นภาษาไทยและผู้ใช้สามารถดูได้โดยไม่ต้องติดตั้งโปรแกรมเพิ่มเติม

**AC-NTF-11 (NFR-NTF-06)**

- Given ผู้ใช้เปิดดูการแจ้งเตือนบนโทรศัพท์มือถือที่มีความกว้างหน้าจอตั้งแต่ 360 px
- When ระบบแสดงรายการแจ้งเตือน
- Then เนื้อหาต้องแสดงได้โดยไม่มีการเลื่อนหน้าจอในแนวนอน
